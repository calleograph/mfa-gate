# Безопасность

## Как сообщить об уязвимости

Не открывайте публичный issue. Сообщите закрыто через GitHub Security Advisories: вкладка **Security → Report a vulnerability** в репозитории `calleograph/mfa-gate`.

Укажите:

- версию сервера (`./mfagatectl status`) или приложения;
- компонент: RADIUS, REST API, Device API, панель, Android-приложение, `mfagatectl`;
- шаги воспроизведения и что получает атакующий;
- если есть, доказательство на тестовом стенде. Не проверяйте уязвимость на чужих установках.

Ответ о получении — в течение 7 дней. Затем согласуем срок исправления и дату раскрытия, обычно не позже 90 дней. Авторы будут указаны в бюллетене, если не попросят иначе.

## Поддерживаемые версии

| Версия | Исправления безопасности |
|---|---|
| последний выпуск 0.x | да |
| более старые 0.x | нет: обновитесь (`./mfagatectl update X.Y.Z`) |

До версии 1.0 исправления выходят только в новом выпуске, без переноса в старые ветки.

## Что считается уязвимостью

- Вход без второго фактора, когда политика его требует. Подтверждение чужого запроса или повтор старого.
- Обход проверки подписи решения устройства, привязка устройства без действующей ссылки.
- Обход проверки RADIUS (секрет, Message-Authenticator), подмена ответа.
- Повышение прав в панели или API: роль, scope, CSRF, сессия.
- Утечка секретов: мастер-ключ, TOTP-секреты, секреты RADIUS/LDAP, ключи API, push-токены. Это касается журналов, ответов API, архива `mfagatectl diagnose` и резервных копий.
- SSRF (в том числе через адрес UnifiedPush), инъекции, XSS в панели.
- Уязвимость в зависимостях, которая достижима в MFA Gate.

## Что не считается уязвимостью

- `on_unavailable=allow` в политике пропускает вход без второго фактора. Это задокументированный режим, такой вход пишется в журнал как предупреждение.
- Отсутствие TLS, если администратор опубликовал панель без reverse proxy с HTTPS.
- Перебор паролей при выключенных пределах или открытом наружу UDP 1812. Ограничивайте RADIUS firewall'ом (см. [docs/install.md](docs/install.md)).
- Атаки, требующие root на сервере или разблокированного телефона пользователя.
