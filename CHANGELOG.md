# Журнал изменений

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [Semantic Versioning](https://semver.org/lang/ru/). Версия продукта — файл `VERSION`; сервер (`server/mfa_gate/config.py`) и Android (`android/VERSION`) выпускаются вместе тегом `vX.Y.Z`.

## [Не выпущено]

### Изменено
- Диагностика «Доставка push» без провайдеров больше не утверждает, что запрос виден только при открытом приложении: сборка foss с мгновенными уведомлениями показывает его сразу.

## [0.3.1] — 2026-11-19

Постоянная подпись Android-приложения, полная документация, исправления.

### Добавлено
- Вики: около 85 страниц — маршруты по ролям (сотрудник, администратор, сетевой администратор, поддержка, безопасность, интегратор), сквозные сценарии, инструкции, схемы компонентов, сетевых потоков и последовательностей входа, порты, справочники (коды отказа, конфигурация, команды, роли, журнал аудита), решение проблем. Исходники — `wiki/`, проверка — `scripts/check_wiki.py`.

### Исправлено
- Резервные коды личного кабинета хранятся как HMAC на ключе, производном от мастер-ключа: украденная база без `master.key` не позволяет перебирать коды. Коды, выпущенные в 0.3.0, продолжают работать.
- Администратор без приложения-аутентификатора, потерявший телефон, не мог ввести аварийный код `mfagatectl emergency`: на шаге подтверждения появилась кнопка «Ввести аварийный код».
- Поле политики «Если у пользователя нет подходящего фактора» прежде намекало, что «Пропустить по паролю» срабатывает и при неотвеченном запросе на телефон; подпись уточнена.
- Подсказки: привязка телефона в кабинете называет кнопки приложения дословно; окно смены секрета RADIUS честно говорит, что запросы со старым секретом отбрасываются без записи в истории; проверка «Миграции» больше не советует команду без версии; у событий журнала «Конфликт учётной записи каталога» и «Смена пароля администратора» появились подписи.

### Изменено
- APK подписаны постоянным ключом MFA Gate: следующие версии устанавливаются поверх, выпуск больше не предварительный. Тестовые APK 0.3.0 поверх не обновляются — удалите приложение, установите 0.3.1 и привяжите телефон заново.
- Ограничение привязки телефонов поднято до 30 в минуту с одного адреса: в день внедрения телефоны офиса выходят в интернет через один адрес.
- Подсказки панели о VPN-шлюзах (RADIUS-клиент, «Адреса и публикация») описывают режимы шлюза по функциям, без привязки к производителям.
- README переписан: что такое MFA Gate, как выглядит вход для сотрудника, возможности, установка; ссылки ведут на документацию в репозитории.

## [0.3.0] — 2026-11-19

Личный кабинет сотрудника, внешний адрес для телефонов, шлюзы с собственной проверкой пароля.

### Добавлено
- Личный кабинет сотрудника по адресу `/`: вход доменной учётной записью, мастер первичной настройки второго фактора (TOTP по умолчанию, телефон с MFA Gate — по политике), вход в кабинет со вторым фактором (TOTP, push, резервный код), свои приложения и телефоны (последний способ удалить нельзя), 10 резервных кодов, история своих входов, сеансы кабинета.
- Защита первичной настройки: только из сетей `MFA_GATE_PORTAL_ENROLL_NETWORKS` (по умолчанию частные сети), только для групп `MFA_GATE_PORTAL_ENROLL_GROUPS`, только до первой регистрации фактора; после потери телефона — действие администратора «Разрешить повторную настройку» на 24 часа. Администратор может сбросить резервные коды.
- Внешний адрес Device API `MFA_GATE_DEVICE_URL` для QR привязки: телефон подтверждает VPN-вход из дома. На этом адресе сервер отдаёт только `/api/device/` и `/health/`.
- RADIUS-клиент: «Кто проверяет доменный пароль» — MFA Gate или сам шлюз. Во втором режиме пустой пароль ведёт к push или запросу кода, 6–8 цифр считаются кодом TOTP (режимы шлюза «только логин» и «логин и одноразовый код»).
- Панель: экран «Адреса и публикация» — компоненты, адреса, направления, кому разрешён доступ, готовые конфигурации nginx и Caddy; проверка внешнего адреса телефонов в диагностике.
- Android (сборка foss): мгновенные уведомления при закрытом приложении через постоянное соединение (служба переднего плана), запуск после перезагрузки и обновления, кнопка настроек экономии заряда.
- Документация: схема для сетевых администраторов (`docs/network.md`), примеры `deploy/proxy/nginx.conf` и `deploy/proxy/Caddyfile`, профиль шлюзов с собственной проверкой пароля, ADR 0014–0017, модель угроз для кабинета, режима шлюза и внешнего Device API, страницы Wiki «Личный кабинет сотрудника», «Сетевая схема и публикация», «Шлюзы с собственной проверкой пароля».

### Изменено
- Панель управления переехала на `/admin/` (старые закладки `/#/…` перенаправляются).
- Поиск пользователя без пароля (REST API и режим шлюза) понимает `DOMAIN\user` и UPN.

### Исправлено
- Long-poll телефона мог пропустить событие о новом запросе, пришедшее между проверкой базы и подпиской, и узнать о запросе только через 25 с; теперь задержка не больше 2 с.

## [0.2.0] — 2026-11-19

Объединение с прежним MFA Gate и установка All-in-One.

### Добавлено
- Установка одной командой `sudo ./install.sh` на Ubuntu/Debian: проверка сервера, установка Docker, конфигурация, свободные порты, запуск, первый администратор.
- Первый администратор с временным паролем и обязательной сменой при первом входе; смена собственного пароля в панели.
- Работа по HTTP для первичной настройки (`http://IP:8080`); за HTTPS reverse proxy cookie получают флаг `Secure` автоматически.
- Интеграция OpenVPN без RADIUS: `integrations/openvpn/mfa-gate-openvpn.sh` (отложенная проверка, static-challenge для TOTP).
- `mfagatectl admin-init`, `mfagatectl uninstall`; при недоступном реестре образ собирается из исходников.
- Нагрузочный тест RADIUS `scripts/radius_load.py`.
- Android: приложение MFA Gate Authenticator, тема «Стекло», подключение к HTTP-серверу по явному подтверждению.

### Изменено
- Единое название MFA Gate: пакет `mfa_gate`, переменные `MFA_GATE_*`, утилита `mfagatectl`, образ `ghcr.io/calleograph/mfa-gate`, схема привязки `mfagate://`, строка подписи `mfa-gate-decision-v1`.
- Ограничение частоты входа хранится в PostgreSQL и общее для всех экземпляров api.
- Веб-панель в теме «Стекло».

### Удалено
- Прежняя реализация на Laravel (до 2026.06.15) — заменена новой; данные старых установок не переносятся автоматически.

## [0.1.0] — 2026-11-18

Первый фундамент.

### Добавлено

- RADIUS-сервер: PAP, Access-Challenge для TOTP, обязательный Message-Authenticator, распознавание повторов шлюза, ожидание push в пределах `MFA_GATE_PUSH_TIMEOUT`.
- Сценарий входа: блокировка после ошибок, первый фактор (локально или LDAP/AD), политика, второй фактор. Стабильные коды причин отказа.
- Push-подтверждение с подписью ECDSA P-256 из Android Keystore. Доставка через FCM, HMS и UnifiedPush (HMS и UnifiedPush экспериментальны), long-poll без push.
- TOTP по RFC 6238 с защитой от повторного использования кода.
- LDAP / Active Directory: несколько контроллеров, LDAPS/STARTTLS, вложенные группы, диагностика.
- Политики по ресурсам и группам: `mfa`, `allow`, `deny`, методы, `on_unavailable`.
- REST API v1 (OpenAPI), ключи API со scopes и ограничением адресов, Device API v1.
- Веб-панель: роли `superadmin`, `admin`, `operator`, `auditor`. Второй фактор обязателен для входа.
- Журнал аудита с выгрузкой CSV, история входов, экран проблем входа.
- Docker Compose и `mfagatectl`: установка, обновление с автооткатом, откат, резервные копии, восстановление, диагностика, аварийный код администратора.
- Android-приложение MFA Gate Authenticator: сборки `gms` (FCM) и `foss` (без сервисов Google).
- CI: ruff, pytest, LDAP-тесты, сквозной стенд, сборка Android, проверка на частные данные. Выпуск образа и APK по тегу.

### Не реализовано

- RADIUS Accounting, атрибуты ответа (Class, Filter-Id, VSA).
- Режим «только второй фактор» по RADIUS.
