# Модель угроз MFA Gate

## Участники и границы доверия

```
 Пользователь ──(VPN-клиент)──► VPN-шлюз ──RADIUS UDP 1812──► [radius] ──┐
 Сотрудник, администратор ──HTTPS──► прокси, внутреннее имя ──► [api] ───┼── PostgreSQL ── [worker] ──► FCM/HMS/UnifiedPush ──► Телефон
 Телефон ──HTTPS из Интернета──► прокси, внешнее имя (/api/device/) ──► [api]
 [api], [radius] ──LDAPS──► Active Directory / LDAP
```

| Граница | Чему доверяем | Чему не доверяем |
|---|---|---|
| Шлюз → radius | пакетам с верным Message-Authenticator от зарегистрированного адреса; в режиме `first_factor=gateway` — ещё и тому, что шлюз проверил пароль (только этому клиенту) | содержимому атрибутов (длины, State, Calling-Station-Id используются только для отображения и сопоставления) |
| Телефон → api | подписи ключом из Keystore (решение), `device_secret` (чтение своих запросов) | push-каналу (только сигнал), часам телефона |
| api/radius → каталог | ответу каталога по проверенному TLS | каталогу без TLS (предупреждение в диагностике) |
| Push-провайдер | ничему: в уведомлении нет данных, только id запроса | — |
| Администратор → api (`/admin/`) | сессии панели после второго фактора + CSRF | сессии до второго фактора (10 минут, без доступа к данным); сессии кабинета |
| Сотрудник → api (`/`) | сессии кабинета после второго фактора | сессии кабинета после одного пароля (короткая, только ввод второго фактора и первая регистрация по правилам ADR 0017); адресу клиента как доказательству личности |
| Интернет → reverse proxy | запросам к `/api/device/` на внешнем имени | любым другим путям и именам: 404 в прокси и в сервере по `Host` |

## Угрозы и меры

| Угроза | Мера | Проверка |
|---|---|---|
| Подбор пароля через RADIUS/API/панель | блокировка после 8 ошибок на 15 мин (`UPDATE` одним запросом, сброс после истечения), общая для `user`, `DOMAIN\user` и UPN; лимит попыток по IP в api; argon2 в отдельном потоке (не останавливает RADIUS) | `test_lockout_after_failures` |
| Перечисление логинов | до второго фактора наружу один текст для неверного пароля, неизвестного логина, блокировки и отключения; точная причина — только в истории и журнале | `test_wrong_password_and_unknown_user_rejected` |
| Захват учётной записи администратора оператором или ключом API | пароль, статус, удаление, TOTP, привязка и отзыв устройств администратора — только у главного администратора | `test_admin_login_requires_second_factor` |
| Подмена второго фактора администратора через первичную настройку TOTP | настройка доступна, только если нет ни TOTP, ни телефона | `test_admin_login_requires_second_factor` |
| Повторное использование одобренного push-входа в панель | push привязан к сессии, одобрение гасится атомарно (`consumed`) | `test_admin_login_requires_second_factor` |
| Перебор TOTP администратора через новые сессии | ввод кода запрещён во время блокировки учётной записи | код `api/auth.py` |
| Доменная учётная запись с логином локального пользователя или уволенного сотрудника | запись с тем же логином принимается только из того же каталога и с тем же objectGUID, иначе отказ и critical в журнале | код `services/authflow.py` |
| Обход запрещающих политик при сбое вычисления вложенных групп AD | сбой = отказ во входе, без отката к прямым группам | `test_ad_nested_groups_failure_denies_login` |
| Блокировка чужой учётной записи перебором | разблокировка администратором; **остаётся риск**: счётчик только по пользователю — нужен отдельный счётчик по адресу шлюза/клиента | — |
| Перебор TOTP | окно ±1 шаг, ошибки OTP увеличивают тот же счётчик блокировки | `test_totp_challenge_and_replay` |
| Повтор принятого TOTP-кода | условный `UPDATE totp_factors SET last_step … WHERE last_step < step` | `test_totp_challenge_and_replay` |
| Повтор подтверждения push / гонка двух ответов | одноразовый challenge, атомарный переход `pending →`, повтор = 409 | `test_push_approve_end_to_end` |
| Подтверждение чужой транзакции | запрос виден и подтверждается только устройством его пользователя (404 иначе); device_id входит в подпись | `test_bad_signature_and_foreign_request` |
| Подмена решения (deny → approve) | решение входит в подписываемую строку | `test_bad_signature_and_foreign_request` |
| Позднее подтверждение после таймаута | при истечении статус фиксируется `expired`; решение принимается только при `expires_at > now()` | `test_push_timeout_rejects_and_late_approve_fails` |
| Подмена State в Access-Challenge | State = UUID транзакции; проверяются логин, ресурс и статус | `test_totp_challenge_and_replay` |
| Несколько push на одну попытку (повторы шлюза) | дедупликация пакета (RFC 5080) + присоединение к открытой транзакции только при совпадении адреса пользователя, канала, клиента и NAS | `test_retransmission_does_not_create_second_push` |
| Чужая попытка «пристраивается» к push жертвы | присоединение запрещено без Calling-Station-Id и между разными клиентами/каналами; **остаточный риск**: злоумышленник с паролем жертвы за тем же NAT в те же секунды — следующий шаг: number matching | — |
| Подделка RADIUS-ответа / BlastRADIUS | Message-Authenticator обязателен во входящих и всегда первый в исходящих | `test_missing_message_authenticator_dropped`, `test_radius_packet.py` |
| Неизвестный NAS | молчаливый отброс, предупреждение в журнале | `test_unknown_radius_client_dropped` |
| Кража `device_secret` | даёт только чтение запросов своего пользователя; подтверждение требует ключа Keystore + биометрии | протокол |
| Кража телефона | биометрия/PIN на каждое подтверждение; отзыв устройства администратором | `test_revoked_device_cannot_poll` |
| «Усталость от push» (спам запросами) | push только после первого фактора; дедупликация повторов шлюза и присоединение к открытой попытке (один push на попытку); блокировка после 8 ошибок; срок ответа `MFA_GATE_PUSH_TIMEOUT`, позднее подтверждение отклоняется; «Отклонить» + журнал; **не сделано**: number matching и ограничение частоты push на пользователя | `test_retransmission_does_not_create_second_push` |
| Украденный пароль → регистрация телефона злоумышленника в кабинете | регистрация по одному паролю — только если у пользователя никогда не было фактора или есть одноразовое разрешение администратора (24 ч); только из `MFA_GATE_PORTAL_ENROLL_NETWORKS` и для `MFA_GATE_PORTAL_ENROLL_GROUPS`; короткая сессия; новые факторы — только в сессии после второго фактора; подтверждение фактора гасит все неиспользованные ссылки привязки, выпущенные самим сотрудником (параллельно полученный QR не добавит второй телефон); регистрация пишется в аудит. **Остаточный риск**: сотрудник, ещё не подключивший фактор, из разрешённой сети — сокращайте окно ранней регистрацией | ADR 0017 |
| Кража или подбор резервных кодов | 10 одноразовых кодов, показываются один раз, хранятся хешами; действуют только для входа в кабинет (не для VPN), после пароля | ADR 0017 |
| Повторная регистрация после удаления всех факторов | отметка первой регистрации не снимается; последний фактор из кабинета удалить нельзя | ADR 0017 |
| Поддельный шлюз в режиме `first_factor=gateway` (push или проверка кода без пароля) | режим только у конкретного клиента, глобального пропуска нет; клиент определяется по адресу источника; свой длинный секрет на клиента; обязательный Message-Authenticator; UDP 1812 открыт только адресам шлюзов; между площадками — IPsec/WireGuard. **Остаточный риск**: взлом самого шлюза | ADR 0016 |
| Перебор кодов через шлюз в режиме `gateway` | код из 6–8 цифр проверяется как TOTP, ошибки идут в счётчик блокировки; прочие значения не проверяются как пароль и не считаются ошибкой | ADR 0016 |
| Доступ к панели, кабинету или REST API из Интернета через внешнее имя Device API | прокси публикует внешнее имя только с `/api/device/`; сервер отвечает 404 на другие пути с `Host` внешнего имени; внутреннее имя закрыто в прокси по адресам источника | ADR 0015, `deploy/proxy/` |
| Атаки на Device API из Интернета (перебор токенов привязки, поток запросов) | токен привязки 32 байта, одноразовый, 24 ч, хранится хешем; служебные запросы — по `device_secret`; подтверждение — подпись ключом Keystore; лимит частоты привязки — 30 в минуту с адреса (`429`), остальные запросы без `device_secret` не принимаются; журнал внешнего имени у прокси | протокол, ADR 0015 |
| Перехват QR-кода привязки | QR показывается в кабинете после пароля и второго фактора (или первой регистрации по ADR 0017) либо администратором; одноразовый, 24 ч (из кабинета — 15 мин); адрес и учётная запись показываются на телефоне перед привязкой | протокол |
| Утечка базы | секреты зашифрованы мастер-ключом с AAD, пароли argon2id, токены — SHA-256 | — |
| Утечка резервной копии | мастер-ключ не входит в копию | `scripts/e2e.sh` |
| Утечка секретов в журналы | маскирование по именам полей; архив диагностики проверяется на значения секретов | `test_diagnostics_and_audit` |
| SSRF через push-адрес устройства | UnifiedPush только для хостов из белого списка, только HTTPS; некорректный адрес помечает канал недействительным | `test_unifiedpush_rejects_bad_and_foreign_urls` |
| Одно устройство останавливает доставку всем | ошибка любого вида изолирована в своём элементе очереди, отправка параллельна с таймаутом 5 с | код `worker.py` |
| Поток поддельных RADIUS-пакетов | Message-Authenticator проверяется до кэша повторов; аудит отбросов не чаще раза в минуту на клиента | код `radius/server.py` |
| CSRF на панели | SameSite=Strict + заголовок `X-CSRF-Token` для изменяющих запросов | `test_admin_login_requires_second_factor` |
| XSS в панели | CSP `script-src 'self'` без inline, данные выводятся как текст | панель |
| Повышение прав | роли проверяются на сервере для каждого метода; ключ API не может назначать роли; последнего главного администратора нельзя лишить прав | `test_api_key_cannot_grant_admin_roles` |
| Чтение чужих результатов API-клиентом | транзакция привязана к создавшему клиенту | `test_rest_access_request_with_push` |
| Ключ, привязанный к ресурсу, запрашивает вход в другой ресурс | 403 `resource_mismatch` | `test_resource_bound_key_cannot_switch_resource` |
| Исчерпание соединений БД long-poll'ом телефонов | транзакция закрывается до ожидания | `test_long_polls_do_not_exhaust_db_pool` |

## Политика отказа

| Сбой | Поведение по умолчанию |
|---|---|
| Каталог недоступен | отказ (`directory_unavailable`) |
| Нет фактора / push не доставлен / нет ответа | отказ (`no_factor`, `push_expired`) |
| База данных недоступна | RADIUS молчит или отвечает отказом, api — 503; после возврата БД работа продолжается без перезапуска |
| Обход | только политика с `on_unavailable=allow` или `action=allow` для явно указанных ресурсов и групп; каждое применение журналируется |
| Аварийный доступ администратора | одноразовый код из консоли сервера, 15 минут, событие critical |
