# Веб-панель администратора

Панель — одностраничное приложение в `server/web/`. Панель открывается по адресу `/admin/`, личный кабинет сотрудника — по `/` ([ADR 0014](adr/0014-portal-and-admin.md)). Сервер (FastAPI) отдаёт `web/admin.html` на пути `/admin/*`, `web/index.html` (портал, `assets/js/portal.js`) — на остальные пути, кроме `/api/*` и `/health/*`, а файлы `web/assets/*` — по адресу `/assets/`. Сборщика нет: нативные ES-модули, без фреймворков и внешних CDN.

```
server/web/
  admin.html                 оболочка панели: CSS, theme.js, app.js, область тостов
  index.html                 оболочка личного кабинета: CSS, theme.js, portal.js
  assets/css/app.css         токены «Стекла», сетка, все компоненты, светлая и тёмная темы
  assets/js/theme.js         классический скрипт: применяет сохранённую тему до отрисовки
  assets/js/app.js           сессия, оболочка, хэш-роутинг, права разделов
  assets/js/api.js           fetch-обёртка: CSRF, единый формат ошибок, перевод сообщений валидации
  assets/js/ui.js            компоненты: h(), значки, кнопки, формы, модальные окна, меню, тосты, таблицы
  assets/js/labels.js        подписи статусов, причин отказа, событий журнала
  assets/js/portal.js        личный кабинет сотрудника (вход, первичная настройка, факторы, резервные коды)
  assets/js/views/*.js       разделы панели: login, overview, users, access, integrations, control, publication, crud
  assets/fonts/              Inter и Manrope (вариативные), JetBrains Mono 400/500; кириллица и латиница; OFL.txt
  assets/img/bg-glass.svg    мягкие волны фона темы «Стекло»
  assets/icons/sprite.svg    Lucide (ISC), LICENSE-lucide.txt; favicon.svg — знак MFA Gate
```

## Ограничения безопасности

CSP сервера: `default-src 'self'; img-src 'self' data:; style-src 'self'; script-src 'self'`. Поэтому:

- нет inline-скриптов, атрибутов `style=""` и обработчиков `on*=`; динамические значения (ширина полос, таймер push) задаются через `el.style.setProperty('--var', …)`;
- QR-коды от сервера (`qr_svg`) показываются как `<img src="data:image/svg+xml;base64,…">`, без вставки разметки;
- пользовательские данные выводятся только через `textContent` (`h()` в `ui.js`), `innerHTML` не используется;
- все изменяющие запросы идут с заголовком `X-CSRF-Token` из ответа `login`/`me`;
- секреты RADIUS- и API-клиентов показываются один раз в окне, которое закрывается только явной кнопкой «Секрет сохранён, закрыть».

## Визуальная система: тема «Стекло»

Оформление «Стекло» построено как система, а не как набор похожих картинок: палитра и состояния, стеклянные поверхности (левая панель, «пилюли», карточки), кнопки с пружинным откликом и бликом, поля со свечением фокуса, короткое движение при появлении страниц, окон и строк. Всё — в `server/web/assets/css/app.css`. Тёмный вариант — та же система на тёмной палитре: стекло выводится из `--surface` выбранной темы.

| Токен | Значения |
|---|---|
| Палитра (светлая) | фон `#eaf2fd` с вертикальным градиентом и волнами `bg-glass.svg`; поверхность `#fff`; текст `#0f1b3d`, вторичный `#4c5c7a`; акцент `#2563eb`, градиент кнопок `#2f6bf2 → #2358d8` |
| Палитра (тёмная) | фон `#0d121b`, поверхность `#161c27`; текст `#e9edf3`, вторичный `#9ba6b8`; акцент `#6f98ff`, текст на акценте `#0a1226` |
| Состояния | `--ok`/`--warning`/`--error`/`--pending` — цвет текста, `*-bg` — фон «пилюли», `*-fill` — заливка полос; текст на фоне не ниже 4,5:1 |
| Стекло | `--glass` (70 % поверхности) — боковая панель и мобильная шапка; `--glass-strong` (90 %) — панели, карточка входа, окна; `--glass-dense` (97 %) — панели с таблицами; размытие `--blur: 16px`, `saturate(1.3)` |

| Сетка | контейнер 1200 px; 12 колонок на десктопе, 8 на планшете, 4 на телефоне; интервал 24/16 |
| Тени | `--shadow-glass` (панели), `--shadow-lift` (подъём), `--shadow-pop` (меню, окна), `--shadow-btn` (главная кнопка) |
| Движение | 120 / 180 / 240 мс, `--ease: cubic-bezier(.22,.8,.24,1)`, `--spring: cubic-bezier(.34,1.56,.64,1)`; появление страницы, окна и первых строк таблиц; при `prefers-reduced-motion` анимации отключаются |

Шрифты: Inter — интерфейс, Manrope — заголовки, бренд и крупные числа, JetBrains Mono — только данные (логины, IP, CIDR, DN, ключи, коды). Все файлы локальные, лицензия OFL в `assets/fonts/OFL.txt`.

Читаемость важнее прозрачности. `backdrop-filter` есть только у крупных поверхностей (боковая панель, мобильная шапка, панели, карточка входа, модальные окна); меню, тосты, кнопки и поля сплошные. Таблицы данных лежат на почти сплошной подложке `--glass-dense`. При `prefers-reduced-transparency: reduce` и в браузерах без `backdrop-filter` все стеклянные токены становятся сплошной поверхностью, размытие и волны отключаются.

Тема: по умолчанию следует `prefers-color-scheme`. Переключатель «Как в системе / Светлая / Тёмная» в подвале боковой панели и на экране входа сохраняет выбор в `localStorage` (`mfa_gate.theme`). Чтение и запись обёрнуты в try/catch, в приватном режиме тема просто не запоминается.

Знак MFA Gate — плитка с градиентом темы и проёмом ворот с замочной скважиной (`brandMark()` в `ui.js`, тот же рисунок в `favicon.svg`).

Фирменный элемент — живой индикатор ожидания push при входе администратора. Второй квадрат «подходит» к первому, пока телефон не ответил. Ниже идёт полоса оставшегося времени из `expires_at`. При подтверждении квадраты совмещаются, при отказе контур становится пунктирным.

## Вход и пароль администратора

- **Временный пароль.** Если `POST /api/v1/auth/login` отвечает `next: "password_change"` (первый администратор от установщика, `create-admin --temporary`), панель показывает экран «Смените временный пароль»: текущий пароль (подставлен из формы входа), новый и повтор. На клиенте проверяется длина нового пароля (не короче 12 символов) и совпадение повтора. Затем `POST /api/v1/auth/password {current_password, new_password}` → `{next: "mfa" | "totp_setup", methods, csrf}`, и вход продолжается обычным вторым фактором. Ошибки показываются у полей: `400 bad_password` — у текущего пароля, `422 same_password` и ошибки валидации — у нового. Если сервер на шаге второго фактора отвечает `403 password_change_required`, панель возвращает на экран смены пароля.
- **Смена своего пароля.** У администратора с `source: "local"` (поле в `/api/v1/auth/me`) в меню профиля (кнопка с именем в подвале боковой панели) есть пункт «Сменить пароль». Окно использует тот же метод с заголовком `X-CSRF-Token`; после ответа `{ok: true}` показывается тост. Остальные сеансы этой учётной записи сервер закрывает сам. У доменных администраторов пункта нет: их пароль меняется в каталоге.

## Работа по HTTP

Первичная установка открывается как `http://IP:порт`, поэтому панель не зависит от secure context:

- копирование секретов: `navigator.clipboard` используется только в secure context; иначе — выделение во временном поле и `execCommand('copy')` (поле создаётся внутри открытого `<dialog>`, иначе оно инертно). Если и это не сработало, видимый секрет остаётся выделенным, а рядом с полем появляется подсказка «Скопируйте вручную… нажмите Ctrl+C»;
- случайные значения — только `crypto.getRandomValues` (доступен по HTTP); `crypto.subtle`, `randomUUID`, Service Worker и Web Push панель не использует;
- при `http:` на не петлевом адресе в подвале боковой панели видна плашка «Соединение без HTTPS — только для изолированной сети» со ссылкой на раздел HTTPS в README. На `localhost`/`127.0.0.1` (SSH-туннель) плашки нет. Предупреждение на экране «Диагностика» приходит от сервера.

## Компоненты (`ui.js`)

- **Кнопки** `button()`: варианты `primary`, `secondary`, `ghost`, `danger`, `danger-ghost`, размер `sm`. У каждой есть состояния hover, active, focus-visible, disabled; на время запроса `busy()` показывает загрузку.
- **Формы** `form()` / `formDialog()`: подписи, подсказки и ошибки у полей (`aria-describedby`, `aria-invalid`). Поддерживаемые типы: текст, пароль, число, textarea, select, переключатель (`role=switch`), флажки, варианты-карточки, теги-списки. Обязательные поля проверяются до запроса. Ошибки сервера `fields[]` показываются у своих полей, остальные — над кнопками.
- **Модальные окна** `modal()` на нативном `<dialog>`: фон недоступен, фокус не выходит из окна, Escape и клик по подложке закрывают окно, фокус возвращается к кнопке, которая его открыла. Для опасных подтверждений первый фокус ставится на «Отмена».
- **Меню действий** `actionMenu()`: стрелки, Home/End, Escape (с возвратом фокуса), Tab, клик вне меню.
- **Таблицы** `table()`: липкая шапка. При ширине меньше 1280 px скрываются второстепенные колонки, меньше 768 px строки становятся карточками (подпись поля берётся из `data-label`).
- **Меню профиля** — тот же `actionMenu()` со своей кнопкой-триггером (`actionMenu(items, label, trigger)`).
- **Состояния**: скелетоны загрузки, пустые состояния с действием, ошибка сети и ошибка прав с кнопкой «Повторить», тосты в `aria-live`.

## Навигация и права

Используется хэш-роутинг (`#/users/<id>`), кнопка «назад» браузера работает. Фильтры и страница записываются в адрес через `history.replaceState`: на них можно дать ссылку, но они не засоряют историю. Ссылка «← Пользователи» в карточке, если пользователь пришёл из списка, возвращает к нему вместе с фильтрами.

Меню: **Обзор**; **Доступ** — пользователи, группы, устройства, политики; **Интеграции** — ресурсы, RADIUS, API, каталоги; **Контроль** — история входов и журнал; **Система** — адреса и публикация, диагностика. «Проблемы входа» — второй вид истории входов (переключатель на странице), отдельного пункта меню у него нет.

| Раздел | Адрес | Право |
|---|---|---|
| Обзор | `#/` | `system:read` |
| Пользователи, карточка | `#/users`, `#/users/<id>` | `users:read` |
| Группы, Устройства | `#/groups`, `#/devices` | `groups:read`, `devices:read` |
| Политики | `#/policies` | `policies:read` |
| Ресурсы, RADIUS, API, LDAP | `#/resources`, `#/radius`, `#/api-clients`, `#/ldap` | `resources:read`, `radius:read`, `apiclients:read`, `ldap:read` |
| История входов: все входы, проблемы | `#/history`, `#/problems` | `requests:read` |
| Журнал | `#/audit` | `audit:read` |
| Адреса и публикация, Диагностика | `#/publication`, `#/diagnostics` | `system:read` |

Разделы без права `…:read` не попадают в меню. Кнопки изменения появляются только при праве `…:write`. Назначать роли можно только при `admins:write` или `*`. Если открыть адрес раздела без права, панель покажет «Раздел недоступен для вашей роли». Ссылка на `/api/docs` для интеграторов есть в подвале боковой панели и в разделе «API-клиенты».

## Как добавить раздел

1. Напишите функцию `async (ctx) => {}` в `views/`. В `ctx` передаются `main`, `params`, `query`, `can`, `setQuery`, `signal` и `reload`.
2. Для обычного CRUD используйте `crudPage(ctx, {...})` из `views/crud.js`.
3. Добавьте маршрут в `ROUTES` и пункт меню в `NAV` в `app.js`, указав право.

## Проверка

Изменения панели проверяются в браузере (agent-browser) на ширинах 320, 390, 768, 1024, 1280, 1440 и 1920 скриптом `~/.claude/design-standard/layout-audit.js`, в светлой и тёмной темах. Он не должен находить горизонтальную прокрутку, отступы вне шкалы и тап-цели меньше 40 px. Кроме того, в консоли браузера не должно быть ошибок, включая нарушения CSP. Поведение без secure context проверяется по не петлевому имени (например, Chrome с `--host-resolver-rules="MAP mfa-gate.test 127.0.0.1"` и адрес `http://mfa-gate.test:порт`).

Скриншоты для README лежат в `docs/images/`: `overview-light.png`, `overview-dark.png`, `user-card.png` (1440×900) и `mobile.png` (390×844).

## Чего не хватает в API

Панель обходит эти пробелы честно: показывает «нет данных» или «недоступно», фиктивных кнопок нет.

- **Фильтр пользователей по наличию фактора и статусу** (`GET /users?factor=none&status=…`). Сейчас фильтр «Нет фактора» работает в браузере по первым 200 записям и предупреждает об этом.
- **Состав группы** (`GET /groups/{id}/members`). Сейчас есть только счётчик участников.
- **Сведения о сервере** (`GET /system/info`: адрес и порт RADIUS, `server_name`, `public_url`). Без них окно секрета не может подсказать, какой адрес указать на шлюзе.
- **Смена секрета RADIUS на сервере** (`POST /radius-clients/{id}/rotate`). Сейчас секрет генерирует браузер (`crypto.getRandomValues`) и передаёт через `PUT`.
- **Справочники причин отказа и типов событий журнала**. Сейчас подписи продублированы в `labels.js`.
- **Счётчики для чек-листа настройки в `/dashboard`** (каталоги, политики). Сейчас обзор делает отдельные запросы, и роли без `ldap:read` или `policies:read` видят «состояние неизвестно».
- **Диапазон дат и сортировка** в `/auth-requests` и `/audit`, пагинация в `/auth-requests/problems`.
- **Проверка настроек каталога до сохранения** (`POST /ldap/diagnose` с телом настроек) и **поиск пользователя в каталоге** до создания (`GET /ldap/lookup?login=`).
- **Активные сессии администраторов** (список и завершение) и **свои факторы администратора** в меню профиля. Смена своего пароля уже есть.
