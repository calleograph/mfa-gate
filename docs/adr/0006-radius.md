# 0006. RADIUS

**Решение.** Собственная реализация на asyncio (RFC 2865 PAP, RFC 3579 Message-Authenticator), ~250 строк кода сервера и кодек с тестовыми векторами RFC.
- Клиент определяется по адресу источника (самая узкая сеть; один адрес — один клиент), неизвестный адрес — пакет отбрасывается молча.
- Message-Authenticator обязателен по умолчанию (BlastRADIUS); неверный — отброс (так проявляется неверный shared secret). В ответах он всегда первый.
- Push: Access-Request удерживается до решения или `MFA_GATE_PUSH_TIMEOUT` (45 с); таймаут шлюза должен быть больше.
- Повторы: пакет с тем же (IP, порт, Identifier, Authenticator) не создаёт новую транзакцию и после ответа получает тот же ответ (RFC 5080). Новый Access-Request той же попытки присоединяется к открытой транзакции — второго push нет — только при совпадении пользователя, ресурса, Calling-Station-Id, клиента, канала и NAS (без Calling-Station-Id присоединения нет: иначе чужая попытка могла бы использовать push жертвы).
- OTP: если push недоступен, а TOTP есть — Access-Challenge, State = id транзакции (16 байт), ответ проверяется по логину и ресурсу.

**Почему не FreeRADIUS + модуль.** Ещё один сервис и язык конфигурации, обработка повторов и ожидания push всё равно в нашем коде. Своя реализация протокола аутентификации небольшая и полностью покрыта тестами.
