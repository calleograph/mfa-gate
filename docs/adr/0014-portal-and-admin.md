# 0014. Личный кабинет сотрудника и панель администратора

**Контекст.** До 0.3.0 веб-интерфейс был один — панель администратора на `/`. Сотрудник не мог сам подключить фактор: каждый телефон и каждый TOTP выпускал администратор, это не масштабируется на сотни пользователей. Нужен кабинет самообслуживания, при этом права и вход администратора меняться не должны.

**Решение.**
- Три части одной системы: кабинет сотрудника на `/`, панель администратора на `/admin/`, инфраструктура аутентификации (RADIUS UDP 1812, REST API `/api/v1/`, Device API `/api/device/v1/`). Один сервис `api`, одна база, один образ.
- Вход в кабинет: доменный пароль (LDAPS через уже настроенные каталоги) или локальный, затем второй фактор. В кабинете: мастер первой настройки (TOTP по умолчанию, push приложения — по выбору, методы ограничивает политика), резервные коды, свои устройства и факторы (последний удалить нельзя), история входов, активные сессии кабинета.
- Панель переехала на `/admin/` без изменений: роли, обязательный второй фактор, CSRF, аудит.
- Два вида сессий (`admin_sessions.kind`): `portal` и `admin`, у каждой свой cookie. Сессия кабинета не даёт доступа к панели; вход в панель — отдельный, со своим вторым фактором. Внутри вида — признак `mfa_passed`:
  - кабинет после пароля — короткая сессия, доступны только ввод второго фактора и, если разрешено ([0017](0017-self-enrollment-and-recovery.md)), первая регистрация фактора;
  - кабинет после второго фактора — всё остальное, в том числе добавление новых факторов;
  - панель — только после второго фактора, как раньше.

**Последствия.** Закладки и инструкции с адресом панели без `/admin/` открывают кабинет. Кабинет публикуется только внутри сети, как и панель ([0015](0015-external-device-api.md)). Нагрузка на администратора уменьшается, но появляется новая точка атаки — регистрация фактора по одному паролю; меры — в [0017](0017-self-enrollment-and-recovery.md) и в модели угроз.

**Альтернативы.** Отдельный сервис или образ для кабинета — второй процесс сопровождения и общая база всё равно; выигрыша нет. Кабинет на поддомене — потребовал бы второго имени и сертификата для внутренней части без пользы для безопасности. Общая сессия для кабинета и панели — кража cookie кабинета давала бы доступ к панели администратора.
