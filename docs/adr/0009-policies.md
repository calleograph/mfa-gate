# 0009. Политики доступа

**Решение.** Правило = условия (ресурсы, группы, группы-исключения) + действие (`mfa` / `allow` / `deny`) + методы (`push`, `totp`) + поведение при недоступности второго фактора (`deny` по умолчанию / `allow`). Включённые правила проверяются по возрастанию `priority`, применяется первое совпавшее. Нет совпадений — MFA обязателен.

**Безопасность по умолчанию.** Недоступен каталог, нет фактора, сбой push — отказ. `allow` и `on_unavailable=allow` — явные исключения, сохранение такой политики пишется в журнал как warning, каждый пропуск без MFA — `mfa_bypass_unavailable` в истории. MFA администраторов политиками не отменяется. Аварийный доступ администратора — только одноразовым кодом из консоли сервера (`mfagatectl emergency`), событие critical.

**Отличие от MFA-Gate.** Там при недоступной таблице политик действовали значения по умолчанию (fail-open) и «последняя политика переписывает предыдущие» — менее предсказуемо.
