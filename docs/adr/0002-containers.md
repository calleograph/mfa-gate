# 0002. Контейнеры

**Решение.** Один образ `mfa-gate`, роль задаётся командой: `migrate` (одноразовый, применяет Alembic до старта остальных), `api` (REST API, Device API, панель), `radius` (UDP 1812), `worker` (доставка push, истечение запросов, очистка, пульс). Плюс `postgres`. Redis не используется: события между процессами — PostgreSQL `LISTEN/NOTIFY`, очередь push — таблица `push_outbox` с `FOR UPDATE SKIP LOCKED`.

**Почему не микросервисы.** RADIUS и API разделены, потому что у них разные порты, протоколы и профиль отказов (перезапуск панели не должен рвать ожидающие VPN-входы). Дальнейшее дробление не даёт выигрыша при нагрузке MFA, но усложняет эксплуатацию.

**Почему без Redis.** Минус один сервис, одна точка истины. NOTIFY доставляется после фиксации транзакции — событие не обгоняет данные. При потере NOTIFY ожидающие перечитывают БД раз в 2 с.

**Последствия.** Масштабирование api/radius — несколько реплик за балансировщиком; дедупликация повторов RADIUS держится в памяти реплики (шлюз шлёт повторы на тот же адрес). Ограничитель частоты входа в api — в памяти процесса (помечено `shortcut:` в коде).
