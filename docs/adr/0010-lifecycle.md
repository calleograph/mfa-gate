# 0010. Установка, обновление, восстановление

**Решение (по образцу эталонный проект и донор B).** `deploy/mfagatectl` — единая команда. Compose без `container_name`, имена из `COMPOSE_PROJECT_NAME`, порты только из обязательных переменных (по умолчанию HTTP на loopback за reverse proxy), PostgreSQL не публикуется, логи ограничены, контейнеры `read_only` и `cap_drop: ALL`.
- Версия образа зафиксирована в `.env` (`MFA_GATE_VERSION`), `latest` не используется. Образы публикуются в GHCR по тегу выпуска.
- `update X.Y.Z`: резервная копия → загрузка образа (при неудаче версия не меняется) → сервис `migrate` → запуск → ожидание healthy → при сбое автоматический `rollback`.
- `rollback`: прежняя версия + восстановление базы из копии перед обновлением (миграции вперёд не откатываются — база возвращается из копии).
- `restore`: в отдельную базу, проверка, подмена по имени; прежняя остаётся как `mfa_gate_prev`; отказ, если копия сделана с другим мастер-ключом.
- `diagnose`: сводка + архив журналов без секретов.

**Отличие от эталонный проект.** Образы не собираются на сервере клиента из исходников, а загружаются готовыми (сборка из исходников остаётся для разработки: `MFA_GATE_IMAGE=mfa-gate`). Root-помощник обновлений из веб-интерфейса не переносился.
