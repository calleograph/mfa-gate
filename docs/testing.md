# Тестирование и результаты

Последний прогон: 2026-11-18, версия 0.1.0.

## Как запускать

| Набор | Команда | Что нужно |
|---|---|---|
| Юнит (сервер) | `cd server && .venv/bin/pytest` | — (LDAP и сквозные пропускаются без стенда) |
| LDAP на настоящем каталоге | `server/tests/ldap_fixture/run.sh` | Docker (поднимает OpenLDAP с TLS, убирает за собой) |

## Пройдено

**Сервер, юнит:** 57 тестов. Кодек RADIUS по векторам RFC 2865, Message-Authenticator, некорректные пакеты; политики (приоритет, исключения, сопоставление групп AD); маскирование журнала; подпись устройства, только ключи P-256; SecretBox с AAD; argon2; UnifiedPush отклоняет чужие и некорректные адреса; разбор логинов и подкодов AD; отказ при сбое вычисления вложенных групп.

**LDAP на OpenLDAP:** 17 тестов. Вход по `user`, `DOMAIN\user` и UPN; неверный пароль; отсутствующий пользователь; пустой пароль; вложенные группы; разрешённые группы; недоступный хост (быстрый отказ по таймауту); переход на второй контроллер; LDAPS со своим CA (правильный CA — вход, чужой — `tls_error`); STARTTLS; вход без сервисной учётной записи; пошаговая диагностика.

**Сквозные на стенде** (`server/tests/test_stack.py`, 21 тест, в Docker и на локальных процессах):
- RADIUS: неизвестный клиент отбрасывается; неверный shared secret отбрасывается; пакет без Message-Authenticator отбрасывается; неверный пароль и неизвестный пользователь отклоняются одинаковым текстом; пользователь без фактора отклоняется.
- Push: привязка по одноразовому QR (повтор ссылки — 410); подтверждение → Access-Accept меньше чем за 3 с после решения; отклонение → Reject; поддельная подпись (deny, выданный за approve) → 400; чужое устройство не видит и не подтверждает запрос (404); повтор подписи → 409; таймаут → Reject, позднее подтверждение не проходит.
- Повторы шлюза: тот же пакет во время ожидания не создаёт вторую транзакцию; новый Access-Request той же попытки присоединяется к ней; повтор после ответа получает кэшированный ответ; в истории одна транзакция.
- Два пользователя одновременно — независимые решения.
- TOTP через Access-Challenge: принятие кода; повтор State, повтор кода в новой транзакции и чужой State отклоняются.
- REST API: запрос доступа с push → accepted; другой ключ не видит чужую транзакцию (404); ключ без прав → 403; ключ, привязанный к ресурсу, не может указать другой ресурс (403).
- Политики: deny для группы, затем allow-исключение.
- Блокировка после 8 ошибок: верный пароль во время блокировки отклоняется, причина `locked` есть в истории.
- Отозванное устройство получает 401 `device_revoked`.
- Вход администратора: пароль → обязательная настройка TOTP → доступ; без CSRF изменения запрещены (403). Ключ API не может назначать роли и менять учётные записи администраторов. Администратор только с телефоном: подмена фактора через первичную настройку → 409; push-вход одноразовый (повтор → `consumed`) и недоступен другой сессии (404).
- Диагностика без ошибок; в журнале нет паролей и секретов.
- 40 одновременных long-poll'ов не мешают API и RADIUS (тест падает без исправления — проверено).

**Жизненный цикл в Docker** (`scripts/e2e.sh`, 13 этапов): чистая установка через `mfagatectl install`; повторная установка идемпотентна; сквозные тесты в контейнерах (21/21); пересоздание контейнеров без потери данных; резервная копия; восстановление возвращает состояние копии; обновление 0.1.0 → 0.1.1 (копия, миграции, healthy); откат с восстановлением базы; недоступный образ — обновление отменено, система не изменилась; без БД `/health/ready` = 503, после возврата БД — 200 без перезапуска; диагностика (0 ошибок, 2 ожидаемых предупреждения: нет push-провайдеров и HTTP вместо HTTPS на стенде).

**Android:** 28 JVM-тестов (векторы RFC 6238 SHA1/256/512, base64url/Base32, разбор `otpauth` и `mfagate://enroll` с 27 некорректными ссылками, строка подписи и проверка подписи по SPKI, HTTP-клиент на MockWebServer); lint обоих flavors; debug и release (R8) APK обоих flavors; в foss-APK нет кода Google.

**Веб-панель:** проверка в браузере (agent-browser): 7 экранов × 7 ширин (320–1920), аудит компоновки без замечаний; вход с TOTP и push; модальные окна, меню, мобильная панель, Escape и возврат фокуса, тёмная и светлая темы; консоль без ошибок и нарушений CSP.

## Провалено

В текущей версии — нет. Найдено и исправлено в ходе работы:
- первый прогон Docker-стенда: `update` провалился, вывод не сохранялся (e2e глушил его); после добавления журналов два следующих прогона прошли — причина не установлена, возможна нестабильность ожидания healthy;
- удержание соединений БД long-poll'ом (исчерпание пула при ~20 открытых приложениях);
- 15 находок ревью безопасности (см. HISTORY.md).
