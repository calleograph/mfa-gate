# Тестирование и результаты

Последний полный прогон: 2026-11-19, версия 0.2.0.

## Как запускать

| Набор | Команда | Что нужно |
|---|---|---|
| Юнит (сервер) | `cd server && .venv/bin/pytest` | — (LDAP и сквозные пропускаются без стенда) |
| LDAP на настоящем каталоге | `server/tests/ldap_fixture/run.sh` | Docker (OpenLDAP с TLS, убирается после прогона) |
| Сквозные + жизненный цикл | `scripts/e2e.sh` | Docker; изолированный стенд со случайными портами на 127.0.0.1 |
| Сквозные против любой установки | `MFA_GATE_TEST_URL=http://IP:8080 MFA_GATE_TEST_RADIUS=IP:1812 MFA_GATE_TEST_KEY=<key_id:secret> MFA_GATE_TEST_CLIENT_CIDR=<адрес теста>/32 pytest tests/test_stack.py` | ключ API со всеми правами (`create-api-client … --scopes all`) |
| Нагрузка RADIUS | `cd server && .venv/bin/python ../scripts/radius_load.py --url … --radius … --key …` | работающая установка |
| Android | `cd android && ./gradlew :app:testFossDebugUnitTest :app:testGmsDebugUnitTest :app:assembleFossRelease :app:assembleGmsRelease` | JDK 21, Android SDK |
| Частные данные | `python3 scripts/check_private_data.py` | — |

## Пройдено

| Набор | Результат |
|---|---|
| Юнит (сервер) | 60 тестов: кодек RADIUS по векторам RFC 2865, Message-Authenticator, некорректные пакеты; политики; маскирование журнала; подпись устройства (только P-256); SecretBox с AAD; argon2; UnifiedPush отклоняет чужие и некорректные адреса; разбор логинов и подкодов AD; отказ при сбое вложенных групп; `.env.example` читается bash; строка подключения compose совпадает с учётной записью PostgreSQL; шлюз сети из `/proc/net/route` |
| LDAP на OpenLDAP | 17 тестов: вход по `user`, `DOMAIN\user`, UPN; неверный пароль; отсутствующий пользователь; пустой пароль; вложенные группы; разрешённые группы; недоступный хост; второй контроллер; LDAPS со своим CA; STARTTLS; вход без сервисной учётной записи; диагностика |
| Сквозные (`test_stack.py`) | 24 теста — см. ниже |
| Docker-стенд (`scripts/e2e.sh`) | 14 из 14 этапов: установка, повторная установка, `admin-init` не трогает существующего администратора, 24 сквозных теста в контейнерах, пересоздание без потери данных, копия, восстановление, обновление 0.1.0 → 0.1.1, откат, отмена обновления на недоступный образ (версия не меняется, сервис работает), работа без БД (503) и возврат без перезапуска, диагностика |
| Android | 31 JVM-тест в каждом варианте (foss/gms): векторы RFC 6238, base64url/Base32, разбор `otpauth` и `mfagate://enroll` (в том числе отклонение старой схемы и пометка `http://` как небезопасного), строка подписи, HTTP-клиент; lint без ошибок; собраны debug и release APK обоих вариантов, в foss нет кода Google |
| Веб-панель | agent-browser: 8 экранов × 7 ширин (320–1920), аудит компоновки без замечаний; вход с временным паролем → смена → TOTP → все разделы → смена пароля из меню; тёмная и светлая темы; клавиатура, Escape, фокус; консоль без ошибок и нарушений CSP; работа вне secure context (HTTP по имени хоста) |
| Нагрузка RADIUS (dev-стенд, 40 одновременных) | 0 ошибок: неверный пароль → Reject 30 запр./с (p50 1,2 с, p95 1,9 с — ограничено argon2id, это намеренная стойкость к перебору); TOTP через Challenge → Accept p50 1,0 с; push с подписанным подтверждением → Accept p50 1,2 с; каждое подтверждение принято ровно один раз, повтор подписи → 409 |

**Сквозные сценарии:** неизвестный RADIUS-клиент, неверный shared secret и пакет без Message-Authenticator отбрасываются; неверный пароль и неизвестный логин — одинаковый Reject; пользователь без фактора — отказ; push: подтверждение → Accept меньше чем за 3 с, отклонение, поддельная подпись (400), чужое устройство (404), повтор подписи (409), таймаут и позднее подтверждение; повторы шлюза не создают вторую транзакцию; одновременные пользователи; TOTP через Access-Challenge с защитой от повтора State и кода; REST API (push, отказ — обычный ответ `rejected`, чужой ключ — 404, ключ без прав — 403, ключ ресурса не может сменить ресурс — 403); политики deny/allow; блокировка после 8 ошибок; отозванное устройство; вход администратора с временным паролем → смена → TOTP, CSRF, ключ API не может трогать администраторов, push-вход одноразовый и без дублей, отвязка телефона не открывает подмену фактора; 40 одновременных long-poll не мешают API и RADIUS; лимит входа общий для двух экземпляров api (ровно 20 из 30); OpenVPN-скрипт (push → 1, неверный TOTP → 0).

## Приёмка на чистом Ubuntu Server (стенд в изолированной сети)

Сервер: Ubuntu 26.04.1 LTS, 2 vCPU, 3,3 ГБ ОЗУ, диск 32 ГБ (корневой раздел LVM расширен с 15 до 30 ГБ за счёт свободного места группы томов).

| Проверка | Результат |
|---|---|
| Установка из публичного GitHub: `git clone`, `cd mfa-gate`, `sudo ./install.sh` | пройдено; установщик сам поставил Docker 29.1 и Compose 2.40, собрал образ (версии в реестре ещё не было), создал администратора |
| Ошибки, найденные установкой и исправленные | версия продукта затиралась переменными `/etc/os-release`; значение с пробелом в `.env.example`; Dockerfile копировал не тот каталог; строка подключения к БД; повторный цикл событий в `create-admin`; `mfagatectl` не работал через ссылку `/usr/local/bin` |
| Повторный запуск поверх частичной установки | конфигурация и секреты сохранены, недостающий администратор создан |
| Удаление с данными (`uninstall --purge`) и установка с нуля | пройдено |
| Панель по HTTP с другой машины сети (`http://IP:8080`, не secure context) | вход с временным паролем, обязательная смена, подключение TOTP, обзор с чек-листом первичной настройки |
| LDAP через форму панели + пошаговая диагностика | все шаги пройдены |
| 24 сквозных теста по сети против установленной системы | 23 пройдено, 1 пропущен (вход администратора — пройден вручную в браузере) |
| Доменный пользователь: заведение из каталога, привязка «телефона», RADIUS доменным паролем + push | Access-Accept; неверный пароль — Reject; deny через вложенную группу; allow по группе каталога |
