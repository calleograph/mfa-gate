# Обновление

Обновление выполняет `mfagatectl update`: копия базы → новая версия → миграции → проверка → автоматический откат при сбое. Перед обновлением прочитайте [CHANGELOG.md](https://github.com/calleograph/mfa-gate/blob/main/CHANGELOG.md): версии `0.x` могут менять настройки.

## Шаг 1. Есть ли новая версия

```bash
sudo mfagatectl check-update
```

**Ожидаемый результат:** `установлена последняя версия 0.3.1` или `доступна версия 0.3.1 (установлена 0.3.0): ./mfagatectl update 0.3.1`.

Команда обращается к `api.github.com` и берёт репозиторий из `MFA_GATE_REPO` в `deploy/.env` (по умолчанию `calleograph/mfa-gate`).

## Шаг 2. Свежая копия и мастер-ключ

`update` сам делает копию базы, но перед любым обновлением убедитесь, что копия мастер-ключа у вас есть ([Резервное копирование](Резервное-копирование.md)), и проверьте место на диске (`df -h /opt`).

## Шаг 3. Обновите файлы установки

```bash
sudo git -C /opt/mfa-gate fetch --tags
sudo git -C /opt/mfa-gate checkout v0.3.1
```

**Ожидаемый результат:** `HEAD is now at …`, а `cat /opt/mfa-gate/VERSION` печатает `0.3.1`.

Каталог установки принадлежит root (установщик передаёт его root, чтобы обычный пользователь не мог подменить скрипты, которые выполняются от root), поэтому `git` запускается через `sudo`. Если вы следите за веткой `main`, а не за выпусками, вместо `checkout` — `sudo git -C /opt/mfa-gate pull`.

Так обновляются `deploy/compose.yml`, `mfagatectl` и исходники. Это важно: если образ новой версии не удастся загрузить из `ghcr.io`, `update` соберёт образ **из исходников этого каталога** — без `git checkout` вы получите старый код с новым номером. Ваши `deploy/.env`, `deploy/data`, `deploy/backups` и `deploy/compose.override.yml` в Git не хранятся и при `checkout` не меняются.

## Шаг 4. Обновление

```bash
sudo mfagatectl update 0.3.1
```

Что происходит:

1. **Копия.** Резервная копия базы в `deploy/backups/<время>-pre-0.3.1` и запись о прежней версии в `deploy/backups/last-update`.
2. **Образ.** `MFA_GATE_VERSION` в `.env` меняется на 0.3.1, образ загружается или собирается. Если образ недоступен — версия возвращается, система не меняется: `образ … недоступен — версия осталась 0.2.0, система не менялась`.
3. **Миграции.** Сервис `migrate` применяет миграции базы, затем стартуют `api`, `radius`, `worker`.
4. **Проверка.** Ожидание статуса healthy у всех трёх сервисов до 3 минут.
5. **Автооткат.** Если запуск или проверка не прошли — `rollback`: прежняя версия и база из копии шага 1, сообщение `обновление отменено, система на версии 0.3.0`.

Во время обновления (обычно 1–3 минуты) входы по VPN не проходят: запланируйте окно обслуживания.

**Ожидаемый результат:** `обновлено до 0.3.1 (копия перед обновлением: …)`.

## Шаг 5. Проверка

```bash
sudo mfagatectl status
sudo mfagatectl diagnose
```

**Ожидаемый результат:** версия `0.3.1`, все сервисы `healthy`, в диагностике нет `FAIL`, строка «Миграции» — `OK`. Выполните пробный вход в VPN.

## Откат вручную

Если после успешного обновления обнаружилась проблема:

```bash
sudo mfagatectl rollback
sudo git -C /opt/mfa-gate checkout v0.3.0
```

`rollback` возвращает версию и **базу целиком** из копии, сделанной последним `update`: миграции базы вперёд необратимы. Всё, что изменилось после обновления (новые пользователи, привязки телефонов, история входов), теряется. Прежняя база до отката сохраняется в PostgreSQL как `mfa_gate_prev` до следующего восстановления.

**Ожидаемый результат:** `восстановлено; прежняя база сохранена как mfa_gate_prev`; `sudo mfagatectl status` показывает прежнюю версию.

## Если что-то пошло не так

- `не удалось получить список выпусков` в `check-update` — нет доступа к `api.github.com` или лимит запросов GitHub; узнайте версию на странице <https://github.com/calleograph/mfa-gate/releases>.
- `версия должна быть вида 1.2.3` — укажите номер без `v`: `update 0.3.1`.
- Сервисы не стали healthy, откат не помог — `sudo mfagatectl logs migrate`, `sudo mfagatectl diagnose` и [Диагностика](Диагностика.md).
