# Обновление

*Для кого: администратор сервера MFA Gate.*

Страница описывает, как перейти на новую версию и как вернуться на прежнюю. Обновление выполняет одна команда `mfagatectl update`: она делает копию базы, ставит новую версию, применяет миграции, проверяет сервисы и при сбое сама возвращает всё как было.

## Зачем это нужно

Новые версии исправляют ошибки и уязвимости. Обновлять вручную, контейнер за контейнером, опасно: миграции базы необратимы, и неудачный запуск может оставить систему в промежуточном состоянии. `mfagatectl update` выполняет шаги в безопасном порядке и не меняет систему, если новый образ недоступен.

## Когда пригодится

- Вышел новый выпуск; узнать об этом можно командой `mfagatectl check-update`.
- После обновления обнаружилась проблема и нужно вернуться на прежнюю версию.

## Что потребуется

- Права `sudo` на сервере.
- Окно обслуживания: во время обновления, обычно 1–3 минуты, входы через VPN и в панель не проходят.
- Сохранённая вне сервера копия мастер-ключа: [Резервное копирование](Резервное-копирование.md).
- Свободное место: копия базы и новый образ. Проверьте `df -h /opt`.

## Где найти

Команды на сервере: `sudo mfagatectl check-update`, `sudo mfagatectl update <версия>`, `sudo mfagatectl rollback`. Список изменений — [Журнал изменений](Журнал-изменений.md). Кнопки обновления в панели нет.

## Как это сделать

### Шаг 1. Узнайте, есть ли новая версия

```bash
sudo mfagatectl check-update
```

**Что увидите:** `установлена последняя версия 0.3.1` или, например, `доступна версия 0.3.1 (установлена 0.3.0): ./mfagatectl update 0.3.1`.

Команда спрашивает GitHub (`api.github.com`) о последнем выпуске репозитория из `MFA_GATE_REPO` в `deploy/.env`. Прочитайте [Журнал изменений](Журнал-изменений.md): версии `0.x` могут менять настройки.

### Шаг 2. Обновите файлы установки

Каталог установки принадлежит root: установщик передаёт его root, чтобы обычный пользователь не мог подменить скрипты, которые выполняются от root. Поэтому `git` запускается через `sudo`.

```bash
sudo git -C /opt/mfa-gate pull
```

Если вы ставили конкретный выпуск по тегу, переключитесь на новый тег:

```bash
sudo git -C /opt/mfa-gate fetch --tags
sudo git -C /opt/mfa-gate checkout v0.3.1
```

**Что увидите:** `cat /opt/mfa-gate/VERSION` печатает `0.3.1`.

Этот шаг обязателен. Так обновляются `deploy/compose.yml`, сама команда `mfagatectl` и исходники. Если образ новой версии не загрузится из `ghcr.io`, `update` соберёт его из исходников этого каталога и проверит, что их версия совпадает с запрошенной. Ваши `deploy/.env`, `deploy/data`, `deploy/backups` и `deploy/compose.override.yml` в Git не хранятся и при `pull` не меняются.

### Шаг 3. Запустите обновление

```bash
sudo mfagatectl update 0.3.1
```

Номер версии указывается без `v`.

Что происходит:

1. **Копия.** База копируется в `deploy/backups/<время>-pre-0.3.1`; прежняя версия и путь к копии записываются в `deploy/backups/last-update`.
2. **Образ.** В `.env` меняется `MFA_GATE_VERSION`, образ загружается или собирается. Если образ недоступен, версия возвращается и система не меняется.
3. **Миграции.** Сервис `migrate` применяет миграции базы, затем стартуют `api`, `radius` и `worker`.
4. **Проверка.** Команда ждёт до 3 минут, пока все три сервиса станут `healthy`.
5. **Автоматический откат.** Если запуск или проверка не прошли, выполняется `rollback`: прежняя версия и база из копии шага 1.

**Что увидите:**

```text
==> обновление 0.3.0 → 0.3.1
==> резервная копия перед обновлением
==> загрузка образа ghcr.io/calleograph/mfa-gate:0.3.1
==> обновлено до 0.3.1 (копия перед обновлением: /opt/mfa-gate/deploy/backups/20261119T020000Z-pre-0.3.1)
```

### Шаг 4. Проверьте результат

```bash
sudo mfagatectl status
sudo mfagatectl diagnose
```

**Что увидите:** `версия: 0.3.1`, все сервисы `healthy`; в диагностике нет строк `FAIL`, строка `Миграции` начинается с `OK`. Выполните пробный вход в VPN и в панель.

### Откат вручную

Если после успешного обновления обнаружилась проблема, верните прежнюю версию.

1. Верните файлы установки к прежнему выпуску:

   ```bash
   sudo git -C /opt/mfa-gate checkout v0.3.0
   ```

2. Выполните откат:

   ```bash
   sudo mfagatectl rollback
   ```

**Что увидите:** `откат на 0.3.0 с восстановлением … (миграции вперёд необратимы — база возвращается из копии)`, затем `восстановлено; прежняя база сохранена как mfa_gate_prev`. `sudo mfagatectl status` показывает прежнюю версию.

**Последствия.** `rollback` возвращает базу **целиком** из копии, сделанной последним `update`. Всё, что изменилось после обновления, — новые пользователи, привязки телефонов, история входов — теряется. Телефоны, привязанные после обновления, придётся привязать заново. База, которая была до отката, остаётся в PostgreSQL под именем `mfa_gate_prev` до следующего восстановления.

Порядок «сначала `git checkout`, потом `rollback`» нужен на случай, если образ прежней версии придётся собирать из исходников: тогда исходники должны быть той же версии.

Чтобы снова обновиться, повторите шаги 2–3.

## Что получится

- `sudo mfagatectl status` показывает новую версию, сервисы `healthy`.
- В `deploy/backups` лежит копия `…-pre-<версия>`, её можно использовать для отката или восстановления.
- Пользователи, телефоны, каталог и RADIUS-клиенты на месте.

**Что проверено.** Обновление 0.2.0 → 0.3.0 по этой инструкции (`git pull`, затем `mfagatectl update`), откат на 0.2.0 и повторное обновление проверены на тестовом сервере с настоящими данными. Автоматическая отмена обновления на недоступный образ и откат проверены в сквозных тестах установки.

Копии `pre-*` остаются на диске после каждого обновления. Удаляйте старые вручную, но не трогайте ту, на которую указывает `deploy/backups/last-update`, пока не уверены в новой версии.

## Если не получается

| Что видно | Почему | Что сделать |
|---|---|---|
| `версия должна быть вида 1.2.3, получено: v0.3.1` | номер указан с `v` | `sudo mfagatectl update 0.3.1` |
| `не удалось получить список выпусков calleograph/mfa-gate` | нет доступа к `api.github.com` или исчерпан лимит запросов GitHub | посмотрите выпуски на странице репозитория |
| `образ … недоступен — версия осталась 0.3.0, система не менялась` | нет доступа к `ghcr.io`, и собрать образ нельзя | проверьте доступ к реестру; сделайте шаг 2 и повторите |
| `образа … нет в реестре, а исходники в этом каталоге — версии …` | файлы установки другой версии | выполните команды из сообщения (`fetch --tags` и `checkout v<версия>`) и повторите |
| `новая версия не стала healthy — откат на 0.3.0`, затем `обновление отменено, система на версии 0.3.0` | новая версия не запустилась | система на прежней версии; соберите `sudo mfagatectl diagnose` и смотрите `sudo mfagatectl logs migrate` |
| `нет сведений о последнем обновлении (…/last-update)` | `rollback` без предыдущего `update` | откатывать не к чему; восстановите нужную копию: [Восстановление](Восстановление.md) |
| `копия сделана с другим мастер-ключом: верните прежний data/secrets/master.key` | мастер-ключ заменён после обновления | верните прежний ключ из сохранённой копии |

Другие случаи — [Решение проблем установки и обновления](Решение-проблем-установки-и-обновления.md).
