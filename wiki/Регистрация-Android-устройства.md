# Регистрация Android-устройства

Приложение **MFA Gate Authenticator** подтверждает входы и показывает коды TOTP. Нужен телефон с Android 8.0 или новее и включённой блокировкой экрана (PIN, графический ключ или отпечаток): без неё приложение не может хранить ключ подтверждения.

Памятка для сотрудника: [docs/user-guide.md](https://github.com/calleograph/mfa-gate/blob/main/docs/user-guide.md) — её можно разослать как есть. Сотрудник может привязать телефон и сам, в [личном кабинете](Личный-кабинет-сотрудника.md); ниже — привязка администратором.

> Статус: приложение проверено JVM-тестами и сборкой; **на реальных устройствах требует проверки** (биометрия на разных версиях Android, фон, экономия энергии). Список ручных проверок: [docs/android.md](https://github.com/calleograph/mfa-gate/blob/main/docs/android.md#ручная-приёмка-на-устройстве).

## Шаг 1. Выберите вариант приложения

| Вариант | Файл в выпуске | Когда выбирать |
|---|---|---|
| `gms` | `mfa-gate-authenticator-<версия>-gms.apk` | телефон с сервисами Google и вы настроили push через FCM ([Настройка Push](Настройка-Push.md)) — уведомления приходят, даже если приложение закрыто |
| `foss` | `mfa-gate-authenticator-<версия>-foss.apk` | телефон без сервисов Google (Huawei и др.) или вы не используете FCM. Без кода Google; запрос виден, когда сотрудник открывает приложение |

Если FCM не настроен, оба варианта работают одинаково. Если сомневаетесь — берите `foss`.

## Шаг 2. Установите приложение

1. Откройте на телефоне страницу выпусков: <https://github.com/calleograph/mfa-gate/releases> → последний выпуск → раздел Assets.
2. Скачайте нужный APK.
3. Откройте файл. Android попросит разрешить установку из этого источника (браузера или диспетчера файлов) — разрешите и нажмите «Установить».

**Ожидаемый результат:** в списке приложений появилась иконка «MFA Gate».

**Как проверить подлинность файла:** в выпуске лежит `SHA256SUMS`. На компьютере: `sha256sum -c SHA256SUMS --ignore-missing` в каталоге со скачанным APK → `…apk: OK`.

Если в названии файла есть `TEST-debug-signed`, это тестовая сборка с отладочной подписью: она годится для испытаний, но обновление на подписанную версию потребует удалить и заново установить приложение (и привязать телефон заново).

Для массовой раздачи используйте вашу систему управления устройствами (MDM) с тем же APK.

## Шаг 3. Выпустите QR-код привязки

В панели (`/admin/`): «Пользователи» → карточка сотрудника → «Привязать телефон».

**Ожидаемый результат:** окно «Привязка телефона» с QR-кодом и сроком действия.

- Код одноразовый и действует 24 часа.
- В QR-код зашит адрес Device API из `MFA_GATE_DEVICE_URL`, а если он не задан — из `MFA_GATE_PUBLIC_URL`. С телефона этот адрес должен открываться из той сети, где телефон будет при входе в VPN — обычно из мобильной сети, до подключения VPN (проверьте в браузере телефона: `https://auth.example.org/api/device/v1/requests` отвечает JSON-ошибкой MFA Gate; при работе по HTTP — `http://192.0.2.10:8080/health/live`). Подробно: [Сетевая схема и публикация](Сетевая-схема-и-публикация.md).
- Не пересылайте QR-код по почте и в мессенджерах: по нему можно привязать чужой телефон. Покажите его сотруднику лично или на экране во время звонка.
- Под QR-кодом есть «Ссылка привязки для ручного ввода» — на случай, если камера не работает.

Пользователя из AD, который ещё ни разу не входил, сначала заведите: «Добавить пользователя» → источник «Из каталога», тот же логин.

## Шаг 4. Привяжите телефон

1. Откройте приложение → «Сканировать QR-код» (при первом запуске это главная кнопка на экране приветствия; потом — вкладка «Серверы»). Разрешите доступ к камере.
2. Отсканируйте QR-код из панели.
3. Проверьте на экране «Проверьте сервер» адрес сервера и учётную запись.
4. Нажмите «Привязать» и подтвердите отпечатком или PIN, если система спросит.
5. Разрешите уведомления, когда приложение попросит.

**Ожидаемый результат:** зелёная плашка «Телефон привязан». В панели в карточке сотрудника, в разделе «Телефоны», появилось устройство со статусом «Активен».

### Предупреждение о работе по HTTP

Если адрес сервера начинается с `http://`, на экране «Проверьте сервер» появится жёлтое предупреждение «Соединение без шифрования — только для изолированной тестовой сети», а кнопка «Привязать» станет активной только после отметки «Понимаю риск, это тестовая сеть». В списке серверов такой сервер помечен «Без шифрования (HTTP)».

Это ожидаемое поведение для первичной настройки. Для рабочей эксплуатации переведите сервер на HTTPS ([HTTPS через reverse proxy](HTTPS-через-reverse-proxy.md)). **После перехода на HTTPS телефоны нужно привязать заново** по новому QR-коду: адрес сервера берётся из QR-кода, перенаправления с HTTP на HTTPS приложение не выполняет.

## Шаг 5. Проверка подтверждения

1. Выполните вход в VPN под этим сотрудником (или `sudo mfagatectl radius-test <логин>` — см. [Настройка RADIUS](Настройка-RADIUS.md)).
2. На телефоне откройте приложение (в варианте `gms` с настроенным FCM придёт уведомление «Запрос на вход»).
3. Проверьте логин, ресурс, IP и нажмите «Подтвердить», подтвердите отпечатком или PIN.

**Ожидаемый результат:** на телефоне «Вход подтверждён», VPN подключился, в «Истории входов» статус «подтверждено» с методом `push`.

Без FCM сотрудник должен открыть приложение после ввода пароля, пока не истекло время ответа (45 секунд по умолчанию). Пока экран «Запросы» открыт, запросы появляются сразу.

## Замена и потеря телефона

- **Новый телефон:** выпустите новый QR-код и привяжите; старое устройство отзовите в карточке («Отозвать»). Можно наоборот: сотрудник удаляет сервер в приложении на старом телефоне («Отвязать») — устройство отзывается и на сервере.
- **Телефон потерян:** сразу «Отозвать» в карточке сотрудника. Отозванное устройство теряет доступ немедленно.
- **После добавления нового отпечатка** Android делает ключ недействительным, приложение попросит привязать телефон заново — выпустите новый QR-код.
