# Первоначальная настройка

*Для кого: главный администратор, который только что установил MFA Gate.*

Страница ведёт от первого входа в панель до системы, готовой к пилоту: временный пароль заменён, у администратора есть второй фактор, проверки состояния в порядке, понятен порядок дальнейшей настройки. На это уходит около 15 минут.

## Зачем это нужно

Установщик создаёт администратора `admin` с временным паролем, который виден на экране сервера. Пока пароль не сменён и не подключён второй фактор, войти в панель полноценно нельзя: MFA Gate требует второй фактор для любой роли, и политики это не отменяют. Сразу после входа стоит проверить состояние системы, чтобы не искать потом, почему не проходит первый вход в VPN.

## Когда пригодится

- Сразу после [Быстрой установки All-in-One](Быстрая-установка-All-in-One.md).
- После повторной установки с удалением данных.

## Что потребуется

- Адрес панели и временный пароль из итогового блока установщика.
- Телефон с приложением-аутентификатором: MFA Gate Authenticator или любым другим приложением для одноразовых кодов (TOTP).
- Компьютер в той же изолированной сети, что и сервер, пока не настроен HTTPS: [Работа по HTTP](Работа-по-HTTP.md).

## Где найти

- Панель: `http://<IP сервера>:<порт>/admin/`, например `http://192.0.2.10:8080/admin/`.
- После входа: **Панель → Обзор**, блок **Первичная настройка**.
- Проверки: **Панель → Диагностика** или команда `sudo mfagatectl diagnose` на сервере.

## Как это сделать

### Шаг 1. Войдите с временным паролем

1. Откройте адрес панели. По адресу без `/admin/` открывается личный кабинет сотрудника — это другая страница.
2. На экране **Вход в панель управления** введите **Логин** `admin` и временный **Пароль**, нажмите **Продолжить**.

**Что увидите:** экран **Смените временный пароль**.

### Шаг 2. Смените пароль

1. Поле **Текущий пароль** уже заполнено. Введите **Новый пароль** не короче 12 символов и не совпадающий с временным.
2. Повторите его в поле **Повторите новый пароль** и нажмите **Сменить пароль и продолжить**.

**Что увидите:** экран **Подключите второй фактор** с QR-кодом.

### Шаг 3. Подключите второй фактор

1. Отсканируйте QR-код приложением-аутентификатором. Если камера недоступна, введите в приложение секрет из поля **Или введите секрет вручную**; кнопка рядом копирует его.
2. Введите шесть цифр из приложения в поле **Код из приложения** и нажмите **Подтвердить и войти**.

**Что увидите:** раздел **Обзор**.

Проверьте второй фактор сразу: откройте меню профиля внизу боковой панели, нажмите **Выйти** и войдите снова. После пароля панель спросит **Код из приложения**.

Если код не подходит, сверьте время на телефоне (включите сетевое время) и на сервере (`timedatectl`).

### Шаг 4. Проверьте состояние системы

Откройте **Панель → Диагностика** или выполните на сервере:

```bash
sudo mfagatectl diagnose
```

**Что увидите** в разделе `== проверки приложения` на свежей установке:

```text
OK   База данных: PostgreSQL 16…, ответ за … мс
OK   Миграции: схема 0004, ожидается 0004
OK   Мастер-ключ: Ключ шифрования загружен
OK   RADIUS-сервер: клиентов 0, запросов 0, отброшено 0
OK   Фоновые задачи и push: работает
WARN Доставка push: провайдеры не настроены — запрос виден при открытом приложении или в foss с мгновенными уведомлениями → …
WARN Адрес портала: http://192.0.2.10:8080 — не HTTPS → …
WARN Адрес для телефонов: http://192.0.2.10:8080 — не HTTPS → …
WARN RADIUS-клиенты: активных: 0 → Добавьте VPN-шлюз в разделе «RADIUS-клиенты»
```

Предупреждения на этом этапе ожидаемы: push, HTTPS и RADIUS-клиенты вы настроите дальше. Строк `FAIL` быть не должно. Команда также создаёт архив для поддержки в `deploy/backups/diag-<время>.tar.gz` — без паролей и ключей.

### Шаг 5. Сохраните мастер-ключ и сделайте первую копию

```bash
sudo cat /opt/mfa-gate/deploy/data/secrets/master.key
sudo mfagatectl backup
```

Строку ключа сохраните вне сервера, например в менеджере паролей. Команда `backup` печатает путь к копии. Подробно и с расписанием — [Резервное копирование](Резервное-копирование.md).

### Шаг 6. Пройдите план настройки

На **Обзоре** блок **Первичная настройка** показывает пять шагов и отмечает выполненные. Ниже тот же порядок с дополнениями, которых в блоке нет.

| № | Что сделать | Где описано | Можно пропустить, если |
|---|---|---|---|
| 1 | Перевести панель на HTTPS и задать внешний адрес для телефонов | [Сценарий: переход на HTTPS и внешний адрес](Сценарий-Переход-на-HTTPS-и-внешний-адрес.md) | нельзя пропускать в рабочей эксплуатации. Сделайте это **до** привязки телефонов: адрес сервера телефон берёт из QR-кода |
| 2 | **Подключите каталог LDAP / AD** | [Подключение Active Directory](Подключение-Active-Directory.md) | все учётные записи будут локальными |
| 3 | **Добавьте защищаемый ресурс** и **Подключите RADIUS-клиент** | [Настройка RADIUS](Настройка-RADIUS.md) | VPN не нужен, только REST API |
| 4 | Настроить VPN-шлюз | [Подключение VPN](Подключение-VPN.md) | — |
| 5 | **Настройте политику доступа** | [Политики доступа](Политики-доступа.md) | устраивает правило по умолчанию: второй фактор нужен всем |
| 6 | **Привяжите телефон пользователю** — пилотному сотруднику | [Регистрация Android-устройства](Регистрация-Android-устройства.md), [Настройка TOTP](Настройка-TOTP.md) | — |
| 7 | Включить доставку push | [Настройка Push](Настройка-Push.md) | устраивает подтверждение при открытом приложении |
| 8 | Включить ежедневные копии | [Резервное копирование](Резервное-копирование.md) | нельзя пропускать |
| 9 | Добавить второго главного администратора | [Создание администратора](Создание-администратора.md) | не рекомендуется пропускать: второй администратор поможет, если первый потеряет телефон |

Без политик действует безопасное правило: второй фактор обязателен для всех, разрешены push и TOTP, пользователь без фактора получает отказ.

### Шаг 7. Проверьте вход пилотного сотрудника

Когда выполнены пункты 2–6:

1. Войдите в VPN под пилотной учётной записью.
2. Подтвердите запрос на телефоне.
3. Откройте **Панель → История входов**.

**Что увидите:** VPN подключился; в истории есть запись с вашим ресурсом и успешным результатом. Если вход не прошёл, в той же записи указана причина отказа.

## Что получится

- Администратор `admin` входит со своим паролем и вторым фактором.
- Диагностика без ошибок, предупреждения понятны.
- Мастер-ключ сохранён вне сервера, первая копия базы сделана.
- Есть план настройки, и блок **Первичная настройка** показывает, что осталось.

## Если не получается

| Что видно | Почему | Что сделать |
|---|---|---|
| «Неверный логин или пароль, либо учётная запись временно заблокирована.» | опечатка, потерянный временный пароль или 8 ошибок подряд | подождите 15 минут или задайте новый пароль: `sudo mfagatectl admin admin` |
| «Неверный или уже использованный код» | расходится время на телефоне или сервере | включите сетевое время, проверьте `timedatectl` |
| «Сессия истекла, войдите заново» | между паролем и кодом прошло больше 10 минут | войдите заново |
| `FAIL Мастер-ключ` | файл ключа повреждён или недоступен | [Диагностика](Диагностика.md) |
| `FAIL RADIUS-сервер: ни разу не отметился` | контейнер `radius` не запущен | `sudo mfagatectl logs radius` |
