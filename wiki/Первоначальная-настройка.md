# Первоначальная настройка

Страница ведёт от первого входа в панель до первого сотрудника, который входит в VPN со вторым фактором.

## Шаг 1. Первый вход и смена временного пароля

1. Откройте панель: адрес из итогового блока установщика с `/admin/` на конце, например `http://192.0.2.10:8080/admin/`. По адресу без `/admin/` открывается личный кабинет сотрудника ([Личный кабинет сотрудника](Личный-кабинет-сотрудника.md)).
2. Введите логин `admin` и временный пароль.
3. Панель покажет экран «Смените временный пароль». Введите текущий (временный) пароль и новый — не короче 12 символов, не совпадающий с временным. Нажмите «Сменить пароль и продолжить».

**Ожидаемый результат:** появляется экран «Подключите второй фактор».

**Как проверить:** в разделе «Журнал» после входа будет событие смены пароля администратора (`admin.password_changed`).

## Шаг 2. Второй фактор администратора

Вход в панель всегда требует второго фактора — для любой роли.

1. На экране «Подключите второй фактор» отсканируйте QR-код приложением-аутентификатором: MFA Gate Authenticator (вкладка «Коды») или любым TOTP-приложением.
2. Введите шестизначный код, который покажет приложение, и нажмите «Войти».

**Ожидаемый результат:** открывается раздел «Обзор».

**Как проверить:** выйдите (меню профиля внизу боковой панели → «Выйти») и войдите снова: после пароля панель спросит код из приложения.

Если код не подходит — проверьте время на телефоне (включите «Время сети») и на сервере (`timedatectl`).

## Шаг 3. Проверка состояния

Откройте раздел «Диагностика» (или выполните на сервере `sudo mfagatectl diagnose`).

**Ожидаемый результат** на свежей установке:

| Проверка | Статус | Почему |
|---|---|---|
| База данных, Миграции, Мастер-ключ | ok | — |
| Пульс `radius` и `worker` | ok | — |
| Доставка push | warning | push через FCM не настроен — это нормально, телефоны работают с открытым приложением ([Настройка Push](Настройка-Push.md)) |
| Публичный адрес | warning | адрес `http://`, а не HTTPS ([Работа по HTTP](Работа-по-HTTP.md)) |
| RADIUS-клиенты | warning | шлюзы ещё не добавлены ([Настройка RADIUS](Настройка-RADIUS.md)) |

Ошибок (`error` / `FAIL`) быть не должно. Если есть — см. [Диагностика](Диагностика.md).

## Шаг 4. План настройки

Выполните по порядку. Каждый шаг — отдельная страница.

| № | Что сделать | Страница | Можно пропустить, если |
|---|---|---|---|
| 1 | Подключить каталог сотрудников | [Подключение Active Directory](Подключение-Active-Directory.md) | пользователи будут локальными (заводятся вручную в панели) |
| 2 | Создать ресурс и RADIUS-клиент для шлюза | [Настройка RADIUS](Настройка-RADIUS.md) | VPN не нужен, только REST API |
| 3 | Настроить VPN-шлюз | [Подключение VPN](Подключение-VPN.md) | — |
| 4 | Привязать телефон тестового пользователя | [Регистрация Android-устройства](Регистрация-Android-устройства.md) | — |
| 5 | Выдать TOTP тем, у кого нет Android | [Настройка TOTP](Настройка-TOTP.md) | у всех Android |
| 6 | Включить push через FCM | [Настройка Push](Настройка-Push.md) | устроит подтверждение с открытым приложением |
| 7 | Перевести панель на HTTPS | [HTTPS через reverse proxy](HTTPS-через-reverse-proxy.md) | **нельзя пропускать** для рабочей эксплуатации |
| 8 | Включить ежедневные резервные копии | [Резервное копирование](Резервное-копирование.md) | **нельзя пропускать** |
| 9 | Добавить второго администратора | [Создание администратора](Создание-администратора.md) | — (рекомендуется, чтобы не потерять доступ) |

## Шаг 5. Политика по умолчанию

Без политик действует правило: **второй фактор обязателен для всех**, разрешены push и TOTP; пользователь без фактора получает отказ `no_factor`. Для начала этого достаточно.

Политики нужны для исключений: закрыть ресурс группе подрядчиков, оставить для старого шлюза только TOTP, временно пропускать по паролю тех, кому ещё не выдали телефон. Создаются в разделе «Политики» → «Создать политику». Модель политик и примеры: [docs/admin-guide.md](https://github.com/calleograph/mfa-gate/blob/main/docs/admin-guide.md#модель-политик).

## Шаг 6. Сквозная проверка

Когда выполнены пункты 1–4 плана:

1. Войдите в VPN под тестовым пользователем.
2. Подтвердите запрос на телефоне.
3. Откройте «История входов».

**Ожидаемый результат:** VPN подключился; в истории запись с каналом `radius`, вашим ресурсом, методом `push` и статусом «подтверждено» (`approved`).

Если вход не прошёл — в той же записи будет причина отказа. Расшифровка причин: [Диагностика](Диагностика.md), раздел «Вход не проходит».
