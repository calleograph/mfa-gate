# Архитектура: данные и шифрование

*Для кого: специалист по ИБ, администратор сервера, архитектор.*

Страница перечисляет, что MFA Gate хранит, чем защищено каждое значение, сколько хранится история и какие данные покидают сервер. Сведения сверены с `server/mfa_gate/models.py`, `security/` и `deploy/mfagatectl`. Угрозы и меры против них: [Безопасность и модель угроз](Безопасность-и-модель-угроз.md).

## Где лежат данные

Всё хранится в каталоге установки, по умолчанию `/opt/mfa-gate/deploy`.

| Путь | Что | Защита |
|---|---|---|
| `.env` | настройки экземпляра и пароль PostgreSQL | права 600, в Git не попадает |
| `data/postgres/` | файлы PostgreSQL: пользователи, факторы, история, журнал | каталог данных PostgreSQL |
| `data/secrets/master.key` | мастер-ключ | каталог `data/secrets` с правами 700; сам файл читаем процессом контейнера (uid 10001) |
| `backups/` | резервные копии базы и архивы диагностики | каталог с правами 700 |
| `compose.override.yml` | локальные дополнения, например файл учётных данных Firebase | создаётся вручную |

PostgreSQL на хост не публикуется: к базе обращаются только контейнеры проекта по внутренней сети Docker.

## Мастер-ключ

Мастер-ключ — 32 случайных байта в base64. Установщик создаёт его один раз командой `openssl rand -base64 32` и передаёт контейнерам как Docker secret: внутри контейнера это файл `/run/secrets/master_key`. В базе и в Git ключа нет.

Ключом шифруется всё, что MFA Gate должен уметь прочитать обратно:

| Значение | Где | AAD |
|---|---|---|
| секреты TOTP | `totp_factors.secret_enc` | `totp:<id фактора>` |
| общие секреты RADIUS-клиентов | `radius_clients.secret_enc` | `radius:<id клиента>` |
| пароль сервисной учётной записи каталога | `ldap_directories.bind_password_enc` | `ldap:<id каталога>` |
| токены доставки push | `devices.push_token_enc` | `push:<id устройства>` |

Алгоритм — AES-256-GCM. Формат значения: байт версии, 12 байт случайного nonce, шифртекст с тегом, всё в base64. Дополнительные данные AAD привязывают шифртекст к своей записи: секрет одного RADIUS-клиента нельзя подставить в запись другого, расшифровка не пройдёт. Версия формата оставляет место для будущей смены ключа.

**Без мастер-ключа резервная копия бесполезна.** Секреты TOTP, RADIUS и каталога из неё не расшифровать. Храните копию ключа отдельно от сервера и от копий базы: [Резервное копирование](Резервное-копирование.md).

Смены мастер-ключа с перешифрованием пока нет: [Планы развития](Планы-развития.md).

## Что хранится хешем

То, что MFA Gate должен только сверять, хранится необратимо.

| Значение | Как хранится | Почему так |
|---|---|---|
| пароли локальных учётных записей | argon2id, параметры библиотеки по умолчанию | пароль придумывает человек: нужна стойкость к перебору |
| `device_secret` телефона | SHA-256 | 32 случайных байта: подбор невозможен, медленный хеш не нужен |
| секреты ключей API | SHA-256 | то же |
| токены ссылок привязки | SHA-256 | то же, плюс одноразовость и срок |
| токены сессий кабинета и панели | SHA-256 | идентификатор сессии в базе — хеш cookie |
| резервные коды | HMAC-SHA256 на ключе, производном от мастер-ключа, с привязкой к пользователю | у кода около 50 бит: без `master.key` украденную базу нельзя перебирать офлайн. Коды, выпущенные в 0.3.0 (обычный SHA-256), тоже принимаются |
| аварийные коды администратора | SHA-256 | одноразовые, 15 минут |

Открытые значения не хранятся: сервер ищет запись по хешу предъявленного значения, поэтому утечка базы не раскрывает сами токены и ключи. Пароли доменных учётных записей MFA Gate не хранит вовсе: он проверяет их в каталоге при каждом входе.

## Что хранится открыто

| Данные | Таблица | Зачем |
|---|---|---|
| логин, имя, почта, телефон, источник, группы каталога | `users` | показ в панели, политики по группам |
| открытый ключ телефона (P-256, SPKI) | `devices.public_key` | проверка подписи решения |
| запросы входа: логин, ресурс, канал, адрес сотрудника, адрес NAS, способ, итог, причина | `auth_requests` | **История входов** и её вид **Проблемы входа** |
| журнал действий | `audit_events` | **Журнал**: кто, что, когда, с какого адреса |
| счётчики лимитов частоты | `rate_limits` | защита от перебора |

В журнал не попадают пароли, коды, секреты, токены и подписи: значения полей с такими именами маскируются всегда. Архив диагностики `mfagatectl diagnose` проверяется на значения секретов и не создаётся, если они нашлись.

## Сроки хранения

Очистку выполняет `worker`, проверка идёт каждые 10 с.

| Данные | Срок по умолчанию | Переменная |
|---|---|---|
| запросы входа (**История входов**) | 180 дней | `MFA_GATE_AUTH_REQUEST_RETENTION_DAYS` |
| журнал аудита | 365 дней | `MFA_GATE_AUDIT_RETENTION_DAYS` |
| сессии кабинета и панели | до истечения срока сессии | — |
| счётчики лимитов | 1 час | — |
| строки очереди push, не отправленные за 10 минут | помечаются неудачными | — |
| запросы push без ответа | помечаются истёкшими сразу после срока | `MFA_GATE_PUSH_TIMEOUT` |

Сроки меняют в `deploy/.env` и применяют командой `sudo mfagatectl start`. Полный перечень переменных: [Справочник: конфигурация](Справочник-конфигурация.md).

## Что знает телефон

| Что | Где на телефоне |
|---|---|
| закрытый ключ подписи P-256 | Android Keystore, не извлекается; каждая подпись требует биометрии или PIN |
| `device_secret` | зашифрован AES-GCM ключом из Keystore |
| секреты TOTP | зашифрованы ключом из Keystore |
| адрес сервера | из QR-кода привязки |

По каждому запросу телефон получает логин, название ресурса, адрес сотрудника (Calling-Station-Id или `source_ip`), имя клиента, время создания и срок. Историю он видит только по своему пользователю.

## Что уходит с сервера наружу

| Куда | Что передаётся | Когда |
|---|---|---|
| контроллеры домена, LDAPS 636 | логин и пароль при проверке, поиск пользователя и групп | при каждом входе с проверкой пароля в MFA Gate |
| `oauth2.googleapis.com` | подписанный запрос токена доступа service account | при включённом FCM, раз в час |
| `fcm.googleapis.com` | токен устройства и сигнал `{"type": "auth_request", "request_id", "device_id", "v": "1"}` | при каждом push, если FCM включён |
| хосты Huawei Push Kit, распределитель UnifiedPush | тот же сигнал | только если эти способы включены (экспериментально) |
| `ghcr.io`, `github.com`, `api.github.com` | запросы образов и сведений о версиях | при установке, проверке версии и обновлении |

Логин, ресурс и адрес сотрудника через Google не проходят. Телефон забирает их с сервера сам по HTTPS.

Что сервер принимает снаружи: только запросы телефонов к `/api/device/` на внешнем адресе. Остальные пути на внешнем имени закрыты в прокси и в самом сервере: [Сетевая схема и публикация](Сетевая-схема-и-публикация.md).

## Что передаётся по сети внутри организации

| Поток | Защита | Что видно на пути |
|---|---|---|
| шлюз → `radius`, UDP 1812 | пароль PAP зашифрован общим секретом, пакет подписан Message-Authenticator | логин, Calling-Station-Id и другие атрибуты передаются открыто |
| браузеры и приложения → прокси | TLS | ничего |
| прокси → `api` | HTTP по `127.0.0.1` или по выделенному адресу | на одном хосте — ничего; прокси в DMZ — трафик между прокси и сервером |
| `api` и `radius` → каталог | LDAPS или StartTLS с проверкой сертификата | ничего при включённой проверке |

RADIUS скрывает только пароль. Между площадками по недоверенной сети пускайте его внутри IPsec или WireGuard. RadSec (RADIUS поверх TLS) не реализован.

## Резервная копия

`sudo mfagatectl backup` выполняет `pg_dump` базы в отдельный каталог внутри `backups/` и пишет манифест: версию продукта, версию схемы, время и первые 16 символов SHA-256 мастер-ключа. Сам ключ в копию не входит.

При восстановлении `mfagatectl` сверяет отпечаток ключа из манифеста с текущим файлом `master.key`. Если ключ другой, восстановление останавливается с сообщением «копия сделана с другим мастер-ключом». Порядок восстановления: [Восстановление](Восстановление.md).
