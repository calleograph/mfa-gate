# Требования к серверу

Установщик `install.sh` сам проверяет эти условия на первом этапе и останавливается с понятным сообщением, если чего-то не хватает. Ниже — как проверить заранее.

## Минимальные требования

| Что | Минимум | Рекомендуется |
|---|---|---|
| ОС | Ubuntu 22.04 или Debian 12 | Ubuntu 24.04 LTS |
| Архитектура | x86_64 или aarch64 | x86_64 |
| Процессор | 1 vCPU | 2 vCPU |
| Память | 1 ГБ | 2 ГБ |
| Свободное место | 5 ГБ на разделе с каталогом установки | 20 ГБ (история входов и резервные копии растут) |
| Доступ в Интернет | к `ghcr.io` или `github.com`, к зеркалам пакетов ОС | — |
| Права | пользователь с `sudo` | — |

Docker ставить заранее не нужно: установщик поставит `docker.io` и `docker-compose-v2` из репозитория ОС, а если их нет — Docker Engine официальным скриптом `get.docker.com`. Если Docker уже стоит, он используется как есть (нужен Docker Compose v2).

На других ОС (RHEL, Rocky, Alma и т. п.) установщик не работает. Там нужна ручная установка: [docs/install.md](https://github.com/calleograph/mfa-gate/blob/main/docs/install.md#ручная-установка).

## Сеть

| Направление | Порт | Зачем |
|---|---|---|
| VPN-шлюзы → сервер | UDP 1812 | RADIUS. Открывайте только адресам шлюзов |
| Администраторы и сотрудники → сервер | TCP 8080 (до HTTPS) или 443 (после настройки HTTPS), из внутренней сети и VPN | панель (`/admin/`) и личный кабинет (`/`) |
| Телефоны сотрудников → сервер | TCP 443 на внешний адрес Device API (`MFA_GATE_DEVICE_URL`), только `/api/device/` | телефоны забирают запросы и отправляют решения. Телефон подтверждает вход до подключения VPN, поэтому доступ нужен из Интернета: [Сетевая схема и публикация](Сетевая-схема-и-публикация.md) |
| Сервер → контроллеры домена | TCP 636 (LDAPS) или 389 (StartTLS) | проверка паролей и групп |
| Сервер → `fcm.googleapis.com`, `oauth2.googleapis.com` | TCP 443 | только если включён push через FCM |
| Сервер → `ghcr.io`, `github.com` | TCP 443 | установка и обновление |

Порты 8080 и 1812 можно изменить при установке (см. [Быстрая установка All-in-One](Быстрая-установка-All-in-One.md)).

## Проверка перед установкой

### 1. Версия ОС и архитектура

```bash
. /etc/os-release && echo "$PRETTY_NAME"; uname -m
```

**Ожидаемый результат:** `Ubuntu 22.04…`/`Ubuntu 24.04…` или `Debian GNU/Linux 12…`, затем `x86_64` или `aarch64`.

### 2. Память и диск

```bash
free -h | sed -n 2p; df -h /opt | tail -n1
```

**Ожидаемый результат:** в строке `Mem:` общий объём не меньше `1.0Gi`; в колонке `Avail` для `/opt` — не меньше `5G`.

### 3. Доступ в Интернет

```bash
curl -fsS -o /dev/null -w '%{http_code}\n' https://ghcr.io/ ; curl -fsS -o /dev/null -w '%{http_code}\n' https://github.com/
```

**Ожидаемый результат:** хотя бы одна команда печатает код `200` (или `3xx`).

**Если не работает:** проверьте DNS (`resolvectl status`), шлюз по умолчанию (`ip route`) и прокси. Если в сети обязателен HTTP-прокси, задайте его перед установкой: `export https_proxy=http://proxy.example.org:3128` и запускайте `sudo -E ./install.sh`. Сам Docker переменные оболочки не видит: прокси для загрузки образов задаётся в службе Docker:

```bash
sudo mkdir -p /etc/systemd/system/docker.service.d
printf '[Service]\nEnvironment="HTTPS_PROXY=http://proxy.example.org:3128"\n' | sudo tee /etc/systemd/system/docker.service.d/proxy.conf
sudo systemctl daemon-reload && sudo systemctl restart docker
```

Если Docker ещё не установлен, выполните эти команды после первого запуска установщика и повторите `sudo ./install.sh`.

### 4. Свободные порты

```bash
sudo ss -ltnp 'sport = :8080'; sudo ss -lunp 'sport = :1812'
```

**Ожидаемый результат:** обе команды печатают только строку заголовка — порты свободны.

Если 8080 занят, установщик сам возьмёт следующий свободный порт до 8100. Если занят 1812 (например, стоит FreeRADIUS), установщик остановится — задайте другой порт (см. [Быстрая установка All-in-One](Быстрая-установка-All-in-One.md)).

### 5. Точное время

Коды TOTP и сроки запросов зависят от часов сервера.

```bash
timedatectl | grep -E 'synchronized|NTP service'
```

**Ожидаемый результат:** `System clock synchronized: yes` и `NTP service: active`.

**Если нет:** `sudo timedatectl set-ntp true`, через минуту повторите проверку.

### 6. Постоянный адрес

Адрес сервера попадает в QR-коды привязки телефонов. Дайте серверу постоянный IP (статический или закреплённый в DHCP) и, лучше сразу, DNS-имя, например `mfa.example.org`. Сменить адрес потом можно, но телефоны придётся привязать заново.

## Где разместить каталог установки

Все данные (база, мастер-ключ, копии) хранятся внутри клонированного каталога, в `deploy/data` и `deploy/backups`. Выберите постоянное место, например `/opt/mfa-gate`, и не удаляйте этот каталог.
