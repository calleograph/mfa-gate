# Требования к серверу

*Для кого: системный администратор, который готовит сервер под MFA Gate.*

Страница помогает за десять минут проверить сервер до установки: подходит ли система, хватит ли памяти и диска, открыта ли сеть. Установщик `install.sh` проверяет те же условия на первом этапе и останавливается с понятным сообщением, но заранее выяснить это проще, чем разбирать ошибку посреди установки.

## Зачем это нужно

MFA Gate ставится одной командой, но только при выполнении нескольких условий: подходящая ОС, доступ в Интернет для загрузки Docker и образа, свободные порты. Кроме того, у сервера должен быть постоянный адрес: он попадает в QR-коды привязки телефонов и в настройки VPN-шлюзов. Сменить его потом можно, но телефоны придётся привязывать заново.

## Когда пригодится

- Вы выбираете или заказываете сервер под MFA Gate.
- Установщик остановился на этапе «Проверка сервера» или «Конфигурация».
- Вы переносите MFA Gate на другой сервер.

## Что потребуется

- Доступ к серверу по SSH и права `sudo`.
- Сведения о сети: адрес сервера, DNS-имя (если уже есть), адреса VPN-шлюзов.

## Пороги установщика

Установщик сравнивает сервер с порогами ниже. Это минимальные условия, при которых установка вообще запускается, а не оценка производительности.

| Что | Порог `install.sh` | Что будет, если не выполнено |
|---|---|---|
| ОС | Ubuntu или Debian. В подсказке установщика: Ubuntu 22.04 и новее, Debian 12 | `ОС … не поддерживается установщиком` |
| Архитектура | x86_64 или aarch64 | `архитектура … не поддерживается` |
| Память | не меньше 900 МБ (в подсказке — «нужно не меньше 1 ГБ») | `мало памяти: … МБ` |
| Диск | не меньше 5 ГБ свободно на разделе с каталогом установки | `мало места на диске: … ГБ` |
| Интернет | ответ от `ghcr.io` или `github.com` | `нет доступа к ghcr.io и github.com` |
| Права | запуск от root (`sudo`) | `Запустите установку с правами администратора: sudo ./install.sh` |

Число процессоров установщик не проверяет.

**Где проверено.** Установка из публичного репозитория проверена на чистом Ubuntu Server 26.04.1 LTS: 2 vCPU, 3,3 ГБ памяти, диск 32 ГБ. Нагрузочный замер RADIUS (40 одновременных запросов, без ошибок) выполнен на сервере разработки и относится только к RADIUS-части; на рабочей нагрузке организации система не измерялась. Подробности — [Что проверено](Что-проверено.md).

**Сколько места займут данные — неизвестно,** это зависит от числа входов. По умолчанию история входов хранится 180 дней, журнал аудита — 365 дней. Перед каждым обновлением создаётся копия базы, и копии остаются на том же диске, пока вы их не удалите. Оставьте запас сверх 5 ГБ и следите за местом командой `df -h`.

Docker заранее ставить не нужно. Установщик возьмёт пакеты `docker.io` и `docker-compose-v2` из репозитория ОС, а если их нет — поставит Docker официальным скриптом `get.docker.com`. Уже установленный Docker используется как есть; нужен Docker Compose v2.

На других системах (RHEL, Rocky Linux, AlmaLinux и подобных) установщик не работает. Там возможна ручная установка: Linux x86_64 или aarch64, Docker Engine 24 и новее с Compose v2, `openssl`, `curl`, `ss`. Порядок описан в [docs/install.md](https://github.com/calleograph/mfa-gate/blob/main/docs/install.md#ручная-установка).

## Сеть

| Направление | Порт | Зачем |
|---|---|---|
| VPN-шлюзы → сервер | UDP 1812 | RADIUS-запросы. Открывайте только адресам шлюзов |
| Администраторы и сотрудники → сервер | TCP 8080 до настройки HTTPS, затем TCP 443 | панель `/admin/` и личный кабинет `/`. Только из внутренней сети и VPN |
| Телефоны сотрудников → внешний адрес | TCP 443, только путь `/api/device/` | телефон подтверждает вход до подключения VPN, поэтому ему нужен доступ из Интернета |
| Сервер → контроллеры домена | TCP 636 (LDAPS) или 389 (StartTLS) | проверка паролей и групп |
| Сервер → `ghcr.io`, `github.com`, `api.github.com` | TCP 443 | установка, обновление, проверка новых версий |
| Сервер → `fcm.googleapis.com`, `oauth2.googleapis.com` | TCP 443 | только если включена доставка push через Firebase Cloud Messaging |
| Сервер → NTP | UDP 123 | точное время: от него зависят коды TOTP и сроки запросов |

Порты 8080 и 1812 можно сменить при установке: [Быстрая установка All-in-One](Быстрая-установка-All-in-One.md). Полная сетевая схема — [Сетевая схема и публикация](Сетевая-схема-и-публикация.md).

## Как проверить сервер

### Шаг 1. ОС и архитектура

```bash
. /etc/os-release && echo "$PRETTY_NAME"; uname -m
```

**Что увидите:** например, `Ubuntu 24.04.1 LTS` и `x86_64`.

### Шаг 2. Память и диск

Установщик смотрит свободное место на разделе, где лежит каталог установки. В примерах это `/opt/mfa-gate`, поэтому проверяем `/opt`.

```bash
free -h | sed -n 2p; df -h /opt | tail -n1
```

**Что увидите:** в строке `Mem:` общий объём не меньше `1.0Gi`; в столбце `Avail` — не меньше `5G`.

### Шаг 3. Доступ в Интернет

```bash
curl -fsS -o /dev/null -w '%{http_code}\n' https://ghcr.io/
curl -fsS -o /dev/null -w '%{http_code}\n' https://github.com/
```

**Что увидите:** хотя бы одна команда печатает `200` или код `3xx`.

Если в сети обязателен HTTP-прокси, задайте его перед установкой и запускайте установщик с `sudo -E`, чтобы переменная дошла до него:

```bash
export https_proxy=http://proxy.example.org:3128
sudo -E ./install.sh
```

Docker переменных оболочки не видит: для загрузки образов прокси задаётся в службе Docker.

```bash
sudo mkdir -p /etc/systemd/system/docker.service.d
printf '[Service]\nEnvironment="HTTPS_PROXY=http://proxy.example.org:3128"\n' | sudo tee /etc/systemd/system/docker.service.d/proxy.conf
sudo systemctl daemon-reload && sudo systemctl restart docker
```

Если Docker ещё не установлен, выполните эти команды после первого запуска установщика и запустите его снова.

### Шаг 4. Свободные порты

```bash
sudo ss -ltnp 'sport = :8080'; sudo ss -lunp 'sport = :1812'
```

**Что увидите:** только строки заголовков — порты свободны.

Если 8080 занят, установщик сам возьмёт следующий свободный порт до 8100. Если занят UDP 1812, например уже работает другой RADIUS-сервер, установщик остановится: задайте другой порт при запуске.

### Шаг 5. Точное время

```bash
timedatectl | grep -E 'synchronized|NTP service'
```

**Что увидите:** `System clock synchronized: yes` и `NTP service: active`. Если нет, выполните `sudo timedatectl set-ntp true` и через минуту проверьте снова.

### Шаг 6. Постоянный адрес и имена

Дайте серверу постоянный IP-адрес (статический или закреплённый в DHCP). Лучше сразу заведите DNS-имена:

- внутреннее, например `mfa.example.org`, — для кабинета и панели;
- внешнее, например `auth.example.org`, — для телефонов, если сотрудники будут входить в VPN из дома.

Телефон берёт адрес сервера из QR-кода. Если сначала привязать телефоны по IP-адресу, а потом перейти на имена, привязку придётся повторить.

## Где разместить каталог установки

MFA Gate ставится командой `git clone` в любой каталог. Все данные живут внутри него: база — в `deploy/data/postgres`, мастер-ключ — в `deploy/data/secrets/master.key`, копии — в `deploy/backups`. Выберите постоянное место, например `/opt/mfa-gate`, и не удаляйте этот каталог.

## Что получится

Сервер удовлетворяет порогам установщика, порты свободны, время синхронизировано, адрес не будет меняться. Можно запускать установку.

## Если не получается

| Что видно | Почему | Что сделать |
|---|---|---|
| `curl: (6) Could not resolve host` | не работает DNS | проверьте `resolvectl status` |
| `curl: (7)` или `(28)` | исходящий 443 закрыт межсетевым экраном | откройте TCP 443 к `ghcr.io` и `github.com` или задайте прокси |
| Порт 1812/udp занят | на сервере работает другой RADIUS-сервер | освободите порт или задайте при установке `MFA_GATE_RADIUS_PORT` |
| Меньше 5 ГБ свободно | маленький корневой раздел | расширьте раздел или клонируйте проект на другой диск |
