# Руководство администратора

*Для кого: администратор, который отвечает за MFA Gate целиком — от сервера до сотрудников.*

Эта страница — обзор работы администратора: из чего состоит система, за что вы отвечаете, где что находится в панели и на сервере, в каком порядке вводить MFA Gate в работу и что делать регулярно. Подробности каждой задачи — на отдельных страницах, ссылки даны по ходу.

## Что вы администрируете

MFA Gate добавляет второй фактор ко входу в VPN и в собственные приложения организации. VPN-шлюз спрашивает MFA Gate по протоколу RADIUS, можно ли впустить сотрудника. Пароль проверяет MFA Gate (по своей базе или через каталог) либо сам шлюз. Затем MFA Gate проверяет второй фактор — подтверждение на телефоне или одноразовый код — и отвечает «пустить» или «не пускать».

В установке All-in-One на одном сервере работают пять сервисов Docker:

| Сервис | Что делает | Доступ снаружи |
|---|---|---|
| `postgres` | база данных PostgreSQL 16 | нет |
| `migrate` | применяет миграции базы при запуске и обновлении, затем завершается | нет |
| `api` | личный кабинет `/`, панель `/admin/`, REST API `/api/v1/`, Device API для телефонов `/api/device/v1/` | HTTP, по умолчанию порт 8080, в работе — через reverse proxy |
| `radius` | RADIUS-сервер для VPN-шлюзов | UDP 1812 |
| `worker` | доставка push, истечение запросов, очистка по срокам хранения | нет |

У системы два адреса: внутренний `https://mfa.example.org/` для кабинета и панели (`/admin/`) и внешний `https://auth.example.org` для телефонов, через который наружу публикуется только `/api/device/`. Подробно — [Сетевая схема и публикация](Сетевая-схема-и-публикация.md).

## Ваши обязанности

- **Сервер.** Установка, HTTPS, межсетевой экран, обновления, резервные копии, восстановление.
- **Доступ.** Каталог Active Directory, ресурсы и RADIUS-клиенты, политики доступа, роли других администраторов.
- **Сотрудники.** Правила самостоятельной настройки в кабинете, помощь при потере телефона, отключение уволенных.
- **Контроль.** История входов, проблемы входа, журнал аудита, подозрительные отклонённые запросы.

## Сервер: файлы и команды

Все данные хранятся в каталоге установки, в примерах — `/opt/mfa-gate`.

| Путь | Что это |
|---|---|
| `deploy/.env` | конфигурация экземпляра и пароль базы, права 600 |
| `deploy/data/postgres/` | файлы базы |
| `deploy/data/secrets/master.key` | мастер-ключ: им зашифрованы секреты TOTP, RADIUS, каталога и push-токены |
| `deploy/backups/` | резервные копии, отметка последнего обновления, архивы диагностики |
| `/var/log/mfa-gate/` | журналы установщика |

Управление — командой `sudo mfagatectl`:

| Команда | Для чего |
|---|---|
| `status`, `logs [сервис]`, `diagnose` | состояние, журналы, проверки и архив для поддержки |
| `start`, `stop`, `restart [сервис]` | запуск и остановка; после правки `.env` — `start` |
| `check-update`, `update <версия>`, `rollback` | обновление и откат |
| `backup`, `restore <каталог>` | копии и восстановление |
| `admin <логин>`, `emergency <логин>` | восстановление доступа администратора |
| `radius-test <логин>` | пробный RADIUS-запрос с сервера |
| `uninstall [--purge]` | удаление |

Полный перечень — [Справочник: команды mfagatectl](Справочник-команды-mfagatectl.md), переменные — [Справочник: конфигурация](Справочник-конфигурация.md).

## Регулярные работы

| Как часто | Что сделать | Где |
|---|---|---|
| Ежедневно | посмотреть **Обзор → Что требует действий**: отклонённые на телефоне запросы, пользователи без фактора, блокировки | панель |
| Ежедневно | убедиться, что появилась ночная копия (расписание настраивается вручную: [Резервное копирование](Резервное-копирование.md)) | `sudo ls -1t /opt/mfa-gate/deploy/backups` |
| Еженедельно | разобрать **Проблемы входа** и события уровня «предупреждение» в **Журнале** | панель |
| Еженедельно | `sudo mfagatectl diagnose` или **Диагностика** — без ошибок | сервер или панель |
| Ежемесячно | `sudo mfagatectl check-update`, при новой версии — обновление в окно обслуживания | [Обновление](Обновление.md) |
| Ежемесячно | проверить свободное место (`df -h`), удалить старые копии `pre-*` и архивы `diag-*` | сервер |
| Раз в квартал | восстановить копию на отдельном сервере | [Восстановление](Восстановление.md) |
| Раз в квартал | пересмотреть список администраторов и их роли, отключить лишних | [Роли администраторов](Роли-администраторов.md) |
| При увольнении | отключить учётную запись и отозвать устройства | [Сценарий: увольнение сотрудника](Сценарий-Увольнение-сотрудника.md) |

Отклонённый на телефоне запрос — важный сигнал: если сотрудник не входил сам, его пароль, вероятно, известен постороннему. Свяжитесь с сотрудником и смените пароль.

## Чего в продукте нет

Нет кнопки обновления в панели: обновление выполняется на сервере. Нет RADIUS Accounting, RadSec, подтверждения вводом числа, WebAuthn и приглашений по почте. Полный перечень и планы — [Возможности](Возможности.md) и [Планы развития](Планы-развития.md).

Что проверено на настоящей инфраструктуре: установка на чистый Ubuntu, обновление и откат на тестовом сервере, вход по RADIUS с подтверждением в сквозных тестах, личный кабинет с настоящим каталогом. Не проверены реальные VPN-шлюзы, реальный Active Directory (каталог проверен на OpenLDAP), приложение на реальных телефонах и доставка через Firebase. Подробно — [Что проверено](Что-проверено.md).
