# Справочник: роли и права

*Для кого: главный администратор, специалист по информационной безопасности, аудитор.*

В панели MFA Gate четыре роли администраторов. Ключи REST API получают права из того же набора строк, что и роли. Здесь собрано, что разрешает каждая роль и каждое право, какие действия доступны только главному администратору и что можно сделать в обход панели из консоли сервера.

Права проверяет сервер при каждом запросе. Панель только скрывает разделы и кнопки, на которые прав нет: если вызвать API напрямую, сервер всё равно ответит отказом `403`.

Пошаговое назначение ролей — [Роли администраторов](Роли-администраторов.md).

## Роли

| Роль в панели | Код | Кратко |
| --- | --- | --- |
| Главный администратор | `superadmin` | Все права, в том числе назначение ролей и управление учётными записями других администраторов |
| Администратор | `admin` | Все разделы на чтение и изменение, кроме управления администраторами |
| Оператор | `operator` | Повседневная поддержка сотрудников: пользователи и их телефоны и коды. Остальное — только просмотр, без RADIUS-клиентов, ключей API и каталогов |
| Аудитор | `auditor` | Только просмотр всех разделов |

Сотрудник без роли в панель не входит: у него есть только личный кабинет. Сессия кабинета не открывает панель — для панели нужен отдельный вход со своим вторым фактором.

## Права по областям

Право записывается как `<область>:read` (просмотр) или `<область>:write` (изменение).

| Область | Что охватывает | Главный администратор | Администратор | Оператор | Аудитор |
| --- | --- | --- | --- | --- | --- |
| `users` | Пользователи: список, карточка, создание, изменение, отключение, удаление, снятие блокировки | чтение, изменение | чтение, изменение | чтение, изменение | чтение |
| `devices` | Телефоны и коды: привязка телефона, выпуск и удаление TOTP, отзыв устройства, **Разрешить повторную настройку**, **Сбросить резервные коды** | чтение, изменение | чтение, изменение | чтение, изменение | чтение |
| `groups` | Группы и их сопоставление с группами каталога | чтение, изменение | чтение, изменение | чтение | чтение |
| `resources` | Ресурсы (VPN, приложения) | чтение, изменение | чтение, изменение | чтение | чтение |
| `policies` | Политики доступа | чтение, изменение | чтение, изменение | чтение | чтение |
| `radius` | RADIUS-клиенты и их секреты | чтение, изменение | чтение, изменение | — | чтение |
| `ldap` | Каталоги LDAP / AD и их диагностика | чтение, изменение | чтение, изменение | — | чтение |
| `apiclients` | Ключи REST API: выпуск, изменение, смена секрета, удаление | чтение, изменение | чтение, изменение | — | чтение |
| `requests` | **История входов** и **Проблемы входа** | чтение | чтение | чтение | чтение |
| `audit` | **Журнал** аудита и выгрузка CSV | чтение | чтение | чтение | чтение |
| `system` | **Обзор**, **Адреса и публикация**, **Диагностика** | чтение | чтение | чтение | чтение |
| `auth` | Запросы проверки второго фактора через REST API (`auth:write`) | чтение, изменение | чтение, изменение | — | чтение |
| `admins` | Управление администраторами | все действия | чтение | — | чтение |

Права `requests:write`, `audit:write`, `system:write`, `auth:read` и `admins:read` входят в роли, но ни один раздел их сейчас не проверяет. Журнал аудита и историю входов нельзя изменить ни в одной роли.

## Разделы меню панели

| Раздел | Нужное право | Видят |
| --- | --- | --- |
| **Обзор** | `system:read` | все роли |
| **Доступ → Пользователи** | `users:read` | все роли |
| **Доступ → Группы** | `groups:read` | все роли |
| **Доступ → Устройства** | `devices:read` | все роли |
| **Интеграции → Ресурсы** | `resources:read` | все роли |
| **Интеграции → RADIUS-клиенты** | `radius:read` | главный администратор, администратор, аудитор |
| **Интеграции → API-клиенты** | `apiclients:read` | главный администратор, администратор, аудитор |
| **Интеграции → LDAP / AD** | `ldap:read` | главный администратор, администратор, аудитор |
| **Интеграции → Адреса и публикация** | `system:read` | все роли |
| **Контроль → Политики** | `policies:read` | все роли |
| **Контроль → История входов** | `requests:read` | все роли |
| **Контроль → Проблемы входа** | `requests:read` | все роли |
| **Контроль → Журнал** | `audit:read` | все роли |
| **Контроль → Диагностика** | `system:read` | все роли |

## Что может только главный администратор

Эти действия требуют права `admins:write`, которое есть только у роли «Главный администратор».

| Действие | Почему ограничено |
| --- | --- |
| Назначить, сменить или снять роль, в том числе при создании пользователя | Иначе администратор мог бы повысить себя или другого |
| Изменить учётную запись, у которой есть роль: имя, почта, пароль, статус, группы | Иначе оператор сменил бы пароль администратора и вошёл под ним |
| Снять блокировку, удалить учётную запись администратора | То же |
| Привязать телефон, выпустить или удалить TOTP, отозвать устройство, разрешить повторную настройку, сбросить резервные коды у администратора | Иначе можно выпустить себе второй фактор чужой учётной записи |

Дополнительно сервер не даст отключить, удалить или лишить роли **последнего** активного главного администратора: ответ `409` с кодом `last_superadmin`.

## Ключи REST API

Ключ получает список прав (scopes) при выпуске. Доступны все права вида `<область>:read` и `<область>:write`, **кроме области `admins`**. Поэтому ключ API не может назначать роли и менять учётные записи администраторов, даже если у него есть `users:write`.

| Ограничение ключа | Что даёт |
| --- | --- |
| Список прав | Для интеграции VPN-портала или приложения обычно достаточно `auth:write` |
| Привязка к ресурсу | Ключ запрашивает вход только в свой ресурс; попытка сменить ресурс — `403 resource_mismatch` |
| Разрешённые сети | Запросы с других адресов — `403 ip_not_allowed` |
| Отключение и смена секрета | Старый секрет перестаёт действовать сразу |

Запрос, созданный ключом, виден только этому ключу. Подробно — [Ключи API](Ключи-API.md).

## Вход в панель

- Второй фактор обязателен для любой роли и политиками не отменяется. До второго фактора сессия живёт 10 минут и даёт доступ только к шагам входа.
- После входа сессия действует 30 минут и продлевается при работе (`MFA_GATE_ADMIN_SESSION_MINUTES`).
- Каждый изменяющий запрос панели проверяется по токену CSRF.
- Попытки входа ограничены: 20 в минуту с одного адреса.

## Действия из консоли сервера

Тот, у кого есть root на сервере, действует в обход ролей. Это осознанное решение: консоль — последний способ вернуть доступ.

| Команда | Что даёт | Журнал |
| --- | --- | --- |
| `mfagatectl admin <логин>` | Создать или восстановить локального главного администратора | `admin.created_cli`, «Внимание» |
| `mfagatectl admin-init` | Первый главный администратор `admin` с временным паролем | `admin.created_cli` |
| `mfagatectl emergency <логин>` | Одноразовый код вместо второго фактора для любой роли администратора, 15 минут | `admin.emergency_code_issued` и `admin.emergency_access`, «Критичное» |
| `python -m mfa_gate create-api-client` | Ключ API с любыми правами, кроме `admins` | `api_client.created`, «Внимание» |

Поэтому доступ к серверу, файлу `deploy/.env` и каталогу `deploy/data/secrets` нужно ограничивать так же строго, как роль главного администратора.
