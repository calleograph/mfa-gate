# Работа по HTTP

После установки All-in-One личный кабинет (`/`), панель (`/admin/`) и Device API работают по `http://IP:8080` без шифрования. Это сделано, чтобы систему можно было поставить и настроить без DNS-имени и сертификата. **Для рабочей эксплуатации переведите сервер на HTTPS:** [HTTPS через reverse proxy](HTTPS-через-reverse-proxy.md).

## Что работает по HTTP

| Функция | По HTTP |
|---|---|
| Вход в панель, все разделы | работает. Cookie сессии выдаётся без флага `Secure`, потому что запрос пришёл по HTTP (`MFA_GATE_COOKIE_SECURE=auto`) |
| Личный кабинет сотрудника | работает так же; доменный пароль сотрудника идёт открытым текстом — до HTTPS не приглашайте сотрудников в кабинет |
| Второй фактор администратора (TOTP, push) | работает |
| RADIUS для VPN-шлюзов | работает и от HTTP не зависит: защищён общим секретом и Message-Authenticator |
| Привязка Android-телефона | работает **после явного подтверждения** на телефоне: «Понимаю риск, это тестовая сеть» |
| Подтверждение входа с телефона | работает. Решение подписано ключом телефона, подделать его при перехвате нельзя |
| REST API для своих приложений | работает |

## Чем опасен HTTP

- **Пароли видны в сети.** Пароль администратора при входе в панель, доменный пароль сотрудника при входе в кабинет и пароль, проверяемый через REST API, идут открытым текстом.
- **Сессию можно перехватить.** Cookie панели и ключи API передаются открыто: кто видит трафик, может действовать от имени администратора.
- **Подмена ответа.** Посредник может подменить страницу панели или QR-код привязки.
- **Секреты в окнах «показывается один раз»** (секреты RADIUS-клиентов, ключи API, TOTP) тоже идут открытым текстом.

Поэтому по HTTP работайте **только в изолированной сети**: отдельный VLAN администраторов, стенд, прямое подключение. Не открывайте порт 8080 в Интернет.

## Как ограничить доступ к порту 8080

Порты Docker обходят `ufw`, поэтому правило `ufw deny 8080` не действует. Ограничение по адресам — в цепочке `DOCKER-USER` (пример — сеть администраторов `203.0.113.0/28`):

```bash
sudo iptables -I DOCKER-USER -p tcp -m conntrack --ctorigdstport 8080 --ctdir ORIGINAL -j DROP
sudo iptables -I DOCKER-USER -p tcp -m conntrack --ctorigdstport 8080 --ctdir ORIGINAL -s 203.0.113.0/28 -j ACCEPT
```

**Как проверить:** с компьютера вне этой сети `curl -m 5 http://192.0.2.10:8080/health/live` завершается таймаутом, из сети администраторов — возвращает ответ. Учтите: телефонам сотрудников тоже нужен доступ к этому порту, пока нет HTTPS.

Сохранение правил после перезагрузки: `sudo netfilter-persistent save` (пакет `iptables-persistent`).

## Как система напоминает об HTTP

- `sudo mfagatectl diagnose` и раздел «Диагностика» показывают предупреждение «Публичный адрес … — не HTTPS».
- Итоговый блок установщика: «Работа идёт по HTTP — только для изолированной сети и первичной настройки».
- Приложение на телефоне помечает сервер «Без шифрования (HTTP)».
