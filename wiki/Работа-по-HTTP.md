# Работа по HTTP

*Для кого: администратор, который только что установил MFA Gate и ещё не настроил HTTPS.*

После установки All-in-One личный кабинет, панель и Device API работают по `http://<IP сервера>:8080` без шифрования. Так сделано, чтобы систему можно было поставить и настроить без DNS-имени и сертификата. Страница объясняет, что в этом режиме работает, чем он опасен и как ограничить риск, пока вы готовите HTTPS.

## Зачем это нужно

HTTP — временный режим для первичной настройки. Важно понимать, какие данные в нём идут открытым текстом, и не начинать в этом режиме пилот с сотрудниками. Иначе придётся объяснять, почему их доменные пароли проходили по сети без шифрования, и привязывать телефоны второй раз.

## Когда пригодится

- Первые часы после установки: вход в панель, подключение каталога, заведение RADIUS-клиентов.
- Изолированный тестовый сегмент без доступа из других сетей.
- Сервер, к которому администратор подключается через SSH-туннель.

## Что потребуется

- Сетевой сегмент, к которому есть доступ только у администраторов, или SSH-доступ к серверу.
- Права `sudo`, если будете ограничивать доступ к порту.

## Где найти

- Предупреждение в панели: внизу боковой панели — **Соединение без HTTPS — только для изолированной сети** со ссылкой **Как включить HTTPS**.
- Проверки: **Панель → Диагностика** или `sudo mfagatectl diagnose`, строки **Адрес портала** и **Адрес для телефонов**.
- Адрес и порт: `MFA_GATE_PUBLIC_URL`, `MFA_GATE_HTTP_BIND` и `MFA_GATE_HTTP_PORT` в `/opt/mfa-gate/deploy/.env`.

## Что работает по HTTP

| Функция | По HTTP |
|---|---|
| Вход в панель и все её разделы | работает. Cookie сессии выдаётся без флага `Secure`, потому что запрос пришёл по HTTP |
| Личный кабинет сотрудника | работает, но доменный пароль сотрудника идёт открытым текстом. До HTTPS не приглашайте сотрудников в кабинет |
| Второй фактор администратора | работает |
| RADIUS для VPN-шлюзов | работает и от HTTP не зависит: защищён общим секретом и атрибутом Message-Authenticator |
| Привязка Android-телефона | работает только после явного подтверждения на телефоне: приложение предупреждает «Без шифрования (HTTP) — только для изолированной тестовой сети» и просит отметить «Понимаю риск, это тестовая сеть» |
| Подтверждение входа с телефона | работает. Решение подписано ключом телефона, подделать его при перехвате нельзя |
| REST API | работает, ключи API идут открытым текстом |

## Чем опасен HTTP

- **Пароли видны в сети.** Пароль администратора, доменный пароль сотрудника в кабинете и пароль, проверяемый через REST API, передаются открыто.
- **Сессию можно перехватить.** Кто видит трафик, может действовать в панели от имени администратора.
- **Ответ можно подменить.** Посредник может подменить страницу или QR-код привязки.
- **Секреты в окнах «показывается один раз»** — секреты RADIUS-клиентов, ключи API, секреты TOTP — тоже идут открытым текстом.

Поэтому по HTTP работайте только в изолированной сети: отдельный сегмент администраторов, прямое подключение, SSH-туннель. Порт 8080 в Интернет не открывайте.

## Как это сделать

### Способ 1. SSH-туннель вместо открытого порта

Самый простой способ безопасно работать до HTTPS — вообще не открывать порт 8080 в сеть, а заходить в панель через SSH.

1. На сервере ограничьте веб-сервис петлевым адресом:

   ```bash
   sudo sed -i 's|^MFA_GATE_HTTP_BIND=.*|MFA_GATE_HTTP_BIND=127.0.0.1|' /opt/mfa-gate/deploy/.env
   sudo mfagatectl start
   ```

   **Что увидите:** `==> запущено`.

2. На своём компьютере откройте туннель:

   ```bash
   ssh -L 8080:127.0.0.1:8080 -l admin 192.0.2.10
   ```

3. Откройте в браузере `http://127.0.0.1:8080/admin/`.

**Что увидите:** страницу входа. Предупреждения о HTTP в боковой панели не будет: трафик идёт внутри SSH и в сеть не выходит.

Телефоны так подключить нельзя: им нужен адрес сервера в сети. Привязку телефонов оставьте на время после HTTPS.

### Способ 2. Ограничить доступ к порту 8080 по адресам

Порты, опубликованные Docker, обходят `ufw` и цепочку `INPUT`, поэтому `ufw deny 8080` не действует. Ограничение задаётся в цепочке `DOCKER-USER`. Пример для сети администраторов `203.0.113.0/28`:

```bash
sudo iptables -I DOCKER-USER -p tcp -m conntrack --ctorigdstport 8080 --ctdir ORIGINAL -j DROP
sudo iptables -I DOCKER-USER -p tcp -m conntrack --ctorigdstport 8080 --ctdir ORIGINAL -s 203.0.113.0/28 -j ACCEPT
```

Правило `-I` вставляется в начало цепочки, поэтому сначала добавляется запрет, затем разрешение — в итоге разрешение оказывается выше. Если порт нестандартный, подставьте свой. При бэкенде nftables и других настройках Docker правила могут отличаться — проверьте результат на своём сервере.

**Как проверить:** с компьютера вне этой сети `curl -m 5 http://192.0.2.10:8080/health/live` завершается таймаутом, из сети администраторов — возвращает `{"status":"ok"}`.

Сохранить правила после перезагрузки: `sudo netfilter-persistent save` из пакета `iptables-persistent`.

Другой вариант — указать в `MFA_GATE_HTTP_BIND` адрес конкретного интерфейса, смотрящего в сеть администраторов, вместо `0.0.0.0`.

## Как система напоминает об HTTP

- Итоговый блок установщика: «Работа идёт по HTTP — только для изолированной сети и первичной настройки».
- Диагностика: `WARN Адрес портала: http://… — не HTTPS` и `WARN Адрес для телефонов: http://… — не HTTPS`.
- Боковая панель: **Соединение без HTTPS — только для изолированной сети**.
- Приложение на телефоне помечает такой сервер как работающий без шифрования.

## Что получится

Панель доступна только администраторам — через SSH-туннель или из разрешённой сети. Сотрудники в кабинет не приглашены, телефоны не привязаны. Можно спокойно настраивать каталог, ресурсы и RADIUS-клиенты, а затем перейти на HTTPS.

## Если не получается

| Что видно | Почему | Что сделать |
|---|---|---|
| После смены `MFA_GATE_HTTP_BIND` панель не открывается по IP | так и задумано: порт слушает только петлевой адрес | используйте SSH-туннель |
| `ufw deny 8080` не закрыл порт | Docker обходит `ufw` | правила в цепочке `DOCKER-USER` |
| Правила пропали после перезагрузки | не сохранены | `sudo netfilter-persistent save` |
| Телефон не привязывается по HTTP | не отмечено «Понимаю риск, это тестовая сеть» или сервер недоступен из сети телефона | отметьте подтверждение; лучше настройте HTTPS |
