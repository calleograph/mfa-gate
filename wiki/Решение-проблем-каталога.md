# Решение проблем каталога

*Для кого: администратор MFA Gate, администратор домена, вторая линия поддержки.*

Доменные сотрудники входят паролем из Active Directory или OpenLDAP. MFA Gate проверяет пароль в каталоге, читает профиль и группы и только потом спрашивает второй фактор. Статья разбирает отказы каталога: как их узнать в истории, как запустить пошаговую диагностику и что значат её результаты.

Работа с Active Directory описана по коду и документации. На настоящем каталоге её проверяли с OpenLDAP, на реальном Active Directory — нет: см. [Что проверено](Что-проверено.md).

## Что потребуется

- Роль **Администратор** или **Главный администратор**: раздел **LDAP / AD** и кнопка **Диагностика** доступны только им. **Оператор** видит каталог только в разделе **Диагностика** и в истории входов.
- Для проверки конкретного сотрудника — его логин и пароль. Сотрудник может ввести пароль сам, в окне диагностики. Пароль никуда не сохраняется и не пишется в журнал.

## Как узнать, что дело в каталоге

| Что видно | Почему | Что сделать |
|---|---|---|
| В истории у многих доменных сотрудников «Каталог LDAP/AD недоступен — вход запрещён.» | Ни один контроллер не ответил, TLS не установлен или каталог настроен неверно, например сервисная учётная запись не входит | Раздел «Каталог недоступен» ниже |
| У одного сотрудника «Каталог не принял пароль.» | Неверный пароль. В Active Directory — подкод `52e` | Сотрудник проверяет пароль на рабочем компьютере. Если там пароль подходит — диагностика с его логином |
| У одного сотрудника «Каталог отклонил вход (учётная запись заблокирована, пароль истёк или нет нужной группы).» | Каталог пускает не всех: состояние учётной записи или разрешённые группы | Диагностика с логином и паролем сотрудника, затем таблица подкодов ниже |
| «Пользователь не найден ни локально, ни в каталогах.» | Логин не находится по фильтру или под Base DN, каталог выключен или не подключён | Диагностика с логином, шаг **Поиск пользователя** |
| В **Журнале** событие «Конфликт учётной записи каталога» (`auth.identity_conflict`) с важностью «Критичное», в истории — «Каталог отклонил вход» | В MFA Gate уже есть локальный пользователь или запись из другого каталога с тем же логином. Доменная учётная запись не наследует чужую роль и факторы, поэтому вход запрещён | Разберитесь, чья это запись. Если локальная запись лишняя — удалите её в **Пользователи** |
| **Диагностика → Каталог «…»: шифрование** — «пароли идут без проверенного TLS» | Шифрование выключено или сертификат контроллера не проверяется | Включите LDAPS и проверку сертификата |

Отказы каталога (учётная запись отключена или истекла, нет разрешённой группы) и недоступность каталога в счётчик блокировки MFA Gate не идут: временной блокировки из-за них не будет. В счётчик идут только неверный пароль и неверный одноразовый код.

## Где найти

- **Панель → Диагностика**, строка **Каталог «имя»**. Проверяет только TCP-соединение с каждым контроллером: «все контроллеры доступны по TCP» или «недоступны: dc1.example.org (TimeoutError)». Если недоступны все — ошибка, если часть — предупреждение.
- **Панель → LDAP / AD**, карточка каталога. Значок связи: «Контроллеры доступны», «Часть контроллеров недоступна», «Каталог недоступен». При проблеме под заголовком появляется плашка с кнопкой **Запустить диагностику**.
- **Панель → LDAP / AD → Диагностика** — пошаговая проверка. Подробно ниже.

## Как запустить диагностику

1. Откройте **Панель → LDAP / AD** и в карточке каталога нажмите **Диагностика**.
2. Оставьте поля пустыми, чтобы проверить только сеть, TLS и сервисную учётную запись. Чтобы проверить конкретного сотрудника, заполните **Логин для проверки** и **Пароль**.
3. Нажмите **Запустить проверку**. Проверка может занять до «тайм-аут × число контроллеров + 2» секунд.

**Что увидите:** итог сверху и список шагов. Проверка идёт по порядку: DNS → TCP → TLS → bind → поиск → пароль → группы, и останавливается на первой ошибке. Итог «Все шаги пройдены — каталог готов к входу пользователей» значит, что каталог в порядке. «Все шаги пройдены, но соединение с каталогом не защищено…» — работает, но без проверенного TLS. «Есть ошибки: N из M шагов» — смотрите шаг с крестиком.

Каждый запуск пишется в **Журнал** как «Диагностика каталога» (`ldap.diagnosed`).

## Что значат шаги диагностики

| Шаг | Что видно при ошибке | Почему | Что сделать |
|---|---|---|---|
| **Имя контроллера (DNS)** | «имя dc1.example.org не разрешается (…)» | Сервер MFA Gate не знает это имя | Проверьте имя и DNS на сервере MFA Gate |
| **Соединение с портом** | «нет соединения с dc1.example.org:636 (…): порт, межсетевой экран, маршрут» | Порт закрыт или контроллер выключен | Откройте доступ с сервера MFA Gate к контроллеру: 636 для LDAPS, 389 для StartTLS |
| **Шифрование (TLS)** | Текст ошибки сертификата, «сервер отклонил STARTTLS» | Сертификат выдан не на это имя, корневой сертификат не доверен, контроллер не поддерживает выбранный режим | Подключайтесь по DNS-имени из сертификата, а не по IP: с проверкой сертификата IP-адрес не проходит. Вставьте корневой сертификат в поле **Корневой сертификат (PEM)** |
| **Шифрование (TLS)**, предупреждение | «шифрование выключено (encryption=none): пароли передаются открытым текстом» | Выбран режим **Без шифрования** | Допустимо только в изолированной сети. Включите LDAPS |
| **Сервисная учётная запись** | «сервисная учётная запись … не вошла: …» | Неверный DN или пароль сервисной записи, запись заблокирована | Проверьте DN и пароль, состояние записи в домене |
| **Сервисная учётная запись** | «bind_dn не задан: для проверки укажите логин и пароль пользователя» | Каталог подключён без сервисной записи | Повторите проверку с логином и паролем сотрудника |
| **База поиска (Base DN)** | «… не читается (…): проверьте значение и права» | Base DN указан с ошибкой или сервисной записи не хватает прав чтения | Исправьте Base DN, выдайте права на чтение |
| **Поиск пользователя** | ««ivanov» не найден по фильтру …» | Сотрудник вне Base DN, фильтр отсекает его, указан не тот атрибут входа | Проверьте фильтр, атрибут входа и Base DN |
| **Поиск пользователя** | «not_found: под логин подходит несколько записей (2); уточните user_filter» | Фильтр находит и пользователя, и, например, контакт или служебную запись | Сузьте фильтр пользователей |
| **Пароль пользователя** | «invalid_credentials: LDAP 49 invalidCredentials; AD 52e: неверный пароль» и подобные | Каталог отказал. Подкод AD объясняет причину | Таблица подкодов ниже |
| **Пароль пользователя** | «account_disabled: userAccountControl: ACCOUNTDISABLE» | Учётная запись отключена в Active Directory | Включите её в домене |
| **Группы пользователя** | «групп с учётом вложенности: N (…); ни одна не входит в allowed_groups — вход будет отклонён» | Сотрудник не состоит в разрешённых группах каталога | Добавьте сотрудника в группу или исправьте **Разрешённые группы** |
| **Группы пользователя** | «unavailable: не удалось вычислить вложенные группы (…)» | Контроллер не выполнил поиск вложенных групп. Вход в этом случае отклоняется: неполный список групп мог бы обойти запрещающую политику | Повторите проверку; если ошибка постоянная — передайте администратору домена |

Если в настройках каталога не хватает обязательного поля или пароль сервисной записи не расшифровывается, диагностика сразу показывает ошибку настройки, без сетевых шагов. Пароль сервисной записи не расшифровывается, если база восстановлена с другим мастер-ключом: введите пароль заново.

## Подкоды Active Directory

При отказе Active Directory добавляет к коду LDAP 49 подкод. MFA Gate показывает его в шаге **Пароль пользователя** и по нему выбирает причину в истории.

| Подкод | Что значит | Код в истории | Что сделать в домене |
|---|---|---|---|
| `525` | Пользователь не найден | «Пользователь не найден…» | Проверьте логин |
| `52e` | Неверный пароль | «Каталог не принял пароль.» | Сотрудник вводит верный пароль или сбрасывает его |
| `52f` | Ограничение учётной записи | «Каталог отклонил вход…» | Проверьте ограничения учётной записи |
| `530` | Вход запрещён в это время | «Каталог отклонил вход…» | Проверьте разрешённые часы входа |
| `531` | Вход запрещён с этого компьютера | «Каталог отклонил вход…» | Проверьте список разрешённых рабочих станций |
| `532` | Срок действия пароля истёк | «Каталог отклонил вход…» | Сотрудник меняет пароль на рабочем компьютере |
| `533` | Учётная запись отключена | «Каталог отклонил вход…» | Включите запись |
| `701` | Срок действия учётной записи истёк | «Каталог отклонил вход…» | Продлите срок |
| `773` | Нужно сменить пароль | «Каталог отклонил вход…» | Сотрудник меняет пароль при входе в домен |
| `775` | Учётная запись заблокирована | «Каталог отклонил вход…» | Разблокируйте и выясните источник неверных паролей |

Учётная запись, заблокированная в домене (`775`), и временная блокировка MFA Gate — разные вещи. Первую снимает администратор домена, вторую — **Снять блокировку** в карточке пользователя MFA Gate.

## Каталог недоступен

Отказ «Каталог LDAP/AD недоступен — вход запрещён.» означает, что ни один каталог не смог проверить пароль. MFA Gate не пропускает вход без проверки пароля. Пока каталог недоступен, доменные сотрудники не войдут, а локальные — войдут.

| Что видно | Почему | Что сделать |
|---|---|---|
| **Диагностика**: «недоступны: …» по всем контроллерам | Сеть между сервером MFA Gate и контроллерами | Шаги DNS и TCP в диагностике каталога; маршрут и межсетевой экран |
| TCP проходит, вход не работает | Ошибка TLS или сервисной учётной записи: такие отказы тоже считаются недоступностью | Диагностика без логина: шаги TLS и **Сервисная учётная запись** |
| Отказ после смены пароля сервисной записи в домене | В MFA Gate остался старый пароль | **LDAP / AD → карточка → Изменить**, введите новый пароль |
| Отказ после восстановления на новом сервере | Пароль сервисной записи зашифрован другим мастер-ключом | Верните прежний мастер-ключ или введите пароль сервисной записи заново: [Восстановление](Восстановление.md) |
| Вход медленный, затем проходит | Первый контроллер в списке не отвечает и пропускается на 60 с | Уберите или исправьте недоступный контроллер в списке **Контроллеры** |

## Если не входит сотрудник без сервисной записи

Каталог можно подключить без сервисной учётной записи. Тогда сотрудник входит своим паролем, и его же правами читаются запись и группы. Есть две особенности:

- Если пароль принят, но собственная запись сотруднику не видна, вход заканчивается «Пользователь не найден ни локально, ни в каталогах.» Проверьте Base DN и права чтения.
- В OpenLDAP группы ищутся под тем же Base DN. Если группы лежат в другой ветке, нужна сервисная учётная запись.
