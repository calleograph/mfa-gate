# Что проверено

*Для кого: администратор, специалист по информационной безопасности, руководитель, который решает о внедрении.*

На этой странице сказано, какие проверки прошла текущая версия MFA Gate 0.3.2 и чего проверить пока не удалось. Последний полный прогон выполнен 19 ноября 2026 года. Подробный отчёт с командами — [docs/testing.md](https://github.com/calleograph/mfa-gate/blob/main/docs/testing.md).

## Коротко

| Проверено | Не проверено |
| --- | --- |
| Установка на чистый Ubuntu Server из публичного репозитория | Настоящие VPN-шлюзы сторонних производителей |
| Обновление, откат, резервная копия и восстановление на тестовом сервере в изолированной сети | Настоящий Active Directory |
| Вход по RADIUS доменным паролем с подтверждением — в сквозных тестах и на тестовом сервере с настоящим каталогом OpenLDAP | Приложение на реальных телефонах |
| Личный кабинет с настоящим каталогом | Доставка push через Firebase, HMS, UnifiedPush |

| --- | --- | --- |

| Приложение Android | 33 JVM-теста в каждой сборке (foss, gms) | Коды по RFC 6238, разбор QR-кодов привязки (в том числе предупреждение об адресе `http://`) и ссылок `otpauth` для приложений-аутентификаторов, строка подписи, HTTP-клиент, задержки повторных подключений. Lint без ошибок, собраны отладочные и выпускные APK обеих сборок, в сборке foss нет кода Google |

### Что проверяют сквозные тесты

- Неизвестный RADIUS-клиент, неверный общий секрет и пакет без Message-Authenticator отбрасываются.
- Неверный пароль и неизвестный логин получают одинаковый отказ; пользователь без способа входа — отказ.
- Подтверждение на телефоне даёт вход меньше чем за 3 с; отклонение, поддельная подпись (`400`), чужое устройство (`404`), повтор подписи (`409`), таймаут и позднее подтверждение обрабатываются правильно.
- Повторы шлюза не создают второй запрос; одновременные пользователи не мешают друг другу.
- Вход по коду через Access-Challenge защищён от повтора State и кода.
- REST API: вход с подтверждением, отказ, чужой ключ (`404`), ключ без прав (`403`), ключ ресурса не может сменить ресурс (`403`).
- Политики «запретить» и «пропустить»; блокировка после 8 ошибок; отозванное устройство.
- Вход администратора с временным паролем, сменой и подключением TOTP; CSRF; ключ API не может менять администраторов; вход в панель с подтверждением одноразовый.
- 40 одновременных ожидающих телефонов не мешают API и RADIUS; предел попыток входа общий для двух экземпляров `api` (ровно 20 из 30).
- Скрипт интеграции OpenVPN: подтверждение даёт вход, неверный код — отказ.
- Личный кабинет: первая настройка TOTP; вход по одному паролю не позволяет добавить способ; последний способ не удаляется; резервный код одноразовый; сессия кабинета не открывает панель; отказ в настройке вне сети регистрации; повторная настройка только по разрешению администратора; адрес для телефонов отдаёт только Device API.
- RADIUS-клиент в режиме **Сам шлюз**: пустой пароль ведёт к подтверждению на телефоне, 6–8 цифр — к проверке кода, неверный код — отказ.

## Проверка на тестовом сервере в изолированной сети

Сервер: Ubuntu Server 26.04.1 LTS, 2 виртуальных процессора, 3,3 ГБ памяти, диск 32 ГБ.

| Проверка | Результат |
| --- | --- |
| Установка из публичного репозитория: `git clone`, `sudo ./install.sh` | Пройдена. Установщик сам поставил Docker и Compose, собрал образ, создал администратора. Найденные ошибки установки исправлены в выпуске |
| Повторный запуск поверх частичной установки | Настройки и секреты сохранены, недостающий администратор создан |
| Удаление с данными и установка с нуля | Пройдены |
| Панель по HTTP с другого компьютера сети | Вход с временным паролем, обязательная смена, подключение TOTP, обзор |
| Каталог через форму панели и пошаговая диагностика | Все шаги пройдены |
| Сквозные тесты по сети против установленной системы | 23 из 24 пройдены автоматически, вход администратора проверен вручную в браузере |
| Доменный пользователь: заведение из каталога, привязка имитации телефона, вход по RADIUS доменным паролем с подтверждением | Вход разрешён; неверный пароль — отказ; запрет через вложенную группу и разрешение по группе каталога работают |
| Обновление 0.2.0 → 0.3.0 по инструкции | Образ загружен из реестра, копия сделана, миграция применена; пользователи, устройства, каталог и RADIUS-клиент на месте |
| Откат на 0.2.0 и повторное обновление | База восстановлена из копии, повторное обновление снова сделало копию |
| Личный кабинет с настоящим каталогом | Пользователь с телефоном сразу переходит к подтверждению; пользователь без способа входа прошёл первичную настройку TOTP |

## Интерфейс

Личный кабинет и панель проверены в браузере на семи ширинах экрана от 320 до 1920 пикселей: компоновка без замечаний, светлая и тёмная темы, клавиатура и фокус, консоль браузера без ошибок и нарушений политики безопасности содержимого, работа по HTTP по имени хоста.

## Нагрузка

Нагрузочный тест RADIUS на сервере разработки, 40 одновременных клиентов, 0 ошибок. Статус: **проверено в ограниченном сценарии**, на целевом сервере не повторялось, вместимость системы на этом основании не заявляется.

| Сценарий | Результат |
| --- | --- |
| Неверный пароль | Отказ, 30 запросов в секунду, медиана 1,2 с, 95-й процентиль 1,9 с. Скорость ограничена намеренно медленным argon2id — это защита от перебора |
| Вход по коду через Access-Challenge | Медиана 1,0 с |
| Вход с подписанным подтверждением телефона | Медиана 1,2 с; каждое подтверждение принято ровно один раз, повтор подписи — `409` |

## Что не проверено

| Что | Почему | Чем заменено |
| --- | --- | --- |
| Настоящие VPN-шлюзы и RADIUS-серверы сторонних производителей, в том числе OpenVPN | Нет шлюза в тестовом окружении | RADIUS проверен собственным клиентом по сети и сквозными тестами. Режимы шлюза, который сам проверяет пароль, — имитацией пакетов по документации производителя. Профили шлюзов на странице [Подключение VPN](Подключение-VPN.md) составлены по документации и на настоящих шлюзах не проверялись |
| Настоящий Active Directory | Нет контроллера домена | OpenLDAP с TLS; правило вложенных групп AD — юнит-тестами |
| Приложение на реальном телефоне: Keystore и биометрия, камера, работа в фоне, экономия заряда, постоянное соединение сборки foss | Нет устройства и эмулятора | Подпись и протокол проверены имитацией телефона; приложение — JVM-тестами и сборкой. Сценарий ручной приёмки — [docs/android.md](https://github.com/calleograph/mfa-gate/blob/main/docs/android.md) |
| Доставка через Firebase, HMS, UnifiedPush | Нет учётных данных | Проверен прямой опрос сервера приложением |
| Независимый аудит безопасности | Не проводился | Внутреннее ревью кода и модели угроз |
