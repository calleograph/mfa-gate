# Планы развития

*Для кого: руководитель, администратор, специалист по информационной безопасности, разработчик.*

**Здесь собраны только идеи. Ничто из перечисленного в версии 0.3.1 не работает, сроков нет.** Список отражает записи разработчиков и помогает понять, куда движется продукт. Решения о внедрении принимайте по тому, что уже есть: [Возможности](Возможности.md) и [Когда продукт не подходит](Когда-продукт-не-подходит.md).

## Идеи

| Идея | Зачем | Что есть сейчас |
| --- | --- | --- |
| RADIUS Accounting и активные VPN-сессии | Видеть в панели, кто сейчас подключён к VPN, сколько длится сессия, и сопоставлять её со входом | Accounting (UDP 1813) не принимается: на шлюзе его нужно выключить или направить в другую систему |
| Атрибуты ответа по группам (Class, Filter-Id) | Передавать шлюзу группу доступа сотрудника, чтобы шлюз назначал правила или адресный пул | Ответ Access-Accept не содержит Class, Filter-Id и атрибутов производителей |
| Подтверждение вводом числа (number matching) | Сотрудник вводит на телефоне число с экрана входа. Это защищает от случайного нажатия при потоке запросов и от попытки, которая «пристроилась» к чужому входу | Есть кнопки **Подтвердить** и **Отклонить** с биометрией, один push на попытку и блокировка после ошибок |
| Ограничение частоты push на одного пользователя | Дополнительная защита от потока запросов | Предела нет; push отправляется только после верного пароля |
| WebAuthn (аппаратные ключи и ключи доступа) | Вход в кабинет и панель аппаратным ключом без кодов | Не поддерживается |
| Kerberos SSO в личном кабинете | Вход с доменного компьютера без пароля как подтверждение того, что сотрудник в домене | Вход в кабинет — по доменному паролю и второму фактору |
| RadSec (RADIUS по TLS) | Шифровать весь обмен со шлюзами, а не только пароль | Не реализован; между площадками RADIUS пускают через IPsec или WireGuard |
| Приложение для iPhone | Подтверждение входа на телефонах Apple | Приложения нет. Сотрудники с iPhone могут пользоваться кодами TOTP в любом приложении-аутентификаторе ([Как подключить приложение с кодами](Как-подключить-приложение-с-кодами.md)) |
| Пароль и код в одном поле по RADIUS | Подключать шлюзы, которые не умеют запрашивать код отдельно | Код запрашивается отдельным шагом (Access-Challenge) или приходит вместо пароля в режиме **Сам шлюз** |
| Смена мастер-ключа | Перешифровать секреты новым ключом без переустановки | Формат шифрования к этому готов, команды нет |
| Отпечаток ключа сервера в QR-коде привязки | Защитить привязку от подмены сервера, даже если TLS настроен с ошибкой | Подлинность сервера обеспечивает TLS |
| Приглашения по почте и импорт пользователей группой из каталога | Упростить массовое подключение сотрудников | Сотрудники входят в кабинет сами; пользователи из каталога заводятся при первом входе или вручную |
| Собственный VPN-клиент | Подключение к VPN с выдачей краткоживущей конфигурации после подтверждения | Отдельное направление, к работе над ним не приступали. MFA Gate встраивается в существующие шлюзы по RADIUS и REST API |

## Проверки, которые хотелось бы провести

Это не функции, а недостающие испытания. Их состояние — на странице [Что проверено](Что-проверено.md).

- Вход через настоящие VPN-шлюзы разных производителей, в том числе с клиентом Windows.
- Работа с настоящим Active Directory.
- Приложение на реальных телефонах: биометрия, работа в фоне, экономия заряда.
- Доставка push через Firebase организации.

## Как повлиять

Если вам нужна одна из идей или чего-то в списке нет, откройте задачу на GitHub и опишите сценарий: какой шлюз, сколько сотрудников, что должно происходить. Порядок — [Участие в разработке](Участие-в-разработке.md).
