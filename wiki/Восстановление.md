# Восстановление

## Восстановление на том же сервере

Сценарий: данные в базе испорчены или удалены по ошибке, сервер и мастер-ключ на месте.

### Шаг 1. Выберите копию

```bash
ls -1t /opt/mfa-gate/deploy/backups | grep -v '^diag-' | head
```

**Ожидаемый результат:** список каталогов вида `20261118T023000Z-daily`, новые сверху. Время — UTC.

### Шаг 2. Восстановите

```bash
sudo mfagatectl restore /opt/mfa-gate/deploy/backups/20261118T023000Z-daily
```

Что делает команда:

1. проверяет контрольную сумму копии (`SHA256SUMS`);
2. проверяет, что текущий `master.key` совпадает с отпечатком в манифесте копии. Если нет — останавливается: `копия сделана с другим мастер-ключом: верните прежний data/secrets/master.key`;
3. останавливает `api`, `radius`, `worker` (входы в это время не проходят);
4. восстанавливает копию во временную базу. Если это не удалось — рабочая база не тронута;
5. подменяет рабочую базу восстановленной; прежняя остаётся как `mfa_gate_prev` до следующего восстановления;
6. запускает сервисы и ждёт статуса healthy.

**Ожидаемый результат:** `восстановлено; прежняя база сохранена как mfa_gate_prev`.

### Шаг 3. Проверка

```bash
sudo mfagatectl status && sudo mfagatectl diagnose
```

**Ожидаемый результат:** все сервисы `healthy`, в диагностике нет `FAIL`. Войдите в панель: пользователи, телефоны и настройки — на момент копии. Выполните пробный вход в VPN.

Всё, что изменилось после времени копии (новые привязки телефонов, пользователи, история), потеряно. Телефоны, привязанные после копии, нужно привязать заново.

## Перенос на другой сервер

Сценарий: старый сервер вышел из строя или вы переезжаете. Нужны: копия базы, мастер-ключ, файл `.env` (и, если настраивали, `compose.override.yml` и `fcm.json`).

### Шаг 1. Подготовьте новый сервер

Проверьте [Требования к серверу](Требования-к-серверу.md). Если у старого сервера было DNS-имя, после переноса направьте его на новый сервер — тогда телефоны и шлюзы продолжат работать без перепривязки. Если адрес меняется, на шлюзах нужно поменять адрес RADIUS-сервера, а телефоны привязать заново.

### Шаг 2. Клонируйте ту же версию

```bash
cd /opt
sudo git clone https://github.com/calleograph/mfa-gate.git && cd mfa-gate
sudo git checkout v0.2.0
```

Версию возьмите из `version=` в файле `manifest` копии. Восстанавливать копию в более старую версию нельзя; в более новую — можно, после восстановления выполните `update` ([Обновление](Обновление.md)).

### Шаг 3. Верните конфигурацию и мастер-ключ

Перенесите файлы на новый сервер (например, `scp` в `/root/restore/`), затем:

```bash
cd /opt/mfa-gate/deploy
sudo install -m 600 /root/restore/.env .env
sudo install -d -m 700 data/secrets
sudo install -m 644 /root/restore/master.key data/secrets/master.key
sudo sha256sum data/secrets/master.key | cut -c1-16
```

**Ожидаемый результат:** отпечаток совпадает с `master_key_sha256=` в `manifest` копии.

Если у вас только строка ключа из менеджера паролей: `printf '%s\n' 'СТРОКА_КЛЮЧА' | sudo tee data/secrets/master.key >/dev/null && sudo chmod 644 data/secrets/master.key`.

Если адрес сервера меняется, исправьте `MFA_GATE_PUBLIC_URL` в `.env`. Если был FCM — верните `compose.override.yml` и `data/secrets/fcm.json` ([Настройка Push](Настройка-Push.md), шаг 4).

### Шаг 4. Установка поверх сохранённой конфигурации

```bash
cd /opt/mfa-gate && sudo ./install.sh
```

**Ожидаемый результат:** на этапе «Конфигурация» — `найдена существующая конфигурация … — секреты и настройки сохраняются`; мастер-ключ не генерируется заново; в конце «Готово». Установщик создаст временного администратора `admin` в пустой базе — после восстановления его не будет, это нормально.

### Шаг 5. Восстановите копию

```bash
sudo install -d -m 700 /opt/mfa-gate/deploy/backups
sudo cp -a /root/restore/20261118T023000Z-daily /opt/mfa-gate/deploy/backups/
sudo mfagatectl restore /opt/mfa-gate/deploy/backups/20261118T023000Z-daily
```

**Ожидаемый результат:** `восстановлено; прежняя база сохранена как mfa_gate_prev`.

### Шаг 6. Проверка и завершение

1. `sudo mfagatectl diagnose` — без `FAIL`.
2. Вход в панель под прежними администраторами (прежние пароли и факторы).
3. Если адрес сервера изменился — RADIUS-клиенты на шлюзах, межсетевые экраны (UDP 1812 только для шлюзов, [Настройка RADIUS](Настройка-RADIUS.md), шаг 4), reverse proxy и сертификат ([HTTPS через reverse proxy](HTTPS-через-reverse-proxy.md)).
4. Пробный вход в VPN.
5. Включите расписание копий на новом сервере ([Резервное копирование](Резервное-копирование.md), шаг 3) и удалите `/root/restore`.

## Если мастер-ключ утерян

Расшифровать секреты из копии невозможно. Восстановление из копии бесполезно: секреты RADIUS-клиентов, каталогов LDAP, TOTP и push-токены не прочитаются. Остаётся новая установка: заново подключить каталог, создать RADIUS-клиенты (и обновить секреты на шлюзах), выдать сотрудникам TOTP и привязать телефоны.
