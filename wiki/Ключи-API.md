# Ключи API

*Для кого: администратор MFA Gate, интегратор.*

Ключ API позволяет вашему приложению или скрипту обращаться к MFA Gate без панели: проверять вход сотрудника со вторым фактором, заводить пользователей, выгружать журнал. Ключ создаётся в панели, права ограничиваются выбранными областями, ресурсом и адресами. Статья — о выпуске и обслуживании ключей; как написать само приложение, рассказывает [Интеграция по REST API](Интеграция-по-REST-API.md).

## Зачем это нужно

- Внутренний портал или веб-приложение должно требовать второй фактор так же, как VPN.
- Система учёта выгружает журнал раз в сутки.
- Скрипт адаптации заранее заводит новых сотрудников и выпускает им ссылку привязки телефона.

## Когда пригодится

- Подключить новое приложение к проверке входа.
- Сменить секрет, если он мог попасть в чужие руки или сотрудник с доступом к нему уволился.
- Отключить интеграцию на время, не удаляя ключ.

## Что потребуется

- Роль **Главный администратор** или **Администратор**. **Аудитор** ключи видит, **Оператор** раздела не видит.
- Ресурс для приложения, если вход проверяется для конкретной системы: **Панель → Ресурсы → Добавить ресурс**, **Тип** — **Приложение**.
- Адрес или сеть, с которой приложение будет обращаться к MFA Gate.

## Где найти

**Панель → API-клиенты** (группа меню **Интеграции**). Кнопки **Создать ключ** и **Документация API**; в меню строки — **Изменить**, **Сменить секрет**, **Удалить**.

В таблице колонки **Клиент** (название и идентификатор ключа), **Права**, **Ресурс**, **Адреса** (**Любые**, если ограничений нет), **Статус**, **Использован**.

Интерактивное описание API открывается по адресу `/api/docs` на сервере MFA Gate, например `https://mfa.example.org/api/docs`, или кнопкой **Документация API**.

## Как это сделать

### Создать ключ

Пример: внутренний портал «Портал самообслуживания» на сервере `192.0.2.30` проверяет вход сотрудников.

1. Откройте **Панель → API-клиенты** и нажмите **Создать ключ**.
2. Заполните поля:

   | Поле | Что указать |
   |---|---|
   | **Название** | `Портал самообслуживания` |
   | **Права ключа** | для проверки входа достаточно **Запросы доступа: изменение** (`auth:write`), отмечено по умолчанию |
   | **Ресурс по умолчанию** | ресурс портала. Если задан, ключ не может проверять вход в другой ресурс |
   | **Разрешённые адреса** | `192.0.2.30` или сеть `192.0.2.0/24`. Значение добавляется клавишей Enter или запятой. Пусто — с любого адреса |
   | **Ключ действует** | включено |

3. Нажмите **Создать**.

**Что увидите:** окно «Ключ API «Портал самообслуживания»» с полями **Идентификатор ключа (key_id)** и **Секрет**, у каждого кнопка копирования.

Секрет показывается один раз. Передайте его владельцу приложения защищённым способом и только потом нажмите **Секрет сохранён, закрыть**. На сервере хранится только хэш секрета, восстановить его нельзя.

### Как приложение передаёт ключ

Каждый запрос идёт с заголовком:

```
Authorization: Basic base64(key_id:secret)
```

Пример проверки входа сотрудника `ivanov`:

```bash
curl -s -u 'KEY_ID:SECRET' -H 'Content-Type: application/json' \
  -d '{"login": "ivanov", "password": "пароль", "source_ip": "203.0.113.25"}' \
  https://mfa.example.org/api/v1/access-requests
```

**Что увидите:** ответ со статусом `pending` и идентификатором запроса, на телефон `ivanov` приходит запрос. Дальше приложение ждёт решения. Порядок запросов и ответы: [Интеграция по REST API](Интеграция-по-REST-API.md).

### Права ключа

| Право | Что даёт |
|---|---|
| **Запросы доступа: изменение** (`auth:write`) | проверка входа: создание запросов, ожидание решения, передача кода |
| **Пользователи** (`users:read`, `users:write`) | список и карточки пользователей, создание, изменение, снятие блокировки |
| **Устройства** (`devices:read`, `devices:write`) | телефоны, ссылки привязки, TOTP, повторная настройка |
| **Журнал** (`audit:read`) | журнал и выгрузка CSV |
| **История входов** (`requests:read`) | история и проблемы входа |
| остальные области | группы, ресурсы, политики, RADIUS-клиенты, каталоги, API-клиенты, состояние системы |

Выдавайте минимум. Права на изменение, кроме `auth:write`, панель помечает как риск. Особенно осторожно с **API-клиенты: изменение**: такой ключ может выпустить другой ключ с любыми правами. Права управлять администраторами ключу выдать нельзя, и учётные записи администраторов ключ не изменит.

Запросы входа через API проходят те же проверки, что и VPN: блокировка, каталог, политики, второй фактор. Политики применяются для ресурса ключа или ресурса из запроса; запрос без ресурса совпадает только с политиками без ресурсов, см. [Политики доступа](Политики-доступа.md).

### Сменить секрет

1. В меню строки ключа выберите **Сменить секрет**.
2. Подтвердите кнопкой **Сменить секрет**.

**Что увидите:** окно с новым секретом. Старый перестаёт действовать сразу: приложение будет получать ошибку 401, пока в нём не укажут новый. Согласуйте время с владельцем приложения.

### Отключить или удалить ключ

- Временно: **Изменить** → снимите **Ключ действует** → **Сохранить**. Запросы с ключом получат 401.
- Насовсем: **Удалить**. Интеграции с этим ключом сразу перестанут работать.

## Что получится

- Приложение обращается к MFA Gate по своему ключу в пределах выданных прав.
- В колонке **Использован** видно время последнего запроса.
- Запросы входа видны в **Истории входов** с каналом **API** и названием приложения.
- Создание, изменение, смена секрета и удаление ключей записываются в **Журнал**; действия, выполненные ключом, — с автором вида `api:Портал самообслуживания`.

## Если не получается

| Что видно | Почему | Что сделать |
|---|---|---|
| `401 bad_credentials` | неверный идентификатор или секрет, ключ выключен или секрет сменили | проверьте заголовок и статус ключа |
| `403 ip_not_allowed` | адрес приложения не входит в **Разрешённые адреса** | добавьте адрес; за reverse proxy проверьте `MFA_GATE_TRUSTED_PROXIES` |
| `403 forbidden` с текстом «Нет права …» | у ключа нет нужной области | добавьте право в **Изменить** |
| `403 resource_mismatch` | ключ привязан к ресурсу, а в запросе указан другой `resource_id` | уберите `resource_id` из запроса или смените ресурс ключа |
| `404` по адресу `/api/docs` | описание API отключено переменной `MFA_GATE_DOCS_ENABLED=false` | используйте копию описания из репозитория |
| Вход отклонён с причиной | обычная причина отказа | см. [История входов и журнал аудита](История-входов-и-журнал-аудита.md) |

Ключ можно выпустить и на сервере, без панели: команда описана в <https://github.com/calleograph/mfa-gate/blob/main/docs/api.md>. Срока действия у ключей нет, и вебхуков об исходе входа нет: см. [Планы развития](Планы-развития.md).
