# Создание администратора

*Для кого: главный администратор MFA Gate.*

Страница объясняет, откуда берётся первый администратор и как добавить других: локальных, из Active Directory или из консоли сервера. В результате у системы будет минимум два главных администратора, и потеря телефона одним из них не оставит организацию без доступа к панели.

## Зачем это нужно

Панелью управляют только учётные записи с ролью. Вход в панель всегда требует второго фактора, поэтому администратор, потерявший телефон, без посторонней помощи войти не сможет. Второй главный администратор решает такую ситуацию за минуту, без доступа к серверу и аварийных кодов. Отдельные учётные записи нужны и для журнала: в нём видно, кто именно что изменил.

## Когда пригодится

- Сразу после первоначальной настройки: добавить второго главного администратора.
- В команде появился оператор поддержки или аудитор.
- Администратор из каталога должен входить доменным паролем.

## Что потребуется

- Роль **Главный администратор**: только она назначает роли другим.
- Для администратора из каталога — подключённый каталог: [Подключение Active Directory](Подключение-Active-Directory.md).
- Для способа через консоль — доступ к серверу с `sudo`.

## Где найти

- Новая учётная запись: **Панель → Пользователи → Добавить пользователя**.
- Роль существующей учётной записи: **Панель → Пользователи → карточка → Изменить → Роль в панели управления**.
- Консоль сервера: `sudo mfagatectl admin-init` и `sudo mfagatectl admin <логин>`.

## Роли

| Роль в панели | Кратко |
|---|---|
| **Главный администратор** | всё, включая назначение ролей |
| **Администратор** | настройка системы и пользователей |
| **Оператор** | повседневная работа с пользователями и устройствами |
| **Аудитор** | только просмотр |

Точный перечень прав — [Роли администраторов](Роли-администраторов.md). Последнего активного главного администратора нельзя лишить роли, отключить или удалить: панель ответит «Нельзя лишить прав последнего главного администратора».

## Как это сделать

### Первый администратор: его создаёт установщик

На этапе «Первый администратор» `install.sh` создаёт главного администратора `admin` с временным паролем и показывает пароль один раз. При первом входе панель требует сменить пароль и подключить второй фактор: [Первоначальная настройка](Первоначальная-настройка.md).

Если активный главный администратор уже есть, установщик его не трогает и пишет `главный администратор уже существует (пароль не менялся)`. То же действие можно выполнить отдельно:

```bash
sudo mfagatectl admin-init
```

**Что увидите:** либо строки `главный администратор admin создан`, `пароль (показывается один раз): …` и `пароль временный: при первом входе в панель его нужно сменить`, либо `главный администратор уже есть — пропущено`.

### Локальный администратор в панели

1. Откройте **Панель → Пользователи** и нажмите **Добавить пользователя**.
2. В поле **Источник учётной записи** выберите **Локальный**.
3. Заполните **Логин** (без пробелов) и **Имя**. При желании — **Почта** и **Телефон**.
4. Задайте **Пароль** не короче 12 символов.
5. В поле **Роль в панели управления** выберите роль. Подсказка под полем напоминает: «Администратор обязан подключить второй фактор при первом входе».
6. Нажмите **Создать**.

**Что увидите:** учётная запись появилась в списке, роль видна в карточке.

Передайте логин и пароль коллеге безопасным способом, не в общем чате. Пароль, заданный в панели, не временный: попросите коллегу сразу сменить его через меню профиля → **Сменить пароль**.

При первом входе новый администратор увидит экран **Подключите второй фактор** и настроит приложение-аутентификатор так же, как вы на шаге 3 первоначальной настройки.

### Администратор из Active Directory

1. Откройте **Панель → Пользователи → Добавить пользователя**.
2. В поле **Источник учётной записи** выберите **Из каталога**. Укажите **Логин** как в каталоге: `sAMAccountName` или UPN. Имя, почта, телефон и группы подтянутся из каталога.
3. Выберите **Роль в панели управления** и нажмите **Создать**.

Если сотрудник уже есть в списке (например, входил в VPN или личный кабинет), откройте его карточку, нажмите **Изменить** и выберите роль.

Такой администратор входит доменным паролем. Пароль меняется в каталоге, а не в MFA Gate. Если у сотрудника уже привязан телефон, панель после пароля отправит запрос на телефон; если фактора нет — попросит подключить TOTP.

### Администратор из консоли сервера

Если войти в панель некому, главного администратора создаёт команда:

```bash
sudo mfagatectl admin ivanov
```

**Что увидите:**

```text
главный администратор ivanov создан
пароль (показывается один раз): …
при первом входе в панель будет предложено подключить TOTP
```

Пароль сгенерирован случайно и не временный. Если локальная учётная запись `ivanov` уже есть, команда задаёт ей новый пароль, снимает блокировку и делает её главным администратором; второй фактор при этом сохраняется. Для учётной записи из каталога команда не работает и отвечает `пользователь из каталога: назначьте роль в панели, пароль меняется в каталоге`.

Каждое такое действие попадает в журнал как **Администратор создан в консоли** с уровнем предупреждения.

## Что получится

- В системе минимум два главных администратора, у каждого свой второй фактор.
- Операторы и аудиторы видят только разрешённые разделы; разделы без прав в меню не показываются.
- В **Панель → Журнал** видно, кто и когда входил.

Совет: держите у каждого администратора два способа подтверждения — телефон и TOTP. Если оба потеряны, войти поможет аварийный код с сервера: при входе его вводят в поле **Код из приложения** или, если TOTP нет, по кнопке **Ввести аварийный код**. Подробно — [Аварийный доступ администратора](Аварийный-доступ-администратора.md).

## Если не получается

| Что видно | Почему | Что сделать |
|---|---|---|
| Нет поля **Роль в панели управления** | у вашей роли нет права назначать роли | попросите главного администратора |
| «Нельзя лишить прав последнего главного администратора» | вы меняете роль единственного главного администратора | сначала назначьте второго |
| Доменный администратор не входит в панель | у учётной записи нет роли или пароль не проходит в каталоге | проверьте роль в карточке и [Решение проблем каталога](Решение-проблем-каталога.md) |
| `пользователь из каталога: назначьте роль в панели, пароль меняется в каталоге` | команда `admin` вызвана для учётной записи из каталога | назначьте роль в панели или используйте другой локальный логин |
