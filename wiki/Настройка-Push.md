# Настройка Push

*Для кого: администратор MFA Gate.*

Push — сигнал на телефон «есть запрос на вход». С ним сотрудник получает уведомление сразу после ввода пароля, даже если приложение закрыто. Без него MFA Gate тоже работает, но сотруднику приходится самому открывать приложение. Статья помогает выбрать способ доставки и включить Firebase Cloud Messaging (FCM).

## Зачем это нужно

Android не держит приложения постоянно запущенными. Чтобы закрытое приложение узнало о запросе, нужен сервис доставки уведомлений. MFA Gate отправляет через него только сигнал:

```json
{"type": "auth_request", "request_id": "<uuid>", "v": "1"}
```

В сигнале нет логина, ресурса, адреса и времени. Получив его, телефон сам забирает подробности с сервера MFA Gate по HTTPS и показывает уведомление. Поэтому через сервис доставки данные о входах не проходят. Сам сигнал ничего не разрешает: подтверждение всегда подписывается ключом телефона.

## Когда пригодится

- Сотрудники жалуются, что запрос «не приходит», пока не откроешь приложение.
- В **Обзоре** или **Диагностике** предупреждение «Доставка push: провайдеры не настроены».
- Перед запуском MFA для большого отдела: с push вход в VPN занимает несколько секунд.

## Способы доставки

| Способ | Вариант приложения | Состояние |
|---|---|---|
| Без push: приложение само опрашивает сервер | `foss` и `gms` | работает всегда, ничего настраивать не нужно |
| FCM (Firebase Cloud Messaging) | `gms` | реализован; на реальном проекте Firebase и телефонах ещё не проверялся |
| HMS (Huawei Push Kit) | сборки с HMS нет | экспериментально, только серверная часть |
| UnifiedPush | поддержки в приложении нет | экспериментально, только серверная часть |

### Без push

- **Приложение открыто** — держит постоянное соединение с сервером и показывает запрос сразу.
- **Приложение закрыто** — проверяет запросы в фоне примерно раз в 15 минут. Для VPN этого мало: после ввода пароля сотрудник должен сам открыть приложение, пока не истекло время ответа (45 с по умолчанию).

Объясните сотрудникам порядок: «ввёл пароль в VPN → открыл MFA Gate → нажал **Подтвердить**». Если этот порядок неудобен и у сотрудников телефоны с сервисами Google, включите FCM. Для телефонов без сервисов Google удобнее TOTP: [Настройка TOTP](Настройка-TOTP.md).

## Что потребуется для FCM

- Доступ к серверу MFA Gate с правами `sudo`.
- Учётная запись Google для проекта Firebase **вашей организации**. Общего проекта MFA Gate нет.
- Доступ с сервера к `oauth2.googleapis.com` и `fcm.googleapis.com` по HTTPS.
- Приложение в варианте `gms` на телефонах сотрудников: [Приложение MFA Gate Authenticator](Приложение-MFA-Gate-Authenticator.md).

## Где найти

- Состояние доставки: **Панель → Диагностика**, строка «Доставка push», и **Панель → Обзор**, блок «Что требует действий».
- Канал каждого телефона: **Панель → Устройства**, колонка **Push** (например, «FCM» или «Нет канала»), и карточка сотрудника, блок **Телефоны** («push: fcm» или «без push-канала»).
- Настройки: файл `/opt/mfa-gate/deploy/.env` и `deploy/compose.override.yml` на сервере. В панели push не настраивается.

## Как включить FCM

### Шаг 1. Создайте проект Firebase и Android-приложение

1. Откройте <https://console.firebase.google.com> и создайте проект. Google Analytics не нужен.
2. В проекте: **Project settings → General → Your apps → Add app → Android**. **Package name** — `io.github.calleograph.mfagate`.
3. Скачайте `google-services.json`. Из него возьмём публичные параметры приложения; встраивать файл в приложение не нужно.

### Шаг 2. Создайте ключ service account

**Project settings → Service accounts → Generate new private key**.

**Что увидите:** скачан JSON с полями `"type": "service_account"`, `private_key`, `client_email`. Это секрет сервера, храните его как пароль. Проверьте, что в Google Cloud Console для проекта включён API **Firebase Cloud Messaging API (V1)**.

### Шаг 3. Соберите файл для MFA Gate

MFA Gate читает один JSON: файл service account и раздел `client` с публичными параметрами приложения. Перенесите оба файла на сервер и выполните:

```bash
sudo apt-get install -y jq
jq --slurpfile g google-services.json '. + {client: {
  project_id:     $g[0].project_info.project_id,
  application_id: $g[0].client[0].client_info.mobilesdk_app_id,
  api_key:        $g[0].client[0].api_key[0].current_key,
  sender_id:      $g[0].project_info.project_number}}' service-account.json > fcm.json
jq '.client' fcm.json
```

**Что увидите:** четыре заполненных поля, ни одно не равно `null`. Если в проекте несколько Android-приложений, замените `client[0]` на номер нужного.

Ограничьте API-ключ в Google Cloud Console (**APIs & Services → Credentials**): только приложение `io.github.calleograph.mfagate` и только Firebase Cloud Messaging. Сам ключ не секретен, он есть в любом опубликованном приложении с Firebase.

### Шаг 4. Подключите файл к контейнерам

```bash
cd /opt/mfa-gate/deploy
sudo install -m 644 /путь/к/fcm.json data/secrets/fcm.json
rm -f /путь/к/fcm.json /путь/к/service-account.json
```

Каталог `data/secrets` закрыт для посторонних, а права 644 на файле нужны, чтобы его прочитал процесс в контейнере.

Создайте `deploy/compose.override.yml`. Команда `mfagatectl` подхватывает его сама:

```bash
sudo tee /opt/mfa-gate/deploy/compose.override.yml >/dev/null <<'EOF'
services:
  api:
    secrets: [master_key, fcm]
  worker:
    secrets: [master_key, fcm]

secrets:
  fcm:
    file: ${MFA_GATE_DATA:?}/secrets/fcm.json
EOF
```

Укажите путь к файлу внутри контейнера и перезапустите:

```bash
sudo sed -i 's|^MFA_GATE_PUSH_FCM_CREDENTIALS_FILE=.*|MFA_GATE_PUSH_FCM_CREDENTIALS_FILE=/run/secrets/fcm|' /opt/mfa-gate/deploy/.env
sudo mfagatectl start
```

**Что увидите:** `запущено`.

### Шаг 5. Проверьте

```bash
sudo mfagatectl logs worker | grep push-провайдеры
sudo mfagatectl diagnose | grep 'Доставка push'
```

**Что увидите:** `push-провайдеры: fcm` и строку «Доставка push» без предупреждения. Если в журнале `worker` есть `FCM не настроен: …`, файл не читается или в нём не хватает полей. Сервер при этом продолжает работать без push.

Затем на телефоне с приложением `gms`:

1. Привяжите телефон ([Регистрация Android-устройства](Регистрация-Android-устройства.md)) или откройте приложение на уже привязанном: оно получит параметры FCM при следующем обращении к серверу.
2. Закройте приложение смахиванием из списка недавних, но не через «Остановить» в настройках Android.
3. Войдите в VPN под этим сотрудником.

**Что увидите:** через несколько секунд уведомление «Запрос на вход». В карточке сотрудника у телефона «push: fcm».

## Что получится

- Сотрудники с вариантом `gms` получают уведомление сразу, даже при закрытом приложении.
- Телефоны без сервисов Google продолжают работать без push.
- Отправкой занимается фоновый сервис `worker`: до 3 попыток на устройство. Если сервис доставки сообщил, что токен телефона недействителен, телефон продолжает работать без push, пока приложение не пришлёт новый токен.

## HMS и UnifiedPush

Обе отправки написаны только на стороне сервера и на реальных аккаунтах не проверялись, в приложении их поддержки пока нет. Переменные HMS задаются в `compose.override.yml`, UnifiedPush включается списком разрешённых хостов распределителя в `MFA_GATE_PUSH_UNIFIEDPUSH_HOSTS`. Подробности: <https://github.com/calleograph/mfa-gate/blob/main/docs/push.md>. Сроки появления в приложении: [Планы развития](Планы-развития.md).

## Если не получается

| Что видно | Почему | Что сделать |
|---|---|---|
| В журнале `worker` «FCM не настроен: …» | файл не прочитан или неполный | проверьте путь в `.env`, права 644 и раздел `client` |
| `push-провайдеры: нет (только long-poll)` | переменная пуста или override не подхватился | проверьте `.env` и `compose.override.yml`, выполните `sudo mfagatectl start` |
| У телефона «без push-канала» | вариант `foss`, нет сервисов Google или приложение не получило токен | откройте приложение; при необходимости привяжите телефон заново |
| Уведомление не приходит после «Остановить» в настройках | Android не доставляет push принудительно остановленным приложениям | откройте приложение вручную один раз |
| Уведомления приходят с задержкой | экономия заряда ограничивает приложение | отключите экономию заряда для MFA Gate Authenticator, см. [Решение проблем телефона и push](Решение-проблем-телефона-и-push.md) |
| Телефон привязан к двум организациям, push от второй не приходит | один телефон получает push только от одного проекта Firebase | для второй организации сотрудник открывает приложение вручную или использует TOTP |
