# Участие в разработке

*Для кого: разработчик, тестировщик, администратор, который хочет предложить исправление, и все, кто готов проверить MFA Gate на своей инфраструктуре.*

MFA Gate — открытый проект под лицензией Apache-2.0. Здесь сказано, какая помощь нужнее всего, как устроен репозиторий, как поднять окружение и запустить тесты и какие правила действуют для изменений. Правила для разработчиков в полном виде — [CONTRIBUTING.md](https://github.com/calleograph/mfa-gate/blob/main/CONTRIBUTING.md).

## Чем можно помочь

| Помощь | Почему это важно |
| --- | --- |
| Проверка на настоящих VPN-шлюзах | RADIUS покрыт тестами, но с настоящими шлюзами сторонних производителей вход ещё не проверяли ([Что проверено](Что-проверено.md)) |
| Проверка с настоящим Active Directory | Каталог проверен на OpenLDAP |
| Проверка приложения на реальных телефонах | Биометрия, работа в фоне и экономия заряда проверены только тестами без устройства |
| Исправления и тесты | Каждое изменение поведения сопровождается тестом |
| Документация и переводы | Вики и описания в `docs/` |

Перед большой доработкой откройте задачу на GitHub и опишите замысел, чтобы не делать одну работу дважды. Об уязвимостях не пишите в открытых задачах: правила — [SECURITY.md](https://github.com/calleograph/mfa-gate/blob/main/SECURITY.md).

## Как устроен репозиторий

| Каталог | Что внутри |
| --- | --- |
| `server/mfa_gate/` | Сервер: `api/` (личный кабинет, панель, REST API, Device API), `radius/`, `services/` (сценарий входа, политики, LDAP, push, журнал), `security/`, `worker.py`, `config.py` (все переменные `MFA_GATE_*`) |
| `server/migrations/` | Миграции базы (Alembic) |
| `server/tests/` | Юнит-тесты, тесты каталога (`ldap_fixture/`), сквозные тесты (`test_stack.py`) |
| `server/web/` | Личный кабинет и панель: статические файлы без сборки, их отдаёт `api` |
| `android/` | Приложение MFA Gate Authenticator ([android/README.md](https://github.com/calleograph/mfa-gate/blob/main/android/README.md)) |
| `deploy/` | `compose.yml`, `.env.example`, `mfagatectl`, примеры настроек прокси |
| `integrations/` | Скрипт для OpenVPN |
| `scripts/` | Сквозные тесты в Docker (`e2e.sh`), нагрузочный тест RADIUS, проверка на частные данные, публикация вики |
| `docs/` | Документация; `docs/adr/` — архитектурные решения, `docs/threat-model.md` — модель угроз |
| `wiki/` | Исходники этой вики ([Сопровождение вики](Сопровождение-вики.md)) |

## Окружение сервера

Нужны Python 3.13 или новее и Docker.

```bash
cd server
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt

# PostgreSQL для разработки, только на loopback
docker run -d --name mfa-gate-dev-pg -p 127.0.0.1:55432:5432 \
  -e POSTGRES_USER=mfagate -e POSTGRES_PASSWORD=mfagate -e POSTGRES_DB=mfagate postgres:16-alpine

export MFA_GATE_DATABASE_URL=postgresql+asyncpg://mfagate:mfagate@127.0.0.1:55432/mfagate
.venv/bin/python -m mfa_gate gen-master-key > "$HOME/mfa-gate-dev.key"   # только один раз; файл вне репозитория
export MFA_GATE_MASTER_KEY_FILE="$HOME/mfa-gate-dev.key"
export MFA_GATE_PUBLIC_URL=http://127.0.0.1:8080
export MFA_GATE_COOKIE_SECURE=false     # панель по http://, только локально
export MFA_GATE_RADIUS_PORT=18120

.venv/bin/python -m mfa_gate migrate
.venv/bin/python -m mfa_gate create-admin admin   # пароль печатается один раз
.venv/bin/python -m mfa_gate api                  # http://127.0.0.1:8080, описание API: /api/docs
.venv/bin/python -m mfa_gate radius               # в отдельном терминале
.venv/bin/python -m mfa_gate worker               # в отдельном терминале
```

Мастер-ключ храните в файле: если перезапустить сервер с другим ключом, зашифрованные секреты (TOTP, RADIUS, каталоги) не расшифруются. Генерировать ключ нужно один раз. Остальные переменные — [Справочник: конфигурация](Справочник-конфигурация.md).

## Тесты

| Набор | Команда | Что нужно |
| --- | --- | --- |
| Проверка стиля | `cd server && .venv/bin/ruff check mfa_gate tests` | — |
| Юнит-тесты | `cd server && .venv/bin/pytest` | — (тесты каталога и сквозные без окружения пропускаются) |
| Каталог на настоящем OpenLDAP | `server/tests/ldap_fixture/run.sh` | Docker; OpenLDAP с TLS поднимается на 127.0.0.1 и удаляется после прогона |
| Сквозные тесты в Docker | `scripts/e2e.sh` | Docker и `server/.venv`; собирает образ, ставит экземпляр со случайными портами на 127.0.0.1, проверяет установку, вход, обновление, откат и копии, затем всё удаляет (`--keep` оставляет экземпляр) |
| Сквозные тесты против любой установки | `MFA_GATE_TEST_URL=http://192.0.2.10:8080 MFA_GATE_TEST_RADIUS=192.0.2.10:1812 MFA_GATE_TEST_KEY=<key_id:secret> MFA_GATE_TEST_CLIENT_CIDR=<адрес теста>/32 pytest tests/test_stack.py` | Ключ API со всеми правами (`create-api-client … --scopes all`) |
| Приложение Android | `cd android && ./gradlew :app:testFossDebugUnitTest :app:assembleFossDebug :app:assembleGmsDebug` | JDK 21, Android SDK |
| Частные данные | `python3 scripts/check_private_data.py` | — |

Пока работает `scripts/e2e.sh`, не правьте файлы в `deploy/` и `scripts/`: bash читает скрипты по ходу выполнения.

## Правила для изменений

- Каждое изменение поведения сопровождается тестом. Для RADIUS, подтверждения на телефоне и политик нужен сквозной тест в `server/tests/test_stack.py`.
- Протокол телефона ([docs/protocol/device-api.md](https://github.com/calleograph/mfa-gate/blob/main/docs/protocol/device-api.md)) меняется только вместе на сервере и в приложении.
- Секреты не пишутся в журналы, в аргументы командной строки и в ответы API, кроме одноразового показа при создании.
- Новая настройка получает безопасное значение по умолчанию. Опасный режим включается явно и пишется в журнал.
- Комментарии в коде и сообщения для администратора — на русском.
- Изменение поведения или настройки отражается в `CHANGELOG.md` (раздел «Не выпущено»), в документации и в вики.

## Никаких частных данных

Репозиторий публичный. В коде, тестах, документации и вики допустимы только нейтральные значения:

- домены `example.org`, `example.com`, `example.net`;
- адреса `192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24` и частные диапазоны;
- никаких названий организаций, реальных логинов, адресов почты, путей вида `/home/<имя>`, ключей и токенов.

Перед коммитом выполните `python3 scripts/check_private_data.py`. Если находка — публичный сервис (например, адрес службы push), добавьте домен в `scripts/private-data.allow` и объясните это в описании запроса на слияние. Если частные данные уже попали в коммит, не исправляйте их новым коммитом поверх: сообщите сопровождающим, историю придётся переписать.

## Коммиты и запросы на слияние

- Одно логическое изменение на коммит. Сообщение — короткая строка о том, что сделано (`radius: отбрасывать пакет без State при повторе`), при необходимости — абзац о причине.
- Запрос на слияние проходит CI: ruff, pytest, тесты каталога, сквозные тесты в Docker, сборку Android и проверку на частные данные.
- Отправляя изменения, вы соглашаетесь распространять их на условиях Apache-2.0 ([Лицензия](Лицензия.md)).

## Выпуск версии

Номер версии хранится в файле `VERSION` и повторяется в `server/mfa_gate/config.py` и `android/VERSION`. Тег `vX.Y.Z` запускает сборку выпуска: образ `ghcr.io/calleograph/mfa-gate:X.Y.Z`, APK обеих сборок и страницу выпуска на GitHub. Без секретов подписи (например, в форке) APK подписываются одноразовым ключом, а выпуск помечается как предварительный.
