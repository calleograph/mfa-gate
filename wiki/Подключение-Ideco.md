# Подключение Ideco

Ideco NGFW Novum сам проверяет логин и доменный пароль сотрудника, а у MFA Gate спрашивает только второй фактор: подтверждение на телефоне или код TOTP. Для этого в MFA Gate у RADIUS-клиента Ideco ставится «Первый фактор» — `gateway`.

> **Не проверено на реальном Ideco.** Сценарий собран по официальной документации Ideco («Двухфакторная аутентификация») и по сквозным тестам RADIUS MFA Gate. Если вы проверили его, пришлите исправления через Issues или Pull Request.

Обозначения: `192.0.2.10` — сервер MFA Gate, `198.51.100.1` — Ideco, `СЕКРЕТ` — общий секрет RADIUS-клиента, `ivanov` — тестовый сотрудник.

## Как это работает

1. Сотрудник вводит логин и пароль в VPN-клиенте. Ideco проверяет их сам (в своём каталоге или AD).
2. Ideco отправляет в MFA Gate RADIUS-запрос (только PAP):
   - режим **«Логин»** — логин и пустой пароль. MFA Gate отправляет push и держит запрос до ответа. Если телефона нет, а TOTP есть, MFA Gate просит код (Access-Challenge), Ideco показывает сообщение «Введите одноразовый код» и отправляет код;
   - режим **«Логин и OTP-код»** — Ideco сам спрашивает у сотрудника код и присылает логин и код. MFA Gate проверяет его как TOTP. Push в этом режиме не используется.
3. MFA Gate отвечает «пустить» или «отказать», Ideco поднимает или не поднимает туннель.

В режиме `gateway` MFA Gate не проверяет пароль: пустое значение запускает второй фактор, 6–8 цифр проверяются как код TOTP, прочие значения не проверяются и ошибкой не считаются. Этот режим действует только для RADIUS-клиента Ideco, остальные шлюзы по-прежнему присылают пароль. Подробно — [docs/integrations.md](https://github.com/calleograph/mfa-gate/blob/main/docs/integrations.md#первый-фактор-mfa_gate-и-gateway).

## Шаг 1. Сотрудники и факторы

Пароль в режиме `gateway` не приходит в MFA Gate, поэтому сотрудник должен быть известен MFA Gate заранее и иметь второй фактор:

- сотрудник сам подключает фактор в [личном кабинете](Личный-кабинет-сотрудника.md) из офисной сети;
- или администратор заводит его в «Пользователях» (источник «Из каталога», тот же логин, что в Ideco) и привязывает телефон или выдаёт TOTP.

Логин в Ideco и в MFA Gate должен совпадать. Если Ideco передаёт логин в виде `CORP\ivanov` или UPN, проверьте на стенде, что MFA Gate находит того же пользователя (в «Истории входов» — правильная учётная запись).

## Шаг 2. RADIUS-клиент в MFA Gate

Панель (`/admin/`) → «RADIUS-клиенты» → «Добавить клиент»:

| Поле | Значение |
|---|---|
| Название | `Ideco` |
| Ресурс | `VPN офис` (создайте ресурс типа VPN, если его нет) |
| Адрес шлюза | `198.51.100.1` — адрес, с которого пакеты Ideco приходят на MFA Gate (после NAT) |
| Первый фактор | `gateway` — шлюз уже проверил пароль |
| Общий секрет | оставьте пустым — MFA Gate сгенерирует длинный секрет |

**Ожидаемый результат:** окно с секретом. Скопируйте его — он показывается один раз.

`gateway` ставьте только для шлюза, который действительно проверяет пароль сам. Не назначайте этот режим сети адресов: один клиент — один Ideco.

## Шаг 3. RADIUS-сервер 2FA в Ideco

Это отдельная настройка, не «Интеграция с RADIUS» (внешний каталог).

Пользователи → Аутентификация → Двухфакторная аутентификация → RADIUS-серверы → добавить:

| Поле Ideco | Значение |
|---|---|
| Название | `MFA Gate` |
| Домен или IP-адрес | `192.0.2.10` |
| Секрет | `СЕКРЕТ` из шага 2 |
| Порт | `1812` (или ваш `MFA_GATE_RADIUS_PORT`) |
| Время ожидания, с | **`60`** (по умолчанию 4 — push не успеет) |
| Количество попыток подключения | `1`–`3` |
| Режим запроса к RADIUS | «Логин» — push и TOTP; «Логин и OTP-код» — только TOTP |
| Сообщение при вводе OTP-кода | только для «Логин и OTP-код», например `Код из приложения MFA Gate` |

Почему 60 секунд: MFA Gate ждёт ответа на телефоне до `MFA_GATE_PUSH_TIMEOUT` (45 с). Время ожидания Ideco должно быть больше. Если шлюз ждёт меньше, сотрудник подтверждает вход, а VPN-клиент уже показал ошибку. Повторы Ideco безопасны: MFA Gate узнаёт повтор и не шлёт второй push.

Если вы выбираете «Логин и OTP-код», push не нужен: сотрудникам достаточно TOTP.

## Шаг 4. Доступ по VPN

Пользователи → VPN-подключения → Доступ по VPN: для нужных групп выберите метод двухфакторной аутентификации — RADIUS-сервер `MFA Gate` из шага 3.

Методы Ideco «TOTP-токен» и «SMS» для пользователей из каталога RADIUS не работают: для них второй фактор даёт только MFA Gate. Где ещё в Ideco задаётся метод 2FA для конкретных протоколов VPN, уточните в документации шлюза.

## Шаг 5. Сеть

- UDP 1812 на сервер MFA Gate — только с адреса Ideco ([Настройка RADIUS](Настройка-RADIUS.md), шаг 4). Если Ideco и MFA Gate на разных площадках и между ними Интернет — только внутри IPsec или WireGuard.
- Телефоны сотрудников подтверждают вход **до** подключения VPN, поэтому Device API должен быть доступен из Интернета: [Сетевая схема и публикация](Сетевая-схема-и-публикация.md).

## Шаг 6. Проверка

1. Режим «Логин»: вход в VPN под `ivanov` → на телефон приходит запрос → «Подтвердить» → VPN подключается.
2. «Отклонить» на телефоне → отказ сразу, в «Истории входов» причина `push_denied`.
3. Неверный пароль → отказ от Ideco, push не приходит, в «Истории входов» MFA Gate записи нет (пароль проверял Ideco).
4. Нет ответа на телефоне → отказ примерно через 45 секунд, а не раньше по таймауту Ideco.
5. Пользователь только с TOTP: Ideco показывает запрос кода, кириллица читается, код принимается, повтор того же кода отклоняется.
6. Режим «Логин и OTP-код»: Ideco спрашивает код с вашим сообщением, вход проходит, в истории метод `totp`.
7. В «Истории входов» — канал `radius`, ресурс `VPN офис`, клиент `Ideco`, IP сотрудника (если Ideco передаёт Calling-Station-Id).
8. В «Журнале» нет `radius.bad_authenticator` — Ideco отправляет Message-Authenticator.

Если пакеты не доходят — [Диагностика](Диагностика.md), раздел «RADIUS не отвечает».
