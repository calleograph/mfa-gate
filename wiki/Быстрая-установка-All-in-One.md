# Быстрая установка All-in-One

*Для кого: системный администратор, который ставит MFA Gate на свой сервер.*

All-in-One — все части MFA Gate на одном сервере: база PostgreSQL, RADIUS-сервер, веб-сервис с личным кабинетом и панелью, фоновый обработчик. После установки у вас будет работающая система по адресу `http://<IP сервера>:8080`, первый администратор с временным паролем и команда управления `mfagatectl`.

## Зачем это нужно

Установщик сам ставит Docker, создаёт конфигурацию с секретами, загружает образ версии 0.3.3, применяет миграции базы, запускает сервисы и проверяет, что они отвечают. Вручную это несколько десятков действий, в каждом из которых легко ошибиться.

## Когда пригодится

- Первая установка MFA Gate.
- Повторная установка поверх существующей: установщик сохраняет настройки и данные и приводит контейнеры к состоянию конфигурации.
- Установка на новый сервер при восстановлении после сбоя.

## Что потребуется

- Сервер, который прошёл проверку: [Требования к серверу](Требования-к-серверу.md).
- Права `sudo`.
- 5–10 минут.

## Как это сделать

### Шаг 1. Получите проект

```bash
sudo apt-get update && sudo apt-get install -y git
sudo git clone https://github.com/calleograph/mfa-gate.git /opt/mfa-gate
cd /opt/mfa-gate
```

Каталог может быть любым; в примерах вики — `/opt/mfa-gate`. Чтобы поставить конкретный выпуск, а не текущее состояние ветки, переключитесь на его тег: `sudo git checkout v0.3.3`.

### Шаг 2. Запустите установщик

```bash
sudo ./install.sh
```

Установщик проходит шесть этапов и печатает каждый с номером, например `[1/6] Проверка сервера`. Удачная проверка отмечается галочкой.

| Этап на экране | Что происходит |
|---|---|
| `Проверка сервера` | ОС, архитектура, память, свободное место, доступ к `ghcr.io` или `github.com` |
| `Docker и необходимые пакеты` | ставит `curl`, `openssl`, `iproute2`, при необходимости Docker и Docker Compose v2, включает службу Docker |
| `Конфигурация` | создаёт `deploy/.env` с правами 600: определяет IP-адрес сервера, выбирает свободный HTTP-порт от 8080 до 8100, проверяет UDP 1812, генерирует пароль базы. Существующий `.env` не трогает |
| `Образы, база данных и запуск` | создаёт мастер-ключ `deploy/data/secrets/master.key`, загружает образ, применяет миграции, запускает сервисы и ждёт их готовности до 3 минут. На экране: `это займёт 1–5 минут; подробности — в журнале` |
| `Первый администратор` | создаёт главного администратора `admin` с временным паролем, если его ещё нет |
| `Проверка работы` | проверяет `/health/ready`, страницу панели и порт RADIUS; создаёт ссылку `/usr/local/bin/mfagatectl` |

Если образа нужной версии нет в реестре, установщик соберёт его из исходников каталога. Это добавит несколько минут.

Подробный журнал каждого запуска пишется в `/var/log/mfa-gate/install-<дата>-<время>.log`. Пароль администратора в журнал не попадает.

**Что увидите:** в конце — итоговый блок.

```text
Готово. MFA Gate 0.3.3 установлен.

  Панель администратора:  http://192.0.2.10:8080/admin/
  Личный кабинет:         http://192.0.2.10:8080/   (сотрудники сами настраивают второй фактор)
  Логин:                  admin
  Временный пароль:       <24 случайных символа>
                          (показан один раз; при первом входе его нужно сменить, затем подключить второй фактор)
  RADIUS для VPN-шлюзов:  UDP-порт 1812 на адресе этого сервера
  Данные и мастер-ключ:   /opt/mfa-gate/deploy/data   (сохраните копию data/secrets/master.key отдельно!)

  Работа идёт по HTTP — только для изолированной сети и первичной настройки.
```

**Сразу сохраните временный пароль.** Он показывается один раз. Если вы его потеряли, задайте новый командой `sudo mfagatectl admin admin`: [Аварийный доступ администратора](Аварийный-доступ-администратора.md).

### Шаг 3. Проверьте установку

```bash
sudo mfagatectl status
```

**Что увидите:** сервисы `api`, `radius`, `worker` и `postgres` в состоянии `Up … (healthy)`, внизу строка `версия: 0.3.3, образ: ghcr.io/calleograph/mfa-gate`. Служебный сервис `migrate` применяет миграции и завершается, поэтому в списке работающих его может не быть.

```bash
curl -fsS http://127.0.0.1:8080/health/ready; echo
```

**Что увидите:** JSON со строкой `"status":"ok"` и номером версии. Если установщик выбрал другой порт, подставьте его — он есть в строке «Панель администратора».

Откройте в браузере адрес панели из итогового блока. **Что увидите:** страницу «Вход в панель управления». Адрес без `/admin/` открывает личный кабинет сотрудника.

### Шаг 4. Сохраните мастер-ключ

Мастер-ключом зашифрованы секреты TOTP, RADIUS-клиентов, каталогов и push-токены. Без него резервные копии бесполезны. Скопируйте ключ в надёжное место вне сервера, отдельно от копий базы:

```bash
sudo cat /opt/mfa-gate/deploy/data/secrets/master.key
```

**Что увидите:** одну строку base64 длиной 44 символа. Подробнее: [Резервное копирование](Резервное-копирование.md).

## Нестандартные порты и адрес

При первой установке значения можно задать переменными окружения. Они записываются в `deploy/.env`, дальше всё берётся оттуда.

| Переменная | По умолчанию | Когда менять |
|---|---|---|
| `MFA_GATE_HTTP_PORT` | 8080 или первый свободный до 8100 | нужен конкретный порт |
| `MFA_GATE_RADIUS_PORT` | 1812 | на сервере уже есть RADIUS-сервер |
| `MFA_GATE_PUBLIC_URL` | `http://<IP сервера>:<порт>` | установщик определил не тот адрес или у сервера уже есть имя |
| `COMPOSE_PROJECT_NAME` | `mfa-gate` | на сервере второй экземпляр MFA Gate |

```bash
cd /opt/mfa-gate
sudo MFA_GATE_HTTP_PORT=8180 MFA_GATE_RADIUS_PORT=11812 MFA_GATE_PUBLIC_URL=http://mfa.example.org:8180 ./install.sh
```

**Что увидите:** в итоговом блоке — заданные порт и адрес. Проверить можно так: `sudo grep -E '^MFA_GATE_(HTTP_PORT|RADIUS_PORT|PUBLIC_URL)=' /opt/mfa-gate/deploy/.env`.

Если `.env` уже существует, переменные при повторном запуске **не применяются**. Измените значения в `deploy/.env` и выполните `sudo mfagatectl start`: контейнеры пересоздадутся с новыми настройками. Нестандартный порт RADIUS укажите и на VPN-шлюзе.

## Повторный запуск

`sudo ./install.sh` можно запускать снова. Он сохраняет `.env`, мастер-ключ, данные и пароль администратора, а на этапе «Первый администратор» пишет `главный администратор уже существует (пароль не менялся)`. Так удобно чинить установку после ручных изменений. Если в `.env` указана другая версия, чем в каталоге, установщик возьмёт версию из `.env`.

## Что получится

- Работают четыре сервиса: `api`, `radius`, `worker`, `postgres`.
- Панель открывается по адресу `http://<IP>:<порт>/admin/`, личный кабинет — по `http://<IP>:<порт>/`.
- RADIUS принимает запросы на UDP 1812; пока не заведены RADIUS-клиенты, все пакеты молча отбрасываются.
- Команда `mfagatectl` доступна из любого каталога: `status`, `logs`, `update`, `backup`, `diagnose` и другие.

Пока система работает по HTTP. Это допустимо только в изолированной сети: [Работа по HTTP](Работа-по-HTTP.md).

## Если не получается

При остановке установщик печатает `ОШИБКА на этапе «…»`, причину, строку «Как исправить» и путь к журналу.

| Что видно | Почему | Что сделать |
|---|---|---|
| `мало памяти: … МБ` | меньше 900 МБ памяти | добавьте память серверу |
| `мало места на диске: … ГБ` | меньше 5 ГБ на разделе с каталогом | освободите место или расширьте раздел |
| `нет доступа к ghcr.io и github.com` | DNS, шлюз или прокси | проверьте сеть; прокси — [Требования к серверу](Требования-к-серверу.md), шаг 3 |
| `порт 1812/udp (RADIUS) занят другой программой` | на сервере другой RADIUS-сервер | `sudo MFA_GATE_RADIUS_PORT=11812 ./install.sh` и этот порт на шлюзе |
| `порт …/tcp занят` | заданный HTTP-порт занят | `sudo MFA_GATE_HTTP_PORT=8180 ./install.sh` |
| `контейнеры не запустились: …` | образ не загрузился или сервис не стал готов за 3 минуты | `sudo /opt/mfa-gate/deploy/mfagatectl status` и `… logs`, затем [Решение проблем установки и обновления](Решение-проблем-установки-и-обновления.md) |
| `API не отвечает на /health/ready` | веб-сервис не видит базу | `sudo mfagatectl logs api` |
