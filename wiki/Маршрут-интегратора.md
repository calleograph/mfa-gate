# Маршрут интегратора

*Для кого: разработчик или инженер, который связывает MFA Gate с другими системами организации.*

## Кому подходит

Этот маршрут для вас, если нужно добавить второй фактор в своё приложение, подключить шлюз без RADIUS, автоматизировать управление пользователями или забирать журнал в другую систему. MFA Gate даёт для этого REST API с ключами и правами. Протокол телефона (Device API) описан для разработчиков приложения, а не для интеграций.

## Способы интеграции

| Задача | Способ | Страница |
|---|---|---|
| VPN-шлюз с RADIUS | RADIUS, PAP | [Подключение VPN](Подключение-VPN.md) |
| Шлюз сам проверяет пароль, спрашивает только второй фактор | RADIUS, вариант **Сам шлюз** | [Шлюзы с собственной проверкой пароля](Шлюзы-с-собственной-проверкой-пароля.md) |
| OpenVPN без RADIUS | готовый скрипт через REST API | [Подключение OpenVPN](Подключение-OpenVPN.md) |
| Своё приложение с формой входа | REST API: `/api/v1/access-requests` | [Интеграция по REST API](Интеграция-по-REST-API.md) |
| Управление пользователями, ресурсами, RADIUS-клиентами | REST API с правами на нужные области | [Ключи API](Ключи-API.md) |
| Выгрузка истории входов и журнала | REST API: `/auth-requests`, `/audit`, `/audit/export.csv` | [История входов и журнал аудита](История-входов-и-журнал-аудита.md) |

Обратных вызовов (webhook) нет: о событиях интеграция узнаёт запросами к API. Назначать группы и пулы адресов по ответу RADIUS тоже нельзя, это запланировано: [Планы развития](Планы-развития.md).

## Что вы будете уметь

- Выбирать способ интеграции под задачу: RADIUS, вариант **Сам шлюз** или REST API.
- Выпускать ключи с минимальными правами и привязкой к ресурсу и адресам.
- Отправлять запрос входа, ждать решения и обрабатывать запрос кода.
- Обрабатывать отказы по стабильным кодам причин и не раскрывать пользователю лишнего.
- Проверять интеграцию по истории входов до выдачи доступа сотрудникам.
