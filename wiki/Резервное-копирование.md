# Резервное копирование

*Для кого: администратор сервера MFA Gate.*

Страница описывает, что сохранять, чтобы MFA Gate можно было восстановить после сбоя, и как настроить ежедневные копии. Итог — три вещи вне сервера: копия базы, мастер-ключ и файлы настроек.

## Зачем это нужно

В базе хранятся пользователи, привязки телефонов, секреты TOTP, RADIUS-клиенты, политики и история входов. Если база потеряна, каждому сотруднику придётся заново привязывать телефон, а на каждом VPN-шлюзе — менять секрет RADIUS. Копия базы без мастер-ключа не поможет: им зашифрованы все секреты внутри неё.

## Когда пригодится

- Сразу после установки: сохранить мастер-ключ и включить расписание.
- Перед рискованным изменением: настройкой каталога, массовой правкой пользователей.
- При переносе на другой сервер.

## Что потребуется

- Права `sudo` на сервере.
- Место для копий вне сервера: другой сервер, сетевое хранилище, носитель.
- Место для мастер-ключа отдельно от копий: менеджер паролей, сейф.

## Где найти

| Что | Где на сервере | Как сохранять |
|---|---|---|
| Копии базы | `/opt/mfa-gate/deploy/backups/<время>-<метка>/` | `mfagatectl backup`, ежедневно по расписанию, переносить с сервера |
| Мастер-ключ | `/opt/mfa-gate/deploy/data/secrets/master.key` | один раз сохранить вне сервера, отдельно от копий |
| Настройки | `deploy/.env`, `deploy/compose.override.yml` и файл учётных данных FCM, если настраивали push | сохранять вне сервера после каждого изменения |

Мастер-ключ даёт доступ ко всем секретам в копии. Поэтому его хранят не рядом с копиями: кто получит и то и другое, получит секреты TOTP и RADIUS.

## Как это сделать

### Шаг 1. Сохраните мастер-ключ

```bash
sudo cat /opt/mfa-gate/deploy/data/secrets/master.key
```

**Что увидите:** одну строку base64 длиной 44 символа. Сохраните её целиком.

Запишите и отпечаток ключа: по нему потом легко проверить, тот ли ключ сохранён.

```bash
sudo sha256sum /opt/mfa-gate/deploy/data/secrets/master.key | cut -c1-16
```

Тот же отпечаток записывается в манифест каждой копии в строке `master_key_sha256=`.

### Шаг 2. Сделайте копию вручную

```bash
sudo mfagatectl backup
```

**Что увидите:** путь к копии, например `/opt/mfa-gate/deploy/backups/20261119T210000Z-manual`. Время в имени — UTC.

В каталоге три файла:

- `db.dump` — дамп базы в формате `pg_dump -Fc`;
- `SHA256SUMS` — контрольная сумма дампа;
- `manifest` — версия MFA Gate, ревизия схемы базы, время, отпечаток мастер-ключа.

Мастер-ключа в копии нет, так задумано. Каталог копии доступен только root, поэтому проверка ниже запускается через `sudo` целиком.

Проверьте копию:

```bash
sudo sh -c 'cd /opt/mfa-gate/deploy/backups/20261119T210000Z-manual && sha256sum -c SHA256SUMS && cat manifest'
```

**Что увидите:** `db.dump: OK` и строки `version=0.3.1`, `schema=0004`, `created=…`, `master_key_sha256=…`.

Метку можно задать своим словом: `sudo mfagatectl backup before-ldap` создаст каталог `…-before-ldap`. Перед каждым обновлением `mfagatectl update` сам делает копию с меткой `pre-<версия>`.

### Шаг 3. Настройте ежедневную копию

Выберите один из вариантов. В обоих указан полный путь к `deploy/mfagatectl`: так расписание не зависит от ссылки `/usr/local/bin/mfagatectl`, которая указывает на последний установленный экземпляр.

#### Вариант A. cron

```bash
sudo tee /etc/cron.d/mfa-gate-backup >/dev/null <<'EOF'
# Ежедневная копия MFA Gate в 02:30 и удаление ежедневных копий старше 14 дней
30 2 * * * root /opt/mfa-gate/deploy/mfagatectl backup daily >/dev/null 2>>/var/log/mfa-gate/backup.log
50 2 * * * root find /opt/mfa-gate/deploy/backups -maxdepth 1 -type d -name '*-daily' -mtime +14 -exec rm -rf {} +
EOF
```

Проверьте ту же команду вручную: `sudo /opt/mfa-gate/deploy/mfagatectl backup daily`. **Что увидите:** путь к каталогу `…-daily`.

#### Вариант B. Таймер systemd

```bash
sudo tee /etc/systemd/system/mfa-gate-backup.service >/dev/null <<'EOF'
[Unit]
Description=MFA Gate: ежедневная резервная копия
Requires=docker.service
After=docker.service

[Service]
Type=oneshot
ExecStart=/opt/mfa-gate/deploy/mfagatectl backup daily
ExecStartPost=/usr/bin/find /opt/mfa-gate/deploy/backups -maxdepth 1 -type d -name '*-daily' -mtime +14 -exec rm -rf {} +
EOF

sudo tee /etc/systemd/system/mfa-gate-backup.timer >/dev/null <<'EOF'
[Unit]
Description=MFA Gate: расписание резервной копии

[Timer]
OnCalendar=*-*-* 02:30:00
RandomizedDelaySec=10m
Persistent=true

[Install]
WantedBy=timers.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now mfa-gate-backup.timer
sudo systemctl start mfa-gate-backup.service
```

**Что увидите:** `systemctl list-timers mfa-gate-backup.timer` показывает время следующего запуска; в `journalctl -u mfa-gate-backup.service` есть путь к новой копии `…-daily`.

Срок хранения 14 дней — пример. Выберите свой по правилам организации.

### Шаг 4. Переносите копии с сервера

Копии лежат на том же диске, что и база: при отказе диска пропадут обе. Переносите их на другой сервер, например после ежедневной копии:

```bash
sudo rsync -a --delete /opt/mfa-gate/deploy/backups/ backup@backup.example.org:/var/backups/mfa-gate/
```

Используйте отдельную учётную запись с ограниченными правами на принимающей стороне и сохраните там доступ только для владельца. Мастер-ключ на этот же носитель не кладите.

### Шаг 5. Сохраните настройки

Скопируйте вне сервера после установки и после каждого изменения:

- `deploy/.env` — в нём пароль базы и все параметры экземпляра;
- `deploy/compose.override.yml` и файл учётных данных FCM, если настраивали push: [Настройка Push](Настройка-Push.md);
- конфигурацию reverse proxy и сертификаты, если они не выпускаются автоматически.

## Что получится

- Мастер-ключ и его отпечаток хранятся вне сервера.
- Каждую ночь появляется копия `…-daily`, старые удаляются.
- Копии регулярно уходят на другой носитель.
- Файлы настроек сохранены.

Время от времени проверяйте, что копию можно восстановить: разверните её на отдельном сервере по странице [Восстановление](Восстановление.md). Восстановление из копии проверено в сквозных тестах установки, но только ваша проверка покажет, что копии в вашем хранилище целы.

## Если не получается

| Что видно | Почему | Что сделать |
|---|---|---|
| `pg_dump не выполнен (postgres запущен?)` | контейнер базы остановлен | `sudo mfagatectl start`, затем повторите |
| `нет /opt/mfa-gate/deploy/.env — сначала ./mfagatectl install` | неверный путь к каталогу установки | проверьте путь в расписании |
| Копий `…-daily` нет | расписание не сработало | `journalctl -u mfa-gate-backup.service` или `/var/log/mfa-gate/backup.log` |
| `db.dump: FAILED` при проверке | файл повреждён при переносе | возьмите копию с сервера или предыдущую |
| Диск заполняется | копии `pre-*` и архивы `diag-*` не удаляются автоматически | удалите старые вручную |
