# Резервное копирование

Для восстановления MFA Gate нужны три вещи:

| Что | Где | Как сохранять |
|---|---|---|
| Копия базы | `deploy/backups/<время>-<метка>/` | `mfagatectl backup`, ежедневно по расписанию, переносить на другой носитель |
| Мастер-ключ | `deploy/data/secrets/master.key` | **один раз** сохранить вне сервера, отдельно от копий базы |
| Настройки | `deploy/.env`, `deploy/compose.override.yml`, `deploy/data/secrets/fcm.json` (если есть) | сохранить вне сервера после каждого изменения |

Мастер-ключом зашифрованы секреты TOTP, RADIUS-клиентов, каталогов LDAP и push-токены. **Без него копия базы бесполезна**, а с ним копия даёт доступ ко всем секретам. Поэтому ключ хранят отдельно от копий: менеджер паролей, сейф, другой носитель.

## Шаг 1. Сохраните мастер-ключ

```bash
sudo cat /opt/mfa-gate/deploy/data/secrets/master.key
```

**Ожидаемый результат:** одна строка base64 (44 символа). Сохраните её целиком в менеджере паролей.

**Как проверить сохранённую копию:** отпечаток должен совпасть.

```bash
sudo sha256sum /opt/mfa-gate/deploy/data/secrets/master.key | cut -c1-16
```

Тот же отпечаток записывается в манифест каждой копии (`master_key_sha256=`).

## Шаг 2. Копия вручную

```bash
sudo mfagatectl backup
```

**Ожидаемый результат:** путь к копии, например `/opt/mfa-gate/deploy/backups/20261118T210000Z-manual`.

Внутри три файла: `db.dump` (`pg_dump` в формате custom), `SHA256SUMS` и `manifest` (версия, ревизия схемы, время, отпечаток мастер-ключа). Мастер-ключа в копии нет — это сделано намеренно.

**Как проверить:**

```bash
cd /opt/mfa-gate/deploy/backups/20261118T210000Z-manual && sudo sha256sum -c SHA256SUMS && sudo cat manifest
```

**Ожидаемый результат:** `db.dump: OK` и строки `version=`, `schema=`, `created=`, `master_key_sha256=`.

Можно задать метку: `sudo mfagatectl backup before-ldap-change` → каталог `…-before-ldap-change`. Перед каждым `update` копия с меткой `pre-<версия>` создаётся автоматически.

## Шаг 3. Ежедневная копия по расписанию

Выберите один вариант.

### Вариант A. cron

```bash
sudo tee /etc/cron.d/mfa-gate-backup >/dev/null <<'EOF'
# Ежедневная копия MFA Gate в 02:30 и удаление ежедневных копий старше 14 дней
30 2 * * * root /opt/mfa-gate/deploy/mfagatectl backup daily >/dev/null 2>>/var/log/mfa-gate/backup.log
50 2 * * * root find /opt/mfa-gate/deploy/backups -maxdepth 1 -type d -name '*-daily' -mtime +14 -exec rm -rf {} +
EOF
```

**Как проверить:** запустите ту же команду вручную — `sudo /opt/mfa-gate/deploy/mfagatectl backup daily` — и убедитесь, что появился каталог `…-daily`. На следующий день: `ls -1t /opt/mfa-gate/deploy/backups | head`.

### Вариант B. systemd timer

```bash
sudo tee /etc/systemd/system/mfa-gate-backup.service >/dev/null <<'EOF'
[Unit]
Description=MFA Gate: ежедневная резервная копия
Requires=docker.service
After=docker.service

[Service]
Type=oneshot
ExecStart=/opt/mfa-gate/deploy/mfagatectl backup daily
ExecStartPost=/usr/bin/find /opt/mfa-gate/deploy/backups -maxdepth 1 -type d -name '*-daily' -mtime +14 -exec rm -rf {} +
EOF

sudo tee /etc/systemd/system/mfa-gate-backup.timer >/dev/null <<'EOF'
[Unit]
Description=MFA Gate: расписание резервной копии

[Timer]
OnCalendar=*-*-* 02:30:00
RandomizedDelaySec=10m
Persistent=true

[Install]
WantedBy=timers.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now mfa-gate-backup.timer
sudo systemctl start mfa-gate-backup.service
```

**Ожидаемый результат:** `systemctl list-timers mfa-gate-backup.timer` показывает время следующего запуска; после ручного `start` в `journalctl -u mfa-gate-backup.service` есть путь к новой копии `…-daily`, а `systemctl status mfa-gate-backup.service` — `status=0/SUCCESS`.

В обоих вариантах указан полный путь к `deploy/mfagatectl`, а не к `/usr/local/bin/mfagatectl`.

## Шаг 4. Перенос копий с сервера

Копии лежат на том же диске, что и база: при отказе диска пропадут обе. Переносите их на другой сервер или носитель, например ежедневно после копии:

```bash
sudo rsync -a --delete /opt/mfa-gate/deploy/backups/ backup@backup.example.org:/var/backups/mfa-gate/
```

Используйте ключ SSH без пароля для пользователя `root` и ограниченную учётную запись на принимающей стороне. Файлы копии доступны только root (права `go-rwx`) — сохраните это и на принимающей стороне.

Мастер-ключ на тот же носитель **не кладите**.

## Что ещё сохранить

- `deploy/.env` — после установки и после каждого изменения (содержит пароль базы).
- `deploy/compose.override.yml` и `deploy/data/secrets/fcm.json`, если вы настроили FCM.
- Конфигурацию reverse proxy (`/etc/nginx/sites-available/mfa-gate` или `/etc/caddy/Caddyfile`).
