# Диагностика

## Инструменты

| Команда | Что показывает |
|---|---|
| `sudo mfagatectl status` | состояние контейнеров (`healthy`/`unhealthy`), опубликованные порты, версия и образ |
| `sudo mfagatectl logs [сервис]` | последние 200 строк журнала: `api`, `radius`, `worker`, `migrate`, `postgres`. Слежение в реальном времени: `sudo mfagatectl logs radius -f` |
| `sudo mfagatectl diagnose` | проверки приложения + архив для поддержки `deploy/backups/diag-<время>.tar.gz` |
| `sudo mfagatectl radius-test <логин>` | тестовый вход по RADIUS изнутри сервера ([Настройка RADIUS](Настройка-RADIUS.md), шаг 5) |
| `/var/log/mfa-gate/install-*.log` | подробный журнал каждого запуска `install.sh` |
| Панель → «Диагностика» | те же проверки, что `diagnose` |
| Панель → «История входов», «Проблемы входа» | каждая попытка входа с причиной отказа; отказы, сгруппированные по пользователю и причине |
| Панель → «Журнал» | действия администраторов и события безопасности (`radius.bad_authenticator`, `device.bad_signature` …) |

### `diagnose`

```bash
sudo mfagatectl diagnose
```

**Ожидаемый результат:** блоки `== версия`, `== контейнеры`, `== проверки приложения` со строками `OK`/`WARN`/`FAIL`, `== готовность HTTP`, `== публичный адрес`, `== диск`, `== резервные копии`, в конце — `архив для поддержки: …/diag-….tar.gz`.

`WARN` — предупреждение (например, push не настроен, адрес не HTTPS), `FAIL` — ошибка с подсказкой после `→`. Архив содержит сводку, последние 300 строк журналов каждого сервиса и `.env` с замаскированными паролями и ключами. Если значение секрета встретится в архиве, архив не создаётся. Прикладывайте его к обращению за помощью.

## Установка

| Сообщение установщика | Причина и решение |
|---|---|
| `Запустите установку с правами администратора` | запускайте `sudo ./install.sh` |
| `ОС … не поддерживается установщиком` | нужна Ubuntu 22.04+ или Debian 12; иначе — ручная установка ([docs/install.md](https://github.com/calleograph/mfa-gate/blob/main/docs/install.md#ручная-установка)) |
| `мало памяти` / `мало места на диске` | нужно ≥ 1 ГБ ОЗУ и ≥ 5 ГБ свободно |
| `нет доступа к ghcr.io и github.com` | **нет Интернета**: проверьте `ping -c1 1.1.1.1` (маршрут), `getent hosts github.com` (DNS), прокси ([Требования к серверу](Требования-к-серверу.md), проверка 3) |
| `порт 8180/tcp занят` | **порт занят** (заданный вручную). Кто занял: `sudo ss -ltnp 'sport = :8180'`. Задайте другой: `sudo MFA_GATE_HTTP_PORT=8280 ./install.sh` |
| `порт 1812/udp (RADIUS) занят другой программой` | часто это FreeRADIUS: `sudo ss -lunp 'sport = :1812'`. Остановите его (`sudo systemctl disable --now freeradius`) или задайте другой порт: `sudo MFA_GATE_RADIUS_PORT=11812 ./install.sh` и укажите его на шлюзах |
| `служба Docker не запущена` | **Docker не стартует** — см. ниже |
| `контейнеры не запустились: …` | `sudo mfagatectl status`, `sudo mfagatectl logs migrate`, `sudo mfagatectl logs api`; последние строки журнала установки |
| `файл …/deploy/.env повреждён` | исправьте строку, указанную в журнале установки (значения с пробелами — в кавычках), или удалите `.env` и запустите установку заново (будет создан новый пароль базы — только для установки без данных) |

Последние строки журнала установки:

```bash
sudo ls -1t /var/log/mfa-gate/ | head -n1
sudo tail -n 50 /var/log/mfa-gate/$(sudo ls -1t /var/log/mfa-gate/ | head -n1)
```

### Docker не стартует

```bash
sudo systemctl status docker --no-pager
sudo journalctl -u docker --no-pager -n 50
```

Типичные причины:

- **Конфликт пакетов** (одновременно `docker.io` и `docker-ce`): `dpkg -l | grep -E 'docker(\.io|-ce)'` — оставьте один.
- **Ошибка в `/etc/docker/daemon.json`**: `sudo python3 -m json.tool /etc/docker/daemon.json` должен печатать JSON без ошибок.
- **Нет места** на `/var/lib/docker`: `df -h /var/lib/docker`.
- **Сервер в контейнере (LXC/OpenVZ) без вложенной виртуализации**: включите `nesting` для контейнера на гипервизоре или используйте виртуальную машину.

После исправления: `sudo systemctl restart docker && sudo docker info >/dev/null && echo ok`, затем `sudo ./install.sh`.

## Панель не открывается

Проверяйте по шагам, от сервера к браузеру.

1. Сервисы живы:

   ```bash
   sudo mfagatectl status
   ```

   `api` должен быть `healthy`. Если нет — `sudo mfagatectl logs api`.

2. Панель отвечает на самом сервере:

   ```bash
   sudo grep -E '^MFA_GATE_HTTP_(BIND|PORT)=' /opt/mfa-gate/deploy/.env
   curl -fsS http://127.0.0.1:8080/health/ready; echo
   ```

   **Ожидаемый результат:** `"status":"ok"`. Ответ `503` — нет связи с базой: `sudo mfagatectl logs postgres`.

3. Порт опубликован на нужном адресе: `sudo ss -ltnp 'sport = :8080'`. После настройки HTTPS там `127.0.0.1:8080` — это правильно, снаружи панель открывается только через `https://`.

4. Сеть до сервера: с компьютера администратора `curl -m 5 http://192.0.2.10:8080/health/live`. Таймаут — межсетевой экран между вами и сервером или правило в `DOCKER-USER` (`sudo iptables -L DOCKER-USER -n`). Правила `ufw` порт Docker не закрывают и не открывают.

5. Через HTTPS: `curl -v https://mfa.example.org/health/ready` — ошибки сертификата, `502 Bad Gateway` (прокси не достучался до `127.0.0.1:8080`: порт в `proxy_pass` не совпадает с `MFA_GATE_HTTP_PORT`).

6. Панель открывается по `/admin/`; по `/` — личный кабинет сотрудника. На внешнем адресе Device API (`MFA_GATE_DEVICE_URL`) панель и кабинет не открываются, ответ `404` — так и задумано.

7. Вход не держится (после пароля снова форма входа): панель открыта по `https://`, но прокси не передаёт `X-Forwarded-Proto`, или наоборот — `MFA_GATE_COOKIE_SECURE=true` при работе по HTTP. Верните `auto`.

## RADIUS не отвечает

Шлюз пишет «таймаут RADIUS», в «Истории входов» записи нет.

1. RADIUS слушает порт:

   ```bash
   sudo mfagatectl status | grep radius
   sudo ss -lunp 'sport = :1812'
   ```

   **Ожидаемый результат:** `radius` — `healthy`; порт 1812 занят процессом `docker-proxy` (или правилами Docker).

2. Пакеты доходят до сервера. На сервере MFA Gate:

   ```bash
   sudo apt-get install -y tcpdump
   sudo tcpdump -ni any udp port 1812
   ```

   Выполните вход на шлюзе. **Ожидаемый результат:** строки `198.51.100.1.xxxxx > 192.0.2.10.1812: RADIUS, Access-Request`. Если пакетов нет — **межсетевой экран**: проверьте внешний экран, облачные правила, цепочку `DOCKER-USER` (`sudo iptables -L DOCKER-USER -n -v`) и `nftables` (`sudo nft list ruleset | grep 1812`). `ufw` на опубликованные порты Docker не влияет: если `sudo ufw status` показывает `1812/udp DENY`, это не причина; но и `ufw allow 1812/udp` ничего не откроет.

3. Пакет принят MFA Gate:

   ```bash
   sudo mfagatectl logs radius | tail -n 20
   ```

   | Строка в журнале | Причина | Решение |
   |---|---|---|
   | `пакет от неизвестного клиента 203.0.113.7 отброшен` | адрес источника не совпадает с RADIUS-клиентом (часто из-за NAT) | укажите в RADIUS-клиенте адрес из этой строки |
   | `пакет от … отброшен: Message-Authenticator …` | **неверный общий секрет** или шлюз не отправляет Message-Authenticator | сверьте секрет («Сменить секрет» и введите новый на шлюзе); включите Message-Authenticator на шлюзе |
   | `NAS-Identifier '…' не совпал для клиента …` | на клиенте задан NAS-Identifier, шлюз отправляет другой | исправьте или очистите поле |
   | `RADIUS-клиент … пропущен: неверный адрес или секрет` | клиент в базе повреждён | откройте клиента в панели, сохраните заново |

   В «Журнале» неверный секрет виден как `radius.bad_authenticator`.

4. Ответ приходит, но шлюз считает его таймаутом: ответ на push ждёт до 45 секунд, а таймаут шлюза меньше. Поставьте на шлюзе ≥ 60 с ([Настройка RADIUS](Настройка-RADIUS.md), шаг 3).

5. Шлюз получает `Поддерживается только PAP` — переключите шлюз на PAP.

## Вход не проходит

Откройте «История входов» (или «Проблемы входа») и найдите причину отказа:

| Причина | Что делать |
|---|---|
| `local_password`, `ldap_password` | неверный пароль; после 8 ошибок подряд — блокировка на 15 минут |
| `unknown_user` | логин не найден: проверьте фильтр и Base DN каталога, включён ли каталог |
| `locked` | подождите 15 минут или «Снять блокировку» в карточке пользователя |
| `user_disabled` | учётная запись отключена в MFA Gate |
| `directory_unavailable` | каталог недоступен: «LDAP / AD» → «Диагностика» ([Подключение Active Directory](Подключение-Active-Directory.md)) |
| `directory_denied` | AD отклонил вход (заблокирован, пароль истёк, нет в разрешённых группах) — подкод в подробностях |
| `no_factor` | нет привязанного телефона и TOTP — [Регистрация Android-устройства](Регистрация-Android-устройства.md) |
| `push_expired` | сотрудник не ответил за 45 секунд: не открыл приложение (без FCM), нет сети на телефоне, push не доставлен |
| `push_denied` | сотрудник нажал «Отклонить». Если он не входил — его пароль известен постороннему: смените пароль |
| `invalid_otp` | неверный или повторный код TOTP; проверьте время на телефоне |
| `policy_deny`, `resource_disabled` | сработала запрещающая политика или ресурс выключен |

Полная таблица причин: [docs/admin-guide.md](https://github.com/calleograph/mfa-gate/blob/main/docs/admin-guide.md#история-входов).

## Телефон не получает запросы

1. На телефоне открыт экран «Запросы»? Без FCM запросы видны только при открытом приложении ([Настройка Push](Настройка-Push.md)).
2. Телефон достаёт до сервера: в браузере телефона откройте `<адрес сервера>/health/live`.
3. Устройство активно: карточка пользователя → «Телефоны» → статус «Активен», время «на связи».
4. Красная плашка «Нет связи с сервером» в приложении — сеть или адрес сервера изменился (после перехода на HTTPS телефон нужно привязать заново).

## Прочее

| Признак | Решение |
|---|---|
| `mfagatectl` пишет `нет /usr/local/bin/.env — сначала ./mfagatectl install` | в версии 0.2.0 команда по ссылке `/usr/local/bin/mfagatectl` может не находить свой каталог. Запускайте по полному пути: `sudo /opt/mfa-gate/deploy/mfagatectl status` |
| В журнале входов адрес прокси вместо адреса сотрудника | адрес прокси не в `MFA_GATE_TRUSTED_PROXIES` ([HTTPS через reverse proxy](HTTPS-через-reverse-proxy.md)) |
| `diagnose`: «Миграции — FAIL» | версия образа и схема базы не совпадают: `sudo mfagatectl logs migrate`, затем `sudo mfagatectl start` |
| `diagnose`: «Мастер-ключ — FAIL» | файл `deploy/data/secrets/master.key` удалён или повреждён: верните сохранённую копию и `sudo mfagatectl restart` |
| Кончается место | `sudo du -sh /opt/mfa-gate/deploy/{data,backups}`; удалите старые копии и архивы `diag-*`; `sudo docker image prune` |

Если проблема не решается — создайте Issue в [репозитории](https://github.com/calleograph/mfa-gate/issues) и приложите архив `diagnose` и журнал установки. Перед отправкой просмотрите их: адреса и логины вашей организации в них есть.
