# Диагностика

*Для кого: администратор MFA Gate, вторая линия поддержки.*

Статья описывает инструменты, которыми проверяют состояние MFA Gate: страницы панели и команды `mfagatectl` на сервере. Здесь сказано, что показывает каждый инструмент, как читать результат и что приложить к обращению. Разбор конкретных неисправностей — в статьях [Решение проблем](Решение-проблем.md).

## Какой инструмент выбрать

| Вопрос | Инструмент | Кому доступен |
|---|---|---|
| Почему не вошёл конкретный сотрудник? | **Панель → История входов** | Все роли панели |
| Кто чаще всего не может войти и почему? | **Панель → Проблемы входа** | Все роли панели |
| Все ли компоненты работают? | **Панель → Диагностика** или `sudo mfagatectl diagnose` | Панель — все роли панели; сервер — администратор сервера |
| Что менял администратор, были ли подозрительные события? | **Панель → Журнал** | Все роли панели |
| Отвечает ли каталог и почему не пускает сотрудника? | **Панель → LDAP / AD → Диагностика** | **Администратор**, **Главный администратор** |
| Доходит ли запрос шлюза и отвечает ли RADIUS? | `sudo mfagatectl logs radius`, `sudo mfagatectl radius-test` | Администратор сервера |
| Почему не запускается сервис? | `sudo mfagatectl status`, `sudo mfagatectl logs <сервис>` | Администратор сервера |

Роль **Оператор** видит историю, проблемы входа, журнал и диагностику, но не видит разделы **LDAP / AD** и **RADIUS-клиенты**. Подробно: [Роли администраторов](Роли-администраторов.md).

## Панель → Диагностика

Страница проверяет компоненты при каждом открытии. Кнопка **Проверить снова** повторяет проверку. Сверху — итог: «Все проверки пройдены.», «Есть предупреждения.» или «Есть ошибки.», число проверок по состояниям, версия и время проверки. Ниже — список: сначала ошибки, затем предупреждения. У проверки с проблемой есть строка с действием.

| Проверка | В порядке | Проблема и действие |
|---|---|---|
| **База данных** | «PostgreSQL 16…, ответ за N мс» | Если база недоступна, страница не откроется вовсе — проверьте на сервере |
| **Миграции** | «схема X, ожидается X» | Ошибка: схема не совпадает с версией программы. Подсказка панели: «Посмотрите журнал: mfagatectl logs migrate; миграции применяются при запуске (mfagatectl install или update <версия>)». Выполните `sudo mfagatectl logs migrate`, устраните причину и повторите `sudo mfagatectl install` или `sudo mfagatectl update <версия>` |
| **Мастер-ключ** | «Ключ шифрования загружен» | Ошибка «Ключ не задан или повреждён» → «Проверьте MFA_GATE_MASTER_KEY_FILE и права на файл» |
| **RADIUS-сервер** | «клиентов N, запросов N, отброшено N» | Ошибка «ни разу не отметился» или «последний сигнал N с назад» → «Проверьте контейнер: ./mfagatectl logs radius». Растущее **отброшено** — пакеты от неизвестных адресов, с неверным секретом или чужим NAS-Identifier |
| **Фоновые задачи и push** | «работает» | Ошибка → «Проверьте контейнер: ./mfagatectl logs worker». Без этого сервиса push не уходит |
| **Доставка push** | «провайдеры: fcm» | Предупреждение «провайдеры не настроены — запрос виден при открытом приложении или в foss с мгновенными уведомлениями» → «Задайте MFA_GATE_PUSH_FCM_CREDENTIALS_FILE». Хвост «устройств без push-канала: N» — телефоны без токена |
| **Адрес портала** | Адрес с `https://` | Предупреждение «… — не HTTPS» → «По HTTP — только изолированная сеть. Для эксплуатации настройте HTTPS через reverse proxy» |
| **Адрес для телефонов** | Внешний адрес с `https://` | Предупреждение «… — не HTTPS». Пометка «тот же, что у портала» напоминает: чтобы подтверждать VPN из дома, телефону нужен внешний адрес `MFA_GATE_DEVICE_URL` |
| **RADIUS-клиенты** | «активных: N» | Предупреждение «активных: 0» → «Добавьте VPN-шлюз в разделе «RADIUS-клиенты»» |
| **Каталог «имя»** | «все контроллеры доступны по TCP» | «недоступны: dc1.example.org (TimeoutError)». Все недоступны — ошибка, часть — предупреждение. Подсказка: «Подробная проверка: раздел LDAP → «Диагностика»» |
| **Каталог «имя»: шифрование** | Строки нет | Предупреждение «пароли идут без проверенного TLS» → «Включите LDAPS и проверку сертификата» |

Проверка каталога здесь — только TCP-соединение. Неверный пароль сервисной записи или ошибку сертификата она не увидит: для этого есть пошаговая диагностика в **LDAP / AD**, см. [Решение проблем каталога](Решение-проблем-каталога.md).

## История входов и проблемы входа

**Панель → История входов** — каждая проверка входа через RADIUS и REST API, а также подтверждения push при входе в панель и в личный кабинет. Фильтры: **Пользователь**, **Результат**, **Канал**, **Причина отказа**. В строке: логин и ресурс или шлюз, статус и текст причины, канал и способ («RADIUS, Push»), адрес сотрудника, время и «ответ за N мс».

**Панель → Проблемы входа** — отказы и истёкшие запросы, сгруппированные по пользователю и причине, за выбранный период: **Сутки**, **7 дней**, **30 дней** или **90 дней**. У каждой строки — подсказка и кнопка: «Найти пользователя», «К каталогам», «К политикам», «К диагностике», «К ресурсам». Логин ведёт в историю с фильтром по нему. Строки с пометкой «Возможна утечка пароля» — отклонённые на телефоне запросы — стоят первыми.

Значения причин: [Справочник: коды причин отказа](Справочник-коды-причин-отказа.md).

Если попытки нет в истории, запрос не дошёл до проверки. Для VPN это почти всегда сеть, адрес или секрет RADIUS-клиента: [Решение проблем входа в VPN](Решение-проблем-входа-в-VPN.md).

## Журнал

**Панель → Журнал** — действия администраторов и события безопасности. Фильтры: **Событие**, **Кто**, **Важность**, **Результат**; кнопка **Скачать CSV** выгружает записи с текущими фильтрами. Для разбора неисправностей полезны события:

| Событие | Что значит |
|---|---|
| «Неверный RADIUS-аутентификатор» (`radius.bad_authenticator`) | Пакет шлюза отброшен: неверный общий секрет или нет Message-Authenticator. Пишется не чаще раза в минуту на клиента |
| «Неверная подпись устройства» (`device.bad_signature`) | Телефон прислал решение с неверной подписью |
| «Устройство отвязано с телефона» (`device.unbound`) | Сотрудник сам отвязал сервер в приложении |
| «Отказ в самостоятельной настройке» (`portal.enroll_denied`) | Сотрудник не смог пройти первую настройку в кабинете: не та сеть, не та группа или фактор уже настраивался |
| «Вход по резервному коду» (`portal.backup_code_used`) | Сотрудник вошёл в кабинет резервным кодом — вероятно, без телефона |
| «Аварийный вход в панель» (`admin.emergency_access`) | Использован аварийный код администратора |
| «Конфликт учётной записи каталога» (`auth.identity_conflict`) | Доменная учётная запись совпала по логину с уже существующей записью; вход запрещён |

Полный список: [Справочник: журнал аудита](Справочник-журнал-аудита.md).

## Команды на сервере

Команды выполняет администратор сервера. После установки команда доступна как `mfagatectl` из любого каталога.

| Команда | Что показывает |
|---|---|
| `sudo mfagatectl status` | Состояние контейнеров (`healthy`, `unhealthy`), опубликованные порты, версия и образ |
| `sudo mfagatectl logs <сервис>` | Последние 200 строк журнала сервиса: `api`, `radius`, `worker`, `migrate`, `postgres`. Слежение: `sudo mfagatectl logs radius -f` |
| `sudo mfagatectl diagnose` | Сводка в терминал и архив для поддержки |
| `sudo mfagatectl radius-test ivanov` | Тестовый запрос RADIUS с самого сервера |
| `sudo mfagatectl check-update` | Есть ли новая версия |

Полный список команд: [Справочник: команды mfagatectl](Справочник-команды-mfagatectl.md).

### diagnose

```bash
sudo mfagatectl diagnose
```

**Что увидите:** блоки `== версия`, `== контейнеры`, `== проверки приложения`, `== готовность HTTP`, `== публичный адрес`, `== диск`, `== резервные копии`. В блоке проверок — те же строки, что на странице **Диагностика**, с метками `OK`, `WARN`, `FAIL` и действием после стрелки `→`. В конце: `==> архив для поддержки: …/backups/diag-<время>.tar.gz`.

Блок `== публичный адрес` проверяет, открывается ли `MFA_GATE_PUBLIC_URL` с самого сервера. Ответ «недоступен с этого хоста» не всегда означает сбой: внешний адрес может быть не виден изнутри сети.

Архив содержит сводку, последние 300 строк журнала каждого сервиса и `.env`, в котором значения паролей, секретов и ключей заменены на `***`. Если пароль базы или мастер-ключ всё же встретятся в файлах, архив не создаётся: `в диагностике найден секрет — архив не создан`. Файл доступен только root.

### radius-test

```bash
sudo mfagatectl radius-test ivanov
```

Команда отправляет запрос из контейнера `api` в RADIUS по внутренней сети Docker и спрашивает `shared secret:` и `пароль:`. Нужен отдельный RADIUS-клиент с адресом этой сети: порядок в [Настройке RADIUS](Настройка-RADIUS.md). Ответ — строка JSON: `result` (`accept`, `reject`, `challenge` или `timeout`), `authenticator_ok`, `message` — текст отказа, `seconds` — время ответа. Если у сотрудника есть телефон, подтвердите запрос на нём: команда ждёт до 60 с.

### Адреса проверки

| Адрес | Ответ |
|---|---|
| `http://127.0.0.1:8080/health/live` на сервере | `{"status":"ok"}` — API запущен |
| `http://127.0.0.1:8080/health/ready` на сервере | `{"status":"ok",…}` — API готов и видит базу; `503` с `"database":"unavailable"` — базы нет |
| `https://auth.example.org/health/live` с телефона | `{"status":"ok"}` — телефон достаёт до сервера |

Порт `8080` — значение по умолчанию. Свой порт: `sudo grep '^MFA_GATE_HTTP_PORT=' /opt/mfa-gate/deploy/.env`.

### Журнал установки

Каждый запуск `install.sh` пишет журнал `/var/log/mfa-gate/install-<время>.log`. Пароль администратора в него не попадает.

## Что приложить к обращению

Соберите сведения до перезапуска сервисов: перезапуск стирает следы причины.

1. Логин сотрудника, время попытки с часовым поясом, шлюз или ресурс.
2. Строку из **Истории входов**: статус, причину, канал, адрес.
3. Итог страницы **Диагностика** — снимок экрана или текст.
4. Архив `sudo mfagatectl diagnose` и, если сбой при установке, журнал установки.

Передавайте архив только по внутреннему каналу. Перед отправкой за пределы организации просмотрите его: адреса, логины и имена серверов вашей организации в нём есть.
