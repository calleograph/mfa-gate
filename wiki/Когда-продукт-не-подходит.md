# Когда продукт не подходит

*Для кого: тот, кто решает, внедрять ли MFA Gate.*

Эта страница поможет решить, стоит ли тратить время на установку. Ниже перечислены случаи, когда MFA Gate не подойдёт или подойдёт с оговорками. У каждого случая указано, что можно сделать.

## Скорее всего, не подойдёт

**Нужен облачный сервис без своего сервера.** MFA Gate работает только на сервере организации с Linux. Его нужно установить, обновлять, копировать и сопровождать, поэтому без администратора не обойтись: [Требования к серверу](Требования-к-серверу.md).

**VPN-шлюз не умеет передавать пароль способом PAP.** MFA Gate принимает от шлюза только PAP. Если шлюз проверяет вход только по MS-CHAPv2 или EAP, например пересылает запросы с сервера политик сети без PAP, подключить его не получится. Режим, в котором пароль проверяет сам шлюз, тоже не поможет: такой шлюз не присылает ни пустого пароля, ни кода: [Подключение VPN](Подключение-VPN.md).

**Шлюз ждёт ответа всего несколько секунд и этот срок нельзя увеличить.** Подтверждение на телефоне занимает время: человек достаёт телефон, читает запрос, прикладывает палец. По умолчанию MFA Gate держит запрос до 45 с, и таймаут шлюза должен быть больше, рекомендуется 60 с. Срок ответа на сервере можно сократить, но при таймауте шлюза около 10 с сотрудник почти никогда не успеет. Такому шлюзу подходят только коды, и то если он умеет показать поле для кода. Если не умеет, надёжного сценария нет.

**Нужен вход по аппаратным ключам или ключам доступа (WebAuthn).** Этого пока нет, есть только телефон и одноразовые коды: [Планы развития](Планы-развития.md).

**Сотрудникам нужны коды по SMS, звонку или почте.** Такого способа нет. Одноразовые коды показывает приложение-аутентификатор на телефоне.

**Сервис должен работать без перерыва при отказе сервера.** Одна установка — один сервер. Готовой схемы из нескольких серверов с общим состоянием нет. Если сервер MFA Gate недоступен, шлюз не получает ответа и вход в VPN не проходит. Защитой служат резервные копии и восстановление на новом сервере: [Сценарий: восстановление после сбоя](Сценарий-Восстановление-после-сбоя.md).

## Подойдёт с оговорками

**У сотрудников iPhone.** Приложения MFA Gate Authenticator для iPhone нет. На iPhone работают одноразовые коды в любом приложении-аутентификаторе: [Как подключить приложение с кодами](Как-подключить-приложение-с-кодами.md). Подтверждения одним нажатием у таких сотрудников не будет. Кроме того, VPN-шлюз должен уметь показать поле для кода, иначе сотрудник с кодами не войдёт.

**Телефоны без сервисов Google, в том числе Huawei.** Подойдёт сборка приложения `foss`: она держит собственное соединение с сервером и показывает запросы без Google. Чтобы система не обрывала это соединение, для приложения нужно отключить экономию заряда. Поведение на прошивках с агрессивной экономией энергии пока не проверялось: [Приложение MFA Gate Authenticator](Приложение-MFA-Gate-Authenticator.md).

**Нет Active Directory или другого LDAP-каталога.** Учётные записи можно завести в панели вручную, но для сотен сотрудников это неудобно: пароли, увольнения и группы придётся вести в двух местах.

**Нужно, чтобы шлюз получал от MFA Gate группы сотрудника или адресный пул.** MFA Gate отвечает только «пустить» или «не пускать», без дополнительных атрибутов. Назначать доступ по группам придётся на самом шлюзе. Передача групп запланирована: [Планы развития](Планы-развития.md).

**Нужен учёт VPN-сессий.** RADIUS Accounting MFA Gate пока не принимает: на шлюзе его нужно выключить или направить в другую систему.

**Пароль и код нужно вводить в одной строке.** По RADIUS такой режим не реализован. Вместо него подходят отдельное поле для кода, которое показывает шлюз, или режим, в котором шлюз сам проверяет пароль: [Шлюзы с собственной проверкой пароля](Шлюзы-с-собственной-проверкой-пароля.md).

**Требуется подтверждение вводом числа с экрана.** Сейчас запрос подтверждается нажатием с отпечатком или PIN. Сотрудник видит адрес и время попытки, а повторные пакеты шлюза не создают лишних запросов. Но злоумышленник, который знает пароль, может присылать запросы снова и снова в надежде на случайное нажатие. Подтверждение вводом числа запланировано: [Безопасность и модель угроз](Безопасность-и-модель-угроз.md).

**Сервер и телефоны сотрудников не могут связаться через интернет.** Чтобы подтвердить вход из дома до подключения VPN, телефону нужен доступ к серверу по внешнему адресу, например `https://auth.example.org`. Если внешний адрес опубликовать нельзя, подтверждение на телефоне будет работать только в офисной сети. Коды работают без связи: [Сетевая схема и публикация](Сетевая-схема-и-публикация.md).

**Конкретная модель шлюза ещё не проверялась.** Протокол RADIUS покрыт сквозными тестами, профили шлюзов составлены по документации производителей. Проверьте вход на своём шлюзе до массового подключения сотрудников: [Что проверено](Что-проверено.md).

## Что вне задачи MFA Gate

- MFA Gate не строит VPN-туннель и не шифрует трафик: это работа шлюза.
- MFA Gate не меняет доменный пароль. Пароль меняется в домене обычным способом организации.
- MFA Gate не защищает вход в Windows на рабочем компьютере. Он защищает VPN и приложения, которые спрашивают его по RADIUS или REST API.
