# Справочник: команды mfagatectl

*Для кого: администратор сервера, техническая поддержка.*

`mfagatectl` — единая команда управления экземпляром MFA Gate: установка, запуск, обновление, откат, резервные копии, диагностика и аварийный доступ. Здесь перечислены все её команды, а также служебные команды приложения, которые выполняются внутри контейнера.

## Как вызывать

Установщик `install.sh` создаёт ссылку `/usr/local/bin/mfagatectl` на файл `deploy/mfagatectl`, поэтому команда доступна из любого каталога:

```bash
sudo mfagatectl status
```

Команда читает настройки из `deploy/.env` (другой файл — переменная `MFA_GATE_ENV_FILE`) и подключает `deploy/compose.override.yml`, если он есть. Ей нужен Docker с плагином `docker compose` v2 и права на него, поэтому запускайте её через `sudo`. При ошибке команда печатает строку `FAIL …` с причиной и завершается с ненулевым кодом.

## Все команды

| Команда | Что делает |
| --- | --- |
| `install` | Первая или повторная установка; повторный запуск безопасен. Если `.env` нет, создаёт его из шаблона с паролем базы и останавливается, чтобы вы проверили адрес и порты (кроме случая, когда адрес передан в `MFA_GATE_PUBLIC_URL`). Затем создаёт каталоги данных, генерирует мастер-ключ (только если его нет), проверяет, что порты HTTP и RADIUS свободны, загружает или собирает образ, запускает службы и ждёт их готовности до 3 минут |
| `start` | Запускает все службы и ждёт готовности до 2 минут. После правки `.env` или `compose.override.yml` пересоздаёт контейнеры с новыми значениями |
| `stop` | Останавливает все службы, контейнеры и данные остаются |
| `restart [служба]` | Перезапускает все службы или одну: `api`, `radius`, `worker`, `postgres`. Новые значения из `.env` не применяет — для этого `start` |
| `status` | Таблица служб с состоянием и портами, установленная версия и образ |
| `logs [служба] [-f]` | Последние 200 строк журнала всех служб или одной (`api`, `radius`, `worker`, `migrate`, `postgres`). С `-f` журнал продолжает выводиться: `mfagatectl logs api -f` |
| `update <версия>` | Обновление до версии вида `0.3.1`: резервная копия с меткой `pre-<версия>` → смена версии в `.env` → загрузка образа → миграции → ожидание готовности до 3 минут. Если образ недоступен, версия возвращается и система не меняется. Если новая версия не запустилась, выполняется `rollback` |
| `rollback` | Возврат к версии и базе, которые были до последнего `update`. Сведения берутся из `backups/last-update`. База восстанавливается из копии целиком: миграции вперёд не отменяются, поэтому изменения после обновления теряются |
| `check-update` | Спрашивает у GitHub последнюю версию (`MFA_GATE_REPO`) и сравнивает с установленной. Ничего не меняет |
| `backup [метка]` | Резервная копия базы в каталог `backups/<время UTC>-<метка>`; метка по умолчанию `manual`. В каталоге — `db.dump`, `SHA256SUMS` и `manifest` (версия, ревизия схемы, время, первые 16 символов SHA-256 мастер-ключа). Печатает путь к копии. **Мастер-ключ в копию не входит** |
| `restore <каталог>` | Восстановление базы из копии. Проверяет контрольную сумму и отпечаток мастер-ключа и откажет, если копия сделана с другим ключом. Останавливает `api`, `radius`, `worker`, восстанавливает базу во временную, подменяет рабочую и запускает службы. Прежняя база остаётся под именем `mfa_gate_prev` до следующего восстановления |
| `diagnose` | Сводка в терминал (версии, контейнеры, проверки приложения, готовность HTTP, доступность публичного адреса, диск, последние копии) и архив `backups/diag-<время>.tar.gz` для поддержки: сводка, по 300 строк журнала каждой службы, `.env` с замаскированными паролями, секретами и ключами. Если в архиве найдётся пароль базы или мастер-ключ, архив не создаётся |
| `admin <логин>` | Создаёт локального главного администратора или восстанавливает существующего локального: новый пароль, снятие блокировки, роль «Главный администратор». Пароль печатается один раз. Для доменной учётной записи откажет: роль ей назначают в панели, пароль меняют в каталоге |
| `admin-init` | Создаёт главного администратора `admin` с временным паролем, который нужно сменить при первом входе. Ничего не делает, если активный главный администратор уже есть. Эту команду вызывает `install.sh` |
| `emergency <логин>` | Одноразовый аварийный код для входа администратора в панель вместо второго фактора. Действует 15 минут и один раз. Выпуск и использование пишутся в журнал аудита с важностью «Критичное». Работает для любой роли администратора |
| `radius-test <логин>` | Отправляет тестовый Access-Request на RADIUS этого же экземпляра. Спрашивает общий секрет и пароль, печатает результат (`accept`, `reject`, `challenge` или `timeout`), сообщение и время ответа |
| `uninstall` | Удаляет контейнеры, данные остаются; повторный `install` вернёт систему |
| `uninstall --purge` | Удаляет контейнеры, базу, мастер-ключ, резервные копии и `.env`. Просит ввести `DELETE`. Восстановить после этого нельзя |
| `help` | Краткая справка. Неизвестная команда выводит её же и завершается с кодом 2 |

## Особенности, которые стоит знать

- **Мастер-ключ.** Без файла `data/secrets/master.key` резервные копии бесполезны: секреты TOTP, RADIUS и каталогов не расшифруются. Храните копию ключа отдельно от копий базы ([Резервное копирование](Резервное-копирование.md)).
- **Образ.** Если `MFA_GATE_IMAGE` указывает на реестр, образ загружается оттуда. Если загрузить не удалось, `mfagatectl` собирает его из исходников, но только когда версия исходников в каталоге совпадает с нужной; иначе подсказывает, как переключить исходники на тег. `MFA_GATE_NO_BUILD=1` запрещает сборку.
- **Порядок запуска.** Служба `migrate` применяет миграции базы и завершается, только после этого стартуют `api`, `radius` и `worker`.
- **Тестовый вход по RADIUS.** `radius-test` отправляет пакет изнутри контейнера `api` в контейнер `radius`. Чтобы RADIUS его принял, нужен RADIUS-клиент на внутреннюю сеть контейнеров `<имя экземпляра>_backend`, иначе пакет будет молча отброшен. Как это настроить — [Настройка RADIUS](Настройка-RADIUS.md), шаг 5. Работу самого шлюза надёжнее проверить входом через шлюз ([Диагностика](Диагностика.md)).

## Служебные команды приложения

Внутри контейнера доступна команда `python -m mfa_gate`. Часть её подкоманд вызывает `mfagatectl`, остальные нужны редко. Запускайте их из каталога `deploy`: `docker compose` сам прочитает `.env` и `compose.override.yml`.

```bash
cd <каталог установки>/deploy
sudo docker compose exec api python -m mfa_gate create-api-client "Портал заявок" --scopes auth:write
```

| Подкоманда | Параметры | Что делает |
| --- | --- | --- |
| `create-admin <логин>` | `--name <имя>`; `--password-stdin` — прочитать пароль из стандартного ввода, без флага пароль генерируется; `--temporary` — сменить при первом входе; `--if-no-admin` — пропустить, если главный администратор есть | Создаёт или восстанавливает локального главного администратора. Пароль не короче 12 символов. Основа команд `admin` и `admin-init` |
| `emergency-access <логин>` | `--minutes 1..60`, по умолчанию 15 | Аварийный код. `mfagatectl emergency` вызывает её со сроком 15 минут; другой срок задаётся только так |
| `create-api-client <название>` | `--scopes <права …>` или `--scopes all`; по умолчанию `auth:write` | Выпускает ключ REST API и печатает `key_id:secret` один раз. Право `all` означает все права ключей, кроме управления администраторами |
| `radius-test` | `--host` (по умолчанию `127.0.0.1`), `--port` (1812), `--secret`, `--user` (обязательно), `--password`, `--calling-station`, `--timeout` (60 с) | Тестовый Access-Request. Код выхода: 0 — accept, 1 — другой ответ, 2 — нет ответа |
| `diagnose` | — | Проверки приложения: строки `OK`, `WARN`, `FAIL` с подсказкой. Код выхода 1, если есть ошибка |
| `gen-master-key` | — | Печатает новый мастер-ключ. Нужна только для разработки: рабочий ключ создаёт `mfagatectl install` |
| `migrate`, `api`, `radius`, `worker` | — | Роли контейнеров. Вручную не запускаются |

## Установщик install.sh

`sudo ./install.sh` из корня репозитория ставит всё на один сервер с Ubuntu или Debian (x86_64, aarch64): проверяет память (не меньше 1 ГБ), диск (не меньше 5 ГБ) и доступ к GitHub, ставит Docker, создаёт `.env`, вызывает `mfagatectl install` и `admin-init`, проверяет HTTP, панель и RADIUS и создаёт ссылку `/usr/local/bin/mfagatectl`. Журнал каждого запуска — `/var/log/mfa-gate/install-<дата>-<время>.log`, пароль администратора в него не попадает. Каталог установки установщик передаёт root, поэтому исходники дальше обновляются через `sudo git -C <каталог> pull`. Подробно — [Быстрая установка All-in-One](Быстрая-установка-All-in-One.md).
