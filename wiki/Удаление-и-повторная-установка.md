# Удаление и повторная установка

*Для кого: администратор сервера MFA Gate.*

Страница описывает три действия: убрать контейнеры с сохранением данных, вернуть систему повторной установкой и удалить MFA Gate полностью, вместе с базой и ключами. Первое и второе обратимы, третье — нет.

## Зачем это нужно

Иногда контейнеры нужно убрать, не теряя данных: перед обслуживанием сервера, при переносе Docker на другой диск или чтобы пересоздать контейнеры с чистого листа. А при выводе системы из эксплуатации или после пробной установки данные нужно удалить так, чтобы на сервере не осталось секретов.

## Когда пригодится

- Пробная установка больше не нужна.
- Нужно пересоздать контейнеры и проверить, что данные переживают это.
- MFA Gate выводится из эксплуатации или переезжает на другой сервер.

## Что потребуется

- Права `sudo` на сервере.
- Перед полным удалением — свежая копия и мастер-ключ вне сервера, если данные могут понадобиться: [Резервное копирование](Резервное-копирование.md).
- Перед удалением рабочей системы — план для сотрудников: после удаления вход в VPN со вторым фактором перестанет работать.

## Где найти

Команды на сервере: `sudo mfagatectl uninstall`, `sudo mfagatectl uninstall --purge`, `sudo ./install.sh` в каталоге установки.

## Как это сделать

### Удалить контейнеры, сохранив данные

```bash
sudo mfagatectl uninstall
```

**Что увидите:**

```text
==> контейнеры удалены; данные сохранены в /opt/mfa-gate/deploy/data и /opt/mfa-gate/deploy/backups — повторный ./mfagatectl install вернёт систему
```

Остаются база, мастер-ключ, резервные копии, `deploy/.env`, образы Docker и журналы установки. Входы через VPN с этого момента не проходят.

Проверьте:

```bash
sudo docker ps --filter label=com.docker.compose.project=mfa-gate
sudo ls /opt/mfa-gate/deploy/data
```

**Что увидите:** пустой список контейнеров; каталоги `postgres` и `secrets` на месте.

### Вернуть систему

```bash
cd /opt/mfa-gate && sudo ./install.sh
```

Повторный запуск сохраняет `.env`, мастер-ключ и данные: пользователи, телефоны и настройки возвращаются как были. Пароль администратора не меняется, установщик пишет `главный администратор уже существует (пароль не менялся)`.

**Что увидите:** `Готово`, `sudo mfagatectl status` показывает все сервисы `healthy`, вход в панель — с прежним паролем.

Тот же способ чинит установку после ручных изменений: возвращает контейнеры к состоянию конфигурации и пересоздаёт ссылку `/usr/local/bin/mfagatectl`. Вместо установщика можно выполнить `sudo /opt/mfa-gate/deploy/mfagatectl install`. Эта команда тоже запускает контейнеры с сохранённой конфигурацией, но не проверяет сервер и не создаёт ни администратора, ни ссылку.

### Удалить вместе с данными

**Действие необратимо.** Удаляются база, мастер-ключ, все резервные копии в `deploy/backups` и `deploy/.env`. Если данные могут понадобиться, сначала сделайте копию и перенесите её вместе с мастер-ключом с сервера.

```bash
sudo mfagatectl uninstall --purge
```

Команда спросит:

```text
Удалить ВСЕ данные MFA Gate (/opt/mfa-gate/deploy/data, /opt/mfa-gate/deploy/backups) без возможности восстановления? Введите DELETE:
```

Введите `DELETE` заглавными буквами. Любой другой ответ отменяет удаление: `FAIL отменено`.

**Что увидите:** `MFA Gate удалён вместе с данными`.

Файлы базы принадлежат пользователю контейнера PostgreSQL, поэтому команда удаляет их через временный контейнер и затем проверяет, что каталоги пусты.

### Что `--purge` не удаляет

Удалите вручную, если нужно:

```bash
sudo rm -f /usr/local/bin/mfagatectl                     # ссылка на команду управления
sudo docker image ls | grep -E 'mfa-gate|postgres'        # образы: удалить через sudo docker image rm <ID>
sudo rm -rf /var/log/mfa-gate                             # журналы установщика и копий
sudo rm -f /etc/cron.d/mfa-gate-backup                    # расписание копий, если настраивали cron
sudo systemctl disable --now mfa-gate-backup.timer 2>/dev/null; sudo rm -f /etc/systemd/system/mfa-gate-backup.*
sudo rm -f /opt/mfa-gate/deploy/compose.override.yml     # если настраивали push через FCM
sudo rm -rf /opt/mfa-gate                                 # сам каталог установки
```

Удалите также:

- правила межсетевого экрана для портов RADIUS и HTTP, если добавляли их в цепочку `DOCKER-USER`;
- конфигурацию reverse proxy и сертификаты;
- RADIUS-сервер MFA Gate в настройках VPN-шлюзов;
- записи DNS, если они больше не нужны.

Docker остаётся на сервере, даже если его ставил установщик.

**Как проверить:** `sudo docker ps -a | grep mfa-gate` — пусто; `ls /opt/mfa-gate` — `No such file or directory`.

### Установить заново с нуля

После `--purge` в каталоге `deploy` не остаётся ни данных, ни `.env`, и `sudo ./install.sh` выполняет установку с самого начала: новый мастер-ключ, новый пароль базы, новый администратор `admin` с временным паролем.

## Что получится

- После `uninstall` — контейнеров нет, данные целы, `install.sh` возвращает систему.
- После `uninstall --purge` — на сервере нет базы, ключа, копий и конфигурации MFA Gate.
- После установки с нуля — чистая система, как после первой установки.

Удаление с данными и последующая установка с нуля проверены на чистом Ubuntu Server.

Телефоны, привязанные к прежней установке, после установки с нуля нужно привязать заново, а секреты новых RADIUS-клиентов — указать на шлюзах. Старые записи в приложении на телефонах сотрудники могут удалить.

## Если не получается

| Что видно | Почему | Что сделать |
|---|---|---|
| `FAIL отменено` | введено не `DELETE` | повторите и введите `DELETE` заглавными |
| `данные удалить не удалось — проверьте вручную …` | временный контейнер не запустился, например нет образа `postgres:16-alpine` | проверьте Docker и удалите каталоги вручную |
| `в … или … остались файлы` | часть файлов не удалилась | посмотрите `sudo ls -la` в указанных каталогах и удалите остаток |
| `нет /opt/mfa-gate/deploy/.env — сначала ./mfagatectl install` | конфигурация уже удалена | контейнеров MFA Gate нет; при необходимости удалите остатки вручную |
| Повторная установка создала нового `admin` | данные были удалены `--purge` | это ожидаемо; восстановить данные можно только из копии |
