# Справочник: порты и сеть

*Для кого: сетевой администратор и администратор сервера.*

Все порты, адреса и сетевые параметры MFA Gate в одном месте. Справочник отвечает на вопросы «что открыть», «откуда», «чем это настраивается». Объяснение схемы и порядок подготовки сети: [Сетевая схема и публикация](Сетевая-схема-и-публикация.md).

## Точный перечень для вашей установки

Таблицы ниже описывают стандартную установку. Перечень с вашими адресами, портами, RADIUS-клиентами, каталогами и способами доставки push показывает панель: **Панель → Интеграции → Адреса и публикация**. Он строится по настройкам сервера: [Адреса и публикация](Адреса-и-публикация.md).

## Входящие соединения

| Сервис | Протокол | Порт | Направление | Кто обращается | Публиковать наружу | Переменная |
|---|---|---|---|---|---|---|
| Личный кабинет `/` | HTTPS | TCP 443 на прокси | входящее | сотрудники из офиса и VPN | нет | `MFA_GATE_PUBLIC_URL` |
| Панель `/admin/` | HTTPS | TCP 443 на прокси | входящее | администраторы | нет; сузьте до сети администраторов | `MFA_GATE_PUBLIC_URL` |
| REST API `/api/v1/` | HTTPS | TCP 443 на прокси | входящее | серверы приложений, скрипт OpenVPN | нет | `MFA_GATE_PUBLIC_URL` |
| Описание API `/api/docs`, `/api/openapi.json` | HTTPS | TCP 443 на прокси | входящее | администраторы, разработчики | нет | `MFA_GATE_PUBLIC_URL`, `MFA_GATE_DOCS_ENABLED` |
| Device API `/api/device/v1/` | HTTPS | TCP 443 на прокси | входящее, в том числе из интернета | телефоны сотрудников | **да**, только этот префикс на внешнем имени | `MFA_GATE_DEVICE_URL` |
| Проверки `/health/live`, `/health/ready` | HTTPS или HTTP | TCP 443 или 8080 | входящее | мониторинг | нет | — |
| Веб-сервис `api` | HTTP | TCP 8080 | входящее | только reverse proxy | нет | `MFA_GATE_HTTP_BIND`, `MFA_GATE_HTTP_PORT` |
| RADIUS | RADIUS (RFC 2865) | UDP 1812 | входящее | только VPN-шлюзы | нет; только адреса шлюзов, между площадками через IPsec или WireGuard | `MFA_GATE_RADIUS_BIND`, `MFA_GATE_RADIUS_PORT` |
| Выпуск сертификата и перенаправление | HTTP | TCP 80 | входящее | Let's Encrypt, браузеры | только при проверке HTTP-01 | — |
| SSH | SSH | TCP 22 | входящее | администраторы сервера | нет | — |

## Исходящие соединения

| Куда | Протокол | Порт | Когда нужно | Чем включается |
|---|---|---|---|---|
| контроллеры домена | LDAPS (или LDAP со StartTLS) | TCP 636 (или 389) | при подключённом каталоге | **Панель → Интеграции → LDAP / AD** |
| `fcm.googleapis.com`, `oauth2.googleapis.com` | HTTPS | TCP 443 | при доставке через FCM | `MFA_GATE_PUSH_FCM_CREDENTIALS_FILE` |
| `push-api.cloud.huawei.com`, `oauth-login.cloud.huawei.com` | HTTPS | TCP 443 | Huawei Push Kit, экспериментально | `MFA_GATE_PUSH_HMS_APP_ID`, `MFA_GATE_PUSH_HMS_CLIENT_SECRET` |
| распределитель UnifiedPush | HTTPS | TCP 443 | экспериментально, в приложении пока не поддерживается | `MFA_GATE_PUSH_UNIFIEDPUSH_HOSTS` |
| `ghcr.io`, `github.com`, `api.github.com` | HTTPS | TCP 443 | установка, проверка версии, обновление | `MFA_GATE_IMAGE`, `MFA_GATE_REPO` |
| серверы NTP | NTP | UDP 123 | всегда: от времени зависят коды TOTP и сроки запросов | настройка системы |
| серверы DNS | DNS | UDP и TCP 53 | всегда | настройка системы |

## Соединения телефона

| Откуда | Куда | Протокол, порт | Зачем |
|---|---|---|---|
| телефон, любая сеть | `auth.example.org` | HTTPS, TCP 443 | привязка, получение запросов, решения; long-poll до 30 с |
| телефон со сборкой `gms` | сервисы Google | HTTPS, TCP 443 | приём сигналов FCM |

Входящих соединений к телефону нет: телефон всегда сам обращается к серверу.

## Не реализовано

| Что | Порт | Что сделать на шлюзе |
|---|---|---|
| RADIUS Accounting (RFC 2866) | UDP 1813 | выключить или направить в другую систему |
| RadSec, RADIUS поверх TLS (RFC 6614) | TCP 2083 | не использовать; шифровать RADIUS через IPsec или WireGuard |
| CHAP, MS-CHAPv2, EAP | — | включить PAP; на CHAP MFA Gate отвечает отказом «Поддерживается только PAP» |

Подробнее о планах: [Планы развития](Планы-развития.md).

## Только внутри сервера

| Что | Порт | Кто |
|---|---|---|
| PostgreSQL | TCP 5432 в сети Docker `backend` | `api`, `radius`, `worker`, `migrate`. На хост не публикуется |
| `api` внутри контейнера | TCP 8080 | опубликован на хосте как `MFA_GATE_HTTP_BIND:MFA_GATE_HTTP_PORT` |
| `radius` внутри контейнера | UDP 1812 | опубликован на хосте как `MFA_GATE_RADIUS_BIND:MFA_GATE_RADIUS_PORT` |

## Переменные сети

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `MFA_GATE_PUBLIC_URL` | адрес вида `http://192.0.2.10:8080`, подставляет установщик | внутренний адрес кабинета и панели |
| `MFA_GATE_DEVICE_URL` | пусто, то есть как `MFA_GATE_PUBLIC_URL` | внешний адрес телефонов; попадает в QR привязки |
| `MFA_GATE_HTTP_BIND` | `0.0.0.0` | адрес хоста для веб-сервиса. За прокси на том же сервере — `127.0.0.1` |
| `MFA_GATE_HTTP_PORT` | `8080` | порт хоста для веб-сервиса |
| `MFA_GATE_RADIUS_BIND` | `0.0.0.0` | адрес хоста для RADIUS |
| `MFA_GATE_RADIUS_PORT` | `1812` | порт хоста для RADIUS |
| `MFA_GATE_TRUSTED_PROXIES` | `auto` | от кого принимать `X-Forwarded-For` и `X-Forwarded-Proto`. `auto` — `127.0.0.1`, `::1` и шлюз сети Docker |
| `MFA_GATE_COOKIE_SECURE` | `auto` | флаг `Secure` у cookie: по схеме запроса, с учётом прокси |
| `MFA_GATE_PUSH_TIMEOUT` | `45` | сколько секунд ждать ответа на телефоне |
| `MFA_GATE_RADIUS_REQUIRE_MESSAGE_AUTHENTICATOR` | `true` | отбрасывать пакеты без Message-Authenticator |
| `MFA_GATE_PORTAL_ENROLL_NETWORKS` | частные сети RFC 1918 и `fc00::/7` | откуда разрешена первичная настройка в кабинете |

Переменные задаются в `/opt/mfa-gate/deploy/.env` и применяются командой `sudo mfagatectl start`. Полный перечень: [Справочник: конфигурация](Справочник-конфигурация.md).

## Сетевые параметры протоколов

| Параметр | Значение | Где задан |
|---|---|---|
| Ожидание решения по push | 45 с | `MFA_GATE_PUSH_TIMEOUT` |
| Время на ввод кода после Access-Challenge | 120 с, передаётся шлюзу в Session-Timeout | `MFA_GATE_OTP_CHALLENGE_TIMEOUT` |
| Окно распознавания повторов RADIUS | 90 с | код `radius/server.py` |
| Применение изменений RADIUS-клиентов | не дольше 15 с, без перезапуска | код `radius/server.py` |
| Long-poll телефона | до 30 с, приложение просит 25 с | Device API |
| Ожидание решения в REST API | до 30 с на один запрос `?wait=` | REST API |
| Лимит входа в кабинет и панель | 20 попыток в минуту с адреса | код `api/deps.py` |
| Лимит привязки телефонов | 30 попыток в минуту с адреса | код `api/deps.py` |
| Блокировка учётной записи | 8 ошибок подряд, на 15 минут | `MFA_GATE_LOCKOUT_THRESHOLD`, `MFA_GATE_LOCKOUT_MINUTES` |
| Таймаут RADIUS на шлюзе | не меньше 60 с | настройка шлюза |
| Таймаут чтения прокси | не меньше 40 с, в примерах 75 с | настройка прокси |

Стандартный `deploy/compose.yml` передаёт в контейнеры не все переменные. `MFA_GATE_OTP_CHALLENGE_TIMEOUT`, `MFA_GATE_LOCKOUT_THRESHOLD`, `MFA_GATE_LOCKOUT_MINUTES`, `MFA_GATE_DOCS_ENABLED` и переменные Huawei Push Kit в нём не перечислены: строка в `.env` на них не подействует. Чтобы изменить такое значение, добавьте его в раздел `environment` нужных сервисов в `compose.override.yml`.

## Команды проверки

```bash
# что слушает сервер
sudo ss -ltnup | grep -E ':(8080|1812|443)\b'

# готовность веб-сервиса изнутри сервера
curl -fsS http://127.0.0.1:8080/health/ready

# внешнее имя отдаёт только Device API (запускать из интернета)
curl -s -o /dev/null -w '%{http_code}\n' https://auth.example.org/admin/      # 404
curl -s https://auth.example.org/api/device/v1/requests                       # JSON unauthenticated

# правила для опубликованных портов Docker
sudo iptables -S DOCKER-USER

# журнал RADIUS: неизвестные клиенты, неверный Message-Authenticator
cd /opt/mfa-gate/deploy && sudo docker compose logs --since 10m radius
```

Если `docker compose` сообщает о незаданных переменных, запускайте его из каталога `deploy/`: он читает `.env` из текущего каталога. Команды управления сервисом: [Справочник: команды mfagatectl](Справочник-команды-mfagatectl.md).
