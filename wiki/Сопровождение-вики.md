# Сопровождение вики

*Для кого: тот, кто выпускает версии MFA Gate и ведёт документацию.*

Здесь описано, где лежат исходники вики, как их проверить и опубликовать и что сверять при каждом выпуске, чтобы вики не отставала от продукта. Как вики устроена для читателя — [Как читать эту вики](Как-читать-эту-вики.md).

## Где лежат исходники

| Что | Где |
| --- | --- |
| Страницы вики | Каталог `wiki/` основного репозитория, один файл `Слова-через-дефис.md` на страницу. Изменения документации проходят ту же проверку, что и код, и привязаны к выпускам |
| Главная, боковое меню, подвал | `wiki/Home.md`, `wiki/_Sidebar.md`, `wiki/_Footer.md` |
| Изображения | `wiki/images/`. Только снимки настоящего интерфейса, с точной альтернативной подписью |
| Служебные материалы | `wiki/_meta/`: редакционный стандарт и план вики. В вики GitHub этот каталог не публикуется |

Перед правкой прочитайте `wiki/_meta/Редакционный-стандарт.md`: в нём правила языка, структуры статей, примеров данных и ссылок. Список страниц и их назначение — `wiki/_meta/План-вики.md`: новая страница сначала появляется в плане.

## Правила, которые чаще всего нарушают

- Ссылки на страницы вики — относительные и **с расширением** `.md`: ссылка на страницу «Политики доступа» ведёт на файл `Политики-доступа.md`. Так они работают и в репозитории, и после публикации: скрипт публикации убирает расширение. Ссылки в двойных квадратных скобках не используются.
- Ссылки на файлы репозитория — полным адресом: `https://github.com/calleograph/mfa-gate/blob/main/docs/network.md`.
- У каждой страницы есть строка `*Для кого: …*` под заголовком и блок `## Что дальше` в конце.
- Примеры данных — только `example.org`, `192.0.2.x`, `198.51.100.x`, `203.0.113.x`, учётная запись `ivanov`. Никаких настоящих доменов, адресов, имён серверов и ключей.
- Продукты, которые изучались при разработке, и производители, на которых ориентировались, не называются; совместимость описывается по стандартам и функциям.
- Никаких служебных пометок для читателя: версий в шапке, уровней проверки и других слов, которые стандарт запрещает. Ограничение объясняется словами рядом с функцией.
- Подписи кнопок и полей — дословно, как в коде интерфейса (`server/web/assets/js/`).

## Проверить исходники

```bash
python3 scripts/check_wiki.py            # ссылки, обязательные блоки, меню, служебные пометки
python3 scripts/check_private_data.py    # частные данные во всём репозитории, включая wiki/; названия сторонних продуктов — по локальному списку, если он есть
```

`check_wiki.py` проверяет каждую страницу `wiki/*.md`:

- ссылки на страницы вики ведут на существующие файлы, а ссылки на изображения — на файлы в `wiki/images/`;
- есть строка «*Для кого: …*» и блок `## Что дальше` (кроме `Home.md`, `_Sidebar.md`, `_Footer.md`);
- страница есть в `_Sidebar.md`;
- нет ссылок в двойных квадратных скобках и служебных пометок, которые запрещает редакционный стандарт (их список — в самом скрипте, выражение `FORBIDDEN`).

При ошибках скрипт перечисляет их и завершается с кодом 1, без ошибок печатает «вики: N страниц, ошибок нет». Обе проверки должны проходить без замечаний до публикации. Орфографию проверьте редактором или `aspell --lang=ru`.

## Опубликовать

Вики GitHub — отдельный git-репозиторий `calleograph/mfa-gate.wiki.git`. Он появляется после того, как в веб-интерфейсе создана первая страница: откройте вкладку **Wiki** и нажмите **Create the first page**. Создать его программно GitHub не позволяет.

```bash
scripts/publish-wiki.sh                  # в calleograph/mfa-gate
scripts/publish-wiki.sh owner/repo       # в вики другого репозитория, например форка
```

Что делает скрипт:

1. Запускает `scripts/check_wiki.py`. Если проверка нашла ошибки, публикация не начинается.
2. Клонирует репозиторий вики во временный каталог. Если вики ещё не создана, сообщает об этом и останавливается.
3. Копирует файлы `wiki/*.md`, в каждом убирая расширение `.md` из ссылок на страницы, и каталог `wiki/images/`. Служебный каталог `wiki/_meta/` не публикуется.
4. Если изменений нет, пишет «изменений нет» и завершается. Иначе делает коммит «Документация MFA Gate <версия>» и сразу отправляет его. Подтверждения скрипт не спрашивает.

Скрипт только добавляет и обновляет файлы: страницу, удалённую из `wiki/`, из вики GitHub нужно удалить вручную.

Вики GitHub не поддерживает запросы на слияние. Ограничьте её правку участниками с правом записи (**Settings → Features → Wikis → Restrict editing to collaborators**), а все правки вносить через `wiki/` основного репозитория: иначе правка в веб-интерфейсе будет затёрта следующей публикацией.

## Что сверять при выпуске версии

1. Прочитайте раздел нового выпуска в `CHANGELOG.md` и записи `HISTORY.md`: что изменилось для читателя.
2. Сверьте связанные страницы с кодом. Источник истины — код текущей версии, а не прежние статьи.
3. Обязательно проверьте страницы из таблицы.

| Страница | Что проверить | Источник |
| --- | --- | --- |
| [Журнал изменений](Журнал-изменений.md) | Раздел новой версии | `CHANGELOG.md` |
| [Что проверено](Что-проверено.md) | Версия и дата прогона, число тестов, новые проверки на настоящей инфраструктуре | `docs/testing.md` |
| [Возможности](Возможности.md), [Планы развития](Планы-развития.md) | Новые функции, идеи, которые стали функциями | `CHANGELOG.md`, `PROJECT.md` |
| [Справочник: конфигурация](Справочник-конфигурация.md) | Новые и изменённые переменные, значения по умолчанию | `deploy/.env.example`, `server/mfa_gate/config.py`, `deploy/compose.yml` |
| [Справочник: команды mfagatectl](Справочник-команды-mfagatectl.md) | Команды и их поведение | `deploy/mfagatectl`, `install.sh`, `server/mfa_gate/cli.py` |
| [Справочник: роли и права](Справочник-роли-и-права.md) | Роли, права, разделы меню | `server/mfa_gate/api/deps.py`, `server/web/assets/js/app.js` |
| [Справочник: журнал аудита](Справочник-журнал-аудита.md) | Новые события и подписи | вызовы `audit(` в `server/mfa_gate/`, `server/web/assets/js/labels.js` |
| [Справочник: коды причин отказа](Справочник-коды-причин-отказа.md) | Коды и тексты | `server/mfa_gate/services/authflow.py`, `labels.js` |
| [Справочник для проверки ИБ](Справочник-для-проверки-ИБ.md), [Безопасность и модель угроз](Безопасность-и-модель-угроз.md) | Меры, пределы, исходящие соединения, остаточные риски | `docs/threat-model.md`, `docs/adr/` |
| [Требования к серверу](Требования-к-серверу.md) | Пороги установщика, версии ОС | `install.sh` |
| Инструкции по разделам панели и кабинета | Подписи кнопок, полей, пути в меню; снимки в `wiki/images/` | `server/web/assets/js/views/*.js`, `portal.js` |

4. Новое число о нагрузке, задержке или требованиях записывайте только с условиями измерения и статусом.
5. Выполните проверки из раздела «Проверить исходники» и опубликуйте вики.
