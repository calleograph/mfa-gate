# Решение проблем установки и обновления

*Для кого: администратор сервера MFA Gate.*

Статья собирает сообщения установщика `install.sh` и команд `mfagatectl`, которые останавливают установку, обновление, откат или восстановление. Для каждого сообщения указаны причина и действие. Команды выполняются на сервере MFA Gate с правами администратора.

## Как читать сообщения

Установщик проходит шесть этапов: «Проверка сервера», «Docker и необходимые пакеты», «Конфигурация», «Образы, база данных и запуск», «Первый администратор», «Проверка работы». При ошибке он останавливается и печатает три строки:

```text
ОШИБКА на этапе «Конфигурация»: порт 8080/tcp занят
Как исправить: задайте свободный порт: sudo MFA_GATE_HTTP_PORT=8180 ./install.sh
Журнал установки: /var/log/mfa-gate/install-20261119-101500.log — приложите его, если обращаетесь за помощью.
```

Команды `mfagatectl` сообщают об ошибке строкой `FAIL …`, о предупреждении — строкой `WARN …`, о ходе работы — строками `==> …`.

Последние строки последнего журнала установки:

```bash
sudo ls -1t /var/log/mfa-gate/ | head -n1
sudo tail -n 50 /var/log/mfa-gate/install-<время>.log
```

Повторный запуск `sudo ./install.sh` безопасен: настройки, секреты и данные сохраняются. После исправления причины просто запустите установщик снова.

## Сообщения установщика

| Что видно | Почему | Что сделать |
|---|---|---|
| `Запустите установку с правами администратора: sudo ./install.sh` | Установщик запущен без `sudo` | `sudo ./install.sh` |
| `ОС … не поддерживается установщиком` | Установщик работает на Ubuntu и Debian | Ubuntu 22.04 и новее или Debian 12. На других ОС — ручная установка по [docs/install.md](https://github.com/calleograph/mfa-gate/blob/main/docs/install.md) |
| `архитектура … не поддерживается` | Процессор не x86_64 и не aarch64 | Другой сервер |
| `мало памяти: … МБ` | Меньше 1 ГБ оперативной памяти | Добавьте память: [Требования к серверу](Требования-к-серверу.md) |
| `мало места на диске: … ГБ` | Меньше 5 ГБ свободно в разделе с каталогом установки | Освободите место или расширьте раздел |
| `нет доступа к ghcr.io и github.com` | Нет интернета, не работает DNS или нужен прокси | `getent hosts github.com` — DNS; `curl -I https://ghcr.io/` — доступ. Для прокси задайте `https_proxy` |
| `не удалось скачать установщик Docker` | Нет доступа к get.docker.com, а пакеты дистрибутива недоступны | Установите Docker вручную и повторите |
| `установка Docker не удалась` | Ошибка пакетов, подробности в журнале | Посмотрите журнал; установите Docker вручную по документации Docker |
| `служба Docker не запущена` | Docker установлен, но не стартует | Раздел «Docker не стартует» ниже |
| `нет docker compose v2` | Нет плагина Compose | `sudo apt-get install docker-compose-v2` или `docker-compose-plugin` |
| `порт 8080/tcp занят` | Порт панели, заданный вручную, занят. Без явного порта установщик сам перебирает порты от 8080 до 8100 | Кто занял: `sudo ss -ltnp 'sport = :8080'`. Другой порт: `sudo MFA_GATE_HTTP_PORT=8180 ./install.sh` |
| `порт 1812/udp (RADIUS) занят другой программой` | На сервере уже работает RADIUS-сервер | Кто занял: `sudo ss -lunp 'sport = :1812'`. Остановите его или задайте другой порт: `sudo MFA_GATE_RADIUS_PORT=11812 ./install.sh` — и укажите этот порт на VPN-шлюзе |
| `файл …/deploy/.env повреждён (синтаксическая ошибка)` | Ручная правка `.env` с ошибкой: значение с пробелами без кавычек | Исправьте строку, указанную в журнале. Удалять `.env` можно только на установке без данных: будет создан новый пароль базы |
| `контейнеры не запустились: …` | Не загрузился образ, не прошли миграции, сервис не стал готов | `sudo mfagatectl status`, `sudo mfagatectl logs migrate`, `sudo mfagatectl logs api` |
| `не удалось создать администратора: …` | API не ответил при создании первого администратора | `sudo mfagatectl logs api` |
| `администратор создан, но пароль не получен` | Пароль не прочитан из вывода команды | Задайте пароль заново: `sudo mfagatectl admin admin` |
| `API не отвечает на /health/ready` или `панель не открывается` | API запущен, но не готов: нет связи с базой или ошибка запуска | `sudo mfagatectl logs api`, `sudo mfagatectl logs postgres` |
| `RADIUS не слушает порт 1812` | Сервис RADIUS не запустился | `sudo mfagatectl logs radius` |
| `каталог … передан root …` | Это не ошибка. Каталог установки передан root, чтобы обычный пользователь не мог подменить скрипты | Обновляйте исходники командой `sudo git -C <каталог> pull` |

## Docker не стартует

```bash
sudo systemctl status docker --no-pager
sudo journalctl -u docker --no-pager -n 50
```

Частые причины:

- **Установлены оба пакета** `docker.io` и `docker-ce`: `dpkg -l | grep -E 'docker(\.io|-ce)'`. Оставьте один.
- **Ошибка в `/etc/docker/daemon.json`**: `sudo python3 -m json.tool /etc/docker/daemon.json` должен печатать JSON без ошибок.
- **Нет места** в `/var/lib/docker`: `df -h /var/lib/docker`.
- **Сервер — контейнер LXC без вложенной виртуализации.** Включите вложенность на гипервизоре или используйте виртуальную машину.

После исправления: `sudo systemctl restart docker`, затем `sudo ./install.sh`.

## Сообщения mfagatectl при установке и запуске

| Что видно | Почему | Что сделать |
|---|---|---|
| `нет …/deploy/.env — сначала ./mfagatectl install` | Экземпляр ещё не установлен в этом каталоге | `sudo ./install.sh` |
| `Docker не установлен`, `Docker недоступен текущему пользователю (группа docker или sudo)` | Команда запущена без прав на Docker | Запускайте через `sudo` |
| `==> создан …/.env (проверьте MFA_GATE_PUBLIC_URL, порты и образ, затем повторите install)` | `mfagatectl install` запущен напрямую без адреса и остановился, чтобы не ставить систему с примерами | Проверьте `.env` и повторите. Проще ставить через `install.sh` |
| `WARN MFA_GATE_PUBLIC_URL оставлен примером — исправьте в .env до привязки телефонов` | В адресе остался `example.org` | Укажите настоящий адрес до привязки телефонов |
| `==> сгенерирован мастер-ключ … — СОХРАНИТЕ ЕГО КОПИЮ ОТДЕЛЬНО` | Создан ключ шифрования | Сохраните копию `data/secrets/master.key` вне сервера: [Резервное копирование](Резервное-копирование.md) |
| `сервисы не стали healthy за 3 мин: ./mfagatectl status; ./mfagatectl logs` | Какой-то из сервисов `api`, `radius`, `worker` не прошёл проверку готовности | `sudo mfagatectl status` покажет, какой. Затем `sudo mfagatectl logs <сервис>` |
| `не удалось загрузить образ …` | Нет доступа к реестру образов | Проверьте доступ к ghcr.io |
| `образа …:X.Y.Z нет в реестре, а исходники в этом каталоге — версии …` | Версия ещё не опубликована, а собрать её можно только из исходников той же версии | Выполните команду из сообщения: `git fetch --tags` и `git checkout vX.Y.Z`, затем повторите |
| `сборка образа не удалась` | Ошибка локальной сборки | Журнал сборки выше в выводе; передайте его администратору проекта |

## Обновление и откат

Команда `sudo mfagatectl update X.Y.Z` делает резервную копию, загружает образ, применяет миграции и ждёт готовности сервисов. Если новая версия не запустилась, она сама откатывается: [Обновление](Обновление.md).

| Что видно | Почему | Что сделать |
|---|---|---|
| `укажите версию, например ./mfagatectl update 0.2.0` | Версия не указана | Узнайте последнюю: `sudo mfagatectl check-update` |
| `версия должна быть вида 1.2.3, получено: …` | Версия указана с ошибкой или с буквой `v` | Укажите номер без `v`: `sudo mfagatectl update 0.3.1` |
| `pg_dump не выполнен (postgres запущен?)` | Резервная копия перед обновлением не создана, обновление не начиналось | `sudo mfagatectl status`; если `postgres` остановлен — `sudo mfagatectl start` |
| `образ …:X.Y.Z недоступен — версия осталась …, система не менялась` | Образ не загрузился | Проверьте номер версии и доступ к ghcr.io |
| `WARN новая версия не стала healthy — откат на …` и `обновление отменено, система на версии …` | Новая версия не запустилась, сработал автоматический откат с восстановлением базы из копии | Система работает на прежней версии. Соберите `sudo mfagatectl diagnose` и передайте архив |
| `==> обновлено до X.Y.Z (копия перед обновлением: …)` | Обновление прошло | Проверьте **Панель → Диагностика** |
| `нет сведений о последнем обновлении (…/last-update)` | Откат вызывается без предшествующего `update` | Откат возможен только после обновления. Иначе — восстановление из копии: [Восстановление](Восстановление.md) |

`sudo mfagatectl rollback` возвращает и версию, и базу на момент перед последним обновлением. Изменения, сделанные после обновления, при этом теряются: миграции необратимы, база возвращается из копии.

## Проверка новой версии

| Что видно | Почему | Что сделать |
|---|---|---|
| `==> установлена последняя версия X.Y.Z` | Обновлять нечего | — |
| `==> доступна версия X.Y.Z (установлена …): ./mfagatectl update X.Y.Z` | Вышла новая версия | Прочитайте [Журнал изменений](Журнал-изменений.md) и обновитесь |
| `не удалось получить список выпусков …` | Нет доступа к api.github.com или превышен лимит запросов | Проверьте доступ, повторите позже |
| `задайте MFA_GATE_REPO в .env` | В `.env` осталось значение-заготовка | Укажите репозиторий в `MFA_GATE_REPO` |

## Восстановление из копии

| Что видно | Почему | Что сделать |
|---|---|---|
| `… не похож на резервную копию MFA Gate` | В каталоге нет `db.dump` или `manifest` | Укажите каталог копии целиком |
| `контрольная сумма копии не совпала` | Копия повреждена при хранении или переносе | Возьмите другую копию |
| `копия сделана с другим мастер-ключом: верните прежний data/secrets/master.key` | Без того ключа данные копии не расшифровать | Верните сохранённый ключ: [Восстановление](Восстановление.md) |
| `pg_restore не выполнен, рабочая база не тронута` | Копия не загрузилась во временную базу | Рабочая система не изменилась. Попробуйте другую копию |
| `==> восстановлено; прежняя база сохранена как mfa_gate_prev` | Восстановление прошло | Проверьте **Панель → Диагностика** |

## После установки или обновления

| Что видно | Почему | Что сделать |
|---|---|---|
| **Диагностика → Миграции**: «схема …, ожидается …» | Схема базы не совпадает с версией программы | `sudo mfagatectl logs migrate` покажет, почему миграции не прошли. Исправив причину, повторите `sudo mfagatectl install` |
| **Диагностика → Мастер-ключ**: «Ключ не задан или повреждён» | Файл `data/secrets/master.key` удалён, изменён или недоступен | Верните сохранённую копию ключа и выполните `sudo mfagatectl restart` |
| Панель не открывается на сервере | `api` не готов | `curl -fsS http://127.0.0.1:8080/health/ready` — ответ `"status":"ok"` значит, что API работает. Ответ `503` с `"database":"unavailable"` — нет связи с базой: `sudo mfagatectl logs postgres` |
| Панель открывается на сервере, но не снаружи | Межсетевой экран, прокси или порт в `proxy_pass` | [HTTPS через reverse proxy](HTTPS-через-reverse-proxy.md) |
| После ввода пароля снова форма входа | Прокси не передаёт `X-Forwarded-Proto` или задано `MFA_GATE_COOKIE_SECURE=true` при работе по HTTP | Верните `MFA_GATE_COOKIE_SECURE=auto` и проверьте настройки прокси |
| Заканчивается место на диске | Старые резервные копии и архивы диагностики | `sudo du -sh /opt/mfa-gate/deploy/{data,backups}`; удалите старые копии и архивы `diag-*`; `sudo docker image prune` |

Если причину найти не удалось, соберите архив `sudo mfagatectl diagnose` и журнал установки и передайте их по внутреннему каналу. Перед отправкой просмотрите файлы: адреса и логины вашей организации в них есть.
